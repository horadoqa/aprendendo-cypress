Testando Formulários com Cypress

Aprenda a automatizar formulários utilizando inputs, selects, checkboxes, radio buttons, textareas e validações com Cypress.

Objetivos da aula

Nas aulas anteriores aprendemos a localizar elementos, realizar cliques, preencher campos e criar asserções.

Agora vamos combinar esses conhecimentos para testar formulários completos utilizando o Cypress.

📝

Preencher inputs

Aprender a preencher campos de texto, email, senha e outros tipos de input.

📋

Trabalhar com selects

Selecionar opções em campos do tipo select.

☑️

Checkbox e radio

Interagir e validar caixas de seleção e opções de escolha.

✅

Validar formulários

Verificar mensagens, valores e comportamentos após o preenchimento.

O que é um formulário?

Um formulário é um conjunto de campos utilizado para coletar informações do usuário.

Formulários estão presentes em diversas aplicações, como páginas de login, cadastro, checkout, busca, contato e configurações de perfil.

📝 Input → recebe informações do usuário.

📋 Select → permite selecionar uma opção.

☑️ Checkbox → permite selecionar uma ou mais opções.

🔘 Radio → permite escolher uma opção dentro de um grupo.

🔲 Textarea → permite inserir textos maiores.

🚀 Submit → envia os dados do formulário.

1. Estrutura básica de um formulário

Um formulário HTML pode conter diferentes tipos de elementos para entrada de dados. 

<form>

<label for="nome">
    Nome
</label>

<input
    type="text"
    id="nome"
>

<label for="email">
    Email
</label>

<input
    type="email"
    id="email"
>

<button type="submit">
    Enviar
</button>

O Cypress pode localizar esses elementos e simular as ações realizadas por um usuário.

Objetivo do teste:

Preencher os campos, enviar o formulário e validar o resultado apresentado pela aplicação.

2. Preenchendo campos de texto

Para preencher um campo de texto utilizamos o comando type(). 

cy.get('#nome')
.type('João Silva')

Também podemos localizar o campo utilizando um atributo data-cy. 

cy.get('[data-cy="nome"]')
.type('João Silva')
📝

type()

Insere texto dentro de um elemento que aceita entrada de dados.

🎯

Seletor estável

Um seletor confiável facilita a manutenção dos testes.

3. Limpando um campo

O Cypress possui o comando clear() para limpar o conteúdo de um campo. 

cy.get('#nome')
.clear()

Também podemos limpar e preencher novamente: 

cy.get('#nome')
.clear()
.type('Maria Silva')

🧹 clear() → remove o conteúdo atual do campo.

✏️ type() → insere um novo valor.

4. Testando campos de email

Campos de email podem ser preenchidos utilizando o mesmo comando type(). 

cy.get('#email')
.type('usuario@email.com')

Também podemos validar se o campo recebeu o valor esperado. 

cy.get('#email')
.should('have.value', 'usuario@email.com')
Boa prática:

Além de preencher o campo, valide o valor quando isso for importante para o comportamento que está sendo testado.

5. Testando campos de senha

Campos do tipo password também podem ser preenchidos com type(). 

cy.get('#senha')
.type('Senha@123')

Em testes reais, devemos ter cuidado para não expor credenciais diretamente no código ou nos relatórios.

Importante:

Evite utilizar credenciais reais em testes automatizados. Prefira contas específicas para automação e mecanismos apropriados para armazenar informações sensíveis.

6. Trabalhando com select

Para selecionar uma opção em um elemento select, utilizamos o comando select(). 

cy.get('#estado')
.select('RJ')

Também podemos selecionar uma opção pelo texto: 

cy.get('#estado')
.select('Rio de Janeiro')

Depois podemos validar a opção selecionada: 

cy.get('#estado')
.should('have.value', 'RJ')
📋

select()

Seleciona uma opção dentro de um elemento select.

🔎

Validação

Podemos verificar se a opção esperada foi selecionada.

7. Trabalhando com checkbox

Checkboxes são utilizados quando o usuário pode selecionar ou desmarcar uma opção. 

cy.get('#termos')
.check()

Para desmarcar: 

cy.get('#termos')
.uncheck()

Também podemos verificar o estado do checkbox: 

cy.get('#termos')
.should('be.checked')

☑️ check() → marca o checkbox.

⬜ uncheck() → desmarca o checkbox.

✅ be.checked → valida se o checkbox está marcado.

8. Trabalhando com radio buttons

Radio buttons permitem selecionar uma opção dentro de um grupo. 

cy.get('#masculino')
.check()

Também podemos validar se a opção foi selecionada: 

cy.get('#masculino')
.should('be.checked')
Diferença importante:

Enquanto um checkbox normalmente representa uma escolha independente, radio buttons geralmente fazem parte de um grupo em que apenas uma opção pode ser selecionada.

9. Trabalhando com textarea

O elemento textarea é utilizado para campos que aceitam textos maiores. 

cy.get('#mensagem')
.type('Esta é uma mensagem de teste.')

Podemos validar o conteúdo: 

cy.get('#mensagem')
.should(
    'have.value',
    'Esta é uma mensagem de teste.'
)

10. Testando campos obrigatórios

Formulários frequentemente possuem campos obrigatórios que precisam ser preenchidos antes do envio.

Um teste pode verificar o comportamento quando o usuário tenta enviar o formulário sem preencher esses campos. 

cy.get('button[type="submit"]')
.click()

cy.get('#mensagem-erro')
.should('be.visible')
Objetivo:

Garantir que a aplicação não permita o envio de dados inválidos ou incompletos quando isso fizer parte da regra de negócio.

11. Testando validações de campos

Podemos testar como a aplicação reage quando o usuário informa dados inválidos.

Por exemplo, um email inválido: 

cy.get('#email')
.type('email-invalido')

cy.get('button[type="submit"]')
.click()

cy.get('#erro-email')
.should('be.visible')

Esse tipo de teste ajuda a verificar as regras de validação implementadas pela aplicação.

12. Enviando o formulário

Depois de preencher os campos, podemos enviar o formulário utilizando click(). 

cy.get('button[type="submit"]')
.click()

Também podemos utilizar um seletor específico: 

cy.get('[data-cy="enviar"]')
.click()

🚀 Preencher → inserir os dados necessários.

🖱️ Enviar → clicar no botão de submissão.

✅ Validar → verificar o resultado esperado.

13. Testando um formulário completo

Podemos combinar diferentes comandos para criar um teste completo de cadastro. 

describe('Cadastro de usuário', () => {

it('deve realizar um cadastro com sucesso', () => {

    cy.visit('/cadastro')

    cy.get('#nome')
        .type('João Silva')

    cy.get('#email')
        .type('joao@email.com')

    cy.get('#senha')
        .type('Senha@123')

    cy.get('#estado')
        .select('RJ')

    cy.get('#termos')
        .check()

    cy.get('button[type="submit"]')
        .click()

    cy.get('#sucesso')
        .should('be.visible')

})

})
Observe o fluxo:

1️⃣ Acessamos a página.

2️⃣ Preenchemos os campos.

3️⃣ Selecionamos opções.

4️⃣ Marcamos o checkbox.

5️⃣ Enviamos o formulário.

6️⃣ Validamos o resultado.

14. Utilizando data-cy nos formulários

Uma estratégia bastante útil é utilizar atributos específicos para automação.

Por exemplo: 

<input
type="text"
data-cy="nome"

>

No Cypress: 

cy.get('[data-cy="nome"]')
.type('João Silva')

cy.get('[data-cy="email"]')
.type('joao@email.com')

cy.get('[data-cy="enviar"]')
.click()
Boa prática:

A utilização de atributos dedicados à automação pode tornar os testes menos dependentes da estrutura visual da página.

15. Validando valores preenchidos

Depois de preencher um campo, podemos verificar seu valor utilizando a asserção have.value. 

cy.get('#nome')
.type('Maria Silva')
.should('have.value', 'Maria Silva')

Também podemos validar um select: 

cy.get('#estado')
.select('RJ')
.should('have.value', 'RJ')
🔎

have.value

Verifica o valor atual de um campo de formulário.

✅

Validação

Confirma que a aplicação recebeu ou manteve o valor esperado.

16. Testes positivos e negativos

Ao testar formulários, é importante considerar tanto cenários válidos quanto cenários inválidos.

🟢

Teste positivo

Utiliza dados válidos e verifica se o formulário é processado corretamente.

🔴

Teste negativo

Utiliza dados inválidos ou incompletos para verificar o comportamento esperado.

Exemplo de cenário negativo: 

cy.get('#email')
.type('email-invalido')

cy.get('button[type="submit"]')
.click()

cy.get('#erro-email')
.should('contain', 'Email inválido')

17. Exemplo: teste de login

Um dos formulários mais comuns em aplicações web é o formulário de login. 

describe('Login', () => {

it('deve realizar login com sucesso', () => {

    cy.visit('/login')

    cy.get('[data-cy="email"]')
        .type('usuario@email.com')

    cy.get('[data-cy="senha"]')
        .type('Senha@123')

    cy.get('[data-cy="entrar"]')
        .click()

    cy.url()
        .should('include', 'dashboard')

})

})
Possível fluxo:

Login → envio das credenciais → autenticação → redirecionamento → validação.

18. Exemplo: formulário de cadastro

Um formulário de cadastro pode possuir diversos tipos de campos. 

cy.get('#nome')
.type('Maria Silva')

cy.get('#email')
.type('maria@email.com')

cy.get('#telefone')
.type('21999999999')

cy.get('#estado')
.select('RJ')

cy.get('#newsletter')
.check()

cy.get('#mensagem')
.type('Cadastro realizado para teste.')

cy.get('[data-cy="enviar"]')
.click()

Esse tipo de fluxo reúne praticamente todos os principais comandos estudados nesta aula.

Erros comuns ao testar formulários

❌

Seletores frágeis

Utilizar seletores baseados em classes ou estruturas que mudam frequentemente.

❌

Não validar o resultado

Preencher e enviar o formulário sem verificar se o comportamento esperado aconteceu.

❌

Testar apenas o caminho feliz

Ignorar cenários com campos vazios ou informações inválidas.

❌

Usar credenciais reais

Expor senhas, tokens ou informações sensíveis diretamente nos testes.

Boas práticas para testes de formulários

🎯

Use seletores estáveis

Prefira atributos dedicados à automação quando disponíveis.

🧪

Teste cenários positivos

Verifique se dados válidos produzem o resultado esperado.

🔴

Teste cenários negativos

Verifique mensagens e comportamentos quando dados inválidos são utilizados.

🔐

Proteja dados sensíveis

Utilize mecanismos apropriados para credenciais e informações confidenciais.

Fluxo recomendado para testar um formulário

5️⃣ Enviar → realizar a submissão.

6️⃣ Validar → verificar o resultado apresentado.
