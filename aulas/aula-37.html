AULA 37 • HOOKS

Hooks

Aprenda a utilizar before, beforeEach, after e afterEach para preparar e finalizar cenários de teste com Cypress.

Objetivos da aula

Nas aulas anteriores, aprendemos a criar comandos personalizados e organizar comportamentos reutilizáveis nos testes.

Agora vamos aprender como utilizar hooks para executar automaticamente determinadas ações antes ou depois dos testes.

🪝

Entender hooks

Compreender o que são hooks e por que eles são utilizados nos testes automatizados.

▶️

before()

Executar uma preparação antes de todos os testes de uma suíte.

🔄

beforeEach()

Executar uma preparação antes de cada teste.

🧹

after e afterEach

Executar ações de finalização depois dos testes.

O que são hooks?

Hooks são funções especiais utilizadas para executar determinadas ações em momentos específicos do ciclo de execução dos testes.

Eles são muito úteis quando precisamos preparar um ambiente, criar dados, realizar login, limpar informações ou executar alguma ação antes ou depois dos testes. 

beforeEach(() => {

// executado antes de cada teste

})

🪝 Hook → função executada automaticamente em um momento específico da suíte de testes.

🎯 Objetivo → evitar repetição de código de preparação ou finalização.

♻️ Reutilização → uma mesma configuração pode ser aplicada a vários testes.

Tipos de hooks

O Cypress disponibiliza quatro hooks principais para organizar a execução dos testes.

Hook Quando executa? Uso comum
before() Uma vez antes de todos os testes. Preparação geral da suíte.
beforeEach() Antes de cada teste. Login e preparação individual.
afterEach() Depois de cada teste. Limpeza de dados e estado.
after() Uma vez depois de todos os testes. Finalização da suíte.

1. before()

O hook before() é executado uma única vez antes de todos os testes do bloco em que foi definido. 

describe('Usuários', () => {

before(() => {

    cy.log('Preparando a suíte')

})

it('deve criar usuário', () => {

    // teste

})

it('deve consultar usuário', () => {

    // teste

})

})

Nesse exemplo, o before() será executado antes do primeiro teste.

Ele não será executado novamente entre o primeiro e o segundo teste.

Quando utilizar?

Utilize before() quando a preparação precisa acontecer apenas uma vez para aquela suíte.

2. beforeEach()

O beforeEach() é executado antes de cada teste dentro do bloco em que foi definido. 

describe('Login', () => {

beforeEach(() => {

    cy.visit('/login')

})

it('deve realizar login', () => {

    // teste

})

it('deve exibir mensagem de erro', () => {

    // teste

})

})

Nesse caso, a página de login será acessada antes de cada teste.

🔄 beforeEach() é especialmente útil quando todos os testes precisam começar em um estado conhecido.

3. afterEach()

O afterEach() é executado depois de cada teste. 

describe('Cadastro', () => {

afterEach(() => {

    cy.log('Finalizando teste')

})

it('deve cadastrar usuário', () => {

    // teste

})

it('deve validar cadastro', () => {

    // teste

})

})

O hook será executado após cada um dos testes.

Uso comum:

O afterEach() pode ser utilizado para limpeza de estado, remoção de dados de teste ou outras ações necessárias depois de cada cenário.

4. after()

O after() é executado uma única vez depois que todos os testes daquele bloco terminarem. 

describe('Produtos', () => {

after(() => {

    cy.log('Finalizando suíte de testes')

})

it('deve cadastrar produto', () => {

    // teste

})

it('deve editar produto', () => {

    // teste

})

})

Diferentemente do afterEach(), esse hook não é executado depois de cada teste.

🧹 after() → executado uma vez ao final do bloco.

🔄 afterEach() → executado depois de cada teste.

5. before x beforeEach

Uma dúvida comum é entender quando utilizar before() ou beforeEach().

Característica before() beforeEach()
Execução Uma vez. Antes de cada teste.
Preparação Geral para a suíte. Individual para cada teste.
Exemplo Configuração inicial. Login ou navegação.

Se cada teste precisa começar com a mesma preparação, beforeEach() geralmente representa melhor essa intenção.

6. after x afterEach

O mesmo conceito vale para os hooks de finalização.

🧹

after()

Executa uma única vez depois de todos os testes do bloco.

🔄

afterEach()

Executa depois de cada teste individual. 

describe('Pedidos', () => {

afterEach(() => {

    cy.log('Limpando estado')

})

after(() => {

    cy.log('Finalizando suíte')

})

})

7. Utilizando beforeEach() para login

Um dos usos mais comuns de hooks é preparar a autenticação antes de cada cenário. 

describe('Área autenticada', () => {

beforeEach(() => {

    cy.visit('/login')

    cy.get('#email')
        .type('usuario@teste.com')

    cy.get('#senha')
        .type('123456')

    cy.get('#login')
        .click()

})

it('deve acessar o dashboard', () => {

    cy.url()
        .should('include', 'dashboard')

})

it('deve visualizar o perfil', () => {

    cy.visit('/perfil')

    cy.contains('Meu perfil')
        .should('be.visible')

})

})

A preparação do login foi centralizada no hook, evitando repetir o mesmo código em cada teste.

8. Hooks com fixtures

Hooks também podem ser combinados com fixtures para carregar dados antes dos testes. 

describe('Login', () => {

beforeEach(() => {

    cy.fixture('usuario.json')
        .as('usuario')

})

it('deve realizar login', () => {

    cy.get('@usuario').then((usuario) => {

        cy.visit('/login')

        cy.get('#email')
            .type(usuario.email)

        cy.get('#senha')
            .type(usuario.senha)

    })

})

})

Dessa forma, cada teste começa com os dados necessários carregados.

9. Hooks em blocos aninhados

Os hooks podem ser utilizados dentro de diferentes blocos describe(). 

describe('Sistema', () => {

beforeEach(() => {

    cy.log('Hook externo')

})

describe('Usuários', () => {

    beforeEach(() => {

        cy.log('Hook de usuários')

    })

    it('deve consultar usuário', () => {

        // teste

    })

})

})

Um hook definido em um bloco externo pode participar da preparação dos testes dos blocos internos.

Hooks aninhados devem ser utilizados com organização para que a preparação dos testes continue fácil de entender.

10. Ordem de execução

É importante entender a sequência em que os hooks participam da execução dos testes. 

before()

beforeEach()

it()

afterEach()

beforeEach()

it()

afterEach()

after()

Considerando uma suíte com dois testes, o fluxo geral pode ser representado dessa forma.

1️⃣ Preparação geral

2️⃣ Preparação do primeiro teste

3️⃣ Execução do primeiro teste

4️⃣ Finalização do primeiro teste

5️⃣ Preparação do segundo teste

6️⃣ Execução do segundo teste

7️⃣ Finalização do segundo teste

8️⃣ Finalização geral

11. Organizando uma suíte com hooks

Hooks podem ajudar a deixar os testes menores e mais focados no comportamento que realmente está sendo validado. 

describe('Produtos', () => {

beforeEach(() => {

    cy.visit('/produtos')

})

it('deve listar produtos', () => {

    cy.get('[data-testid="produto"]')
        .should('have.length.greaterThan', 0)

})

it('deve abrir produto', () => {

    cy.get('[data-testid="produto"]')
        .first()
        .click()

})

})

O hook concentra a navegação inicial, enquanto cada teste permanece responsável pela validação do seu próprio comportamento.

12. Reduzindo duplicação

Sem hooks, podemos acabar repetindo a mesma preparação em vários testes. 

it('teste 1', () => {

cy.visit('/produtos')

// teste

})

it('teste 2', () => {

cy.visit('/produtos')

// teste

})

it('teste 3', () => {

cy.visit('/produtos')

// teste

})

Podemos centralizar a preparação: 

beforeEach(() => {

cy.visit('/produtos')

})

it('teste 1', () => {

// teste

})

it('teste 2', () => {

// teste

})

it('teste 3', () => {

// teste

})

A centralização reduz repetição, mas o hook deve continuar representando uma preparação realmente compartilhada pelos testes.

13. Cuidados ao utilizar hooks

⚠️

Não exagere

Evite colocar toda a lógica do teste dentro de hooks.

🧩

Mantenha o contexto

O hook deve ter relação clara com os testes do bloco.

🔍

Facilite a leitura

Quem lê o teste deve conseguir entender quais pré-condições estão sendo aplicadas.

♻️

Evite duplicação

Use hooks quando eles realmente reduzirem código repetido.

14. Quando utilizar cada hook?

Hook Objetivo Exemplo
before() Preparação única. Criar configuração inicial.
beforeEach() Preparação por teste. Login ou navegação.
afterEach() Limpeza por teste. Remover estado criado.
after() Finalização única. Encerrar preparação global.

15. Exemplo completo

Agora vamos combinar os quatro hooks em uma mesma suíte para visualizar o fluxo completo. 

describe('Usuários', () => {

before(() => {

    cy.log('Preparação geral')

})

beforeEach(() => {

    cy.visit('/usuarios')

})

it('deve listar usuários', () => {

    cy.get('[data-testid="usuario"]')
        .should('exist')

})

it('deve abrir usuário', () => {

    cy.get('[data-testid="usuario"]')
        .first()
        .click()

})

afterEach(() => {

    cy.log('Finalizando teste')

})

after(() => {

    cy.log('Finalizando suíte')

})

})

Esse padrão permite separar claramente as ações de preparação, execução e finalização dos testes.

Boas práticas com hooks

🎯

Tenha um propósito claro

Cada hook deve executar ações relacionadas à preparação ou finalização dos testes.

🧹

Mantenha a limpeza

Utilize hooks de finalização quando houver estado que precise ser limpo.

📖

Preserve a legibilidade

Evite esconder comportamentos importantes dentro de hooks muito complexos.

♻️

Reutilize com equilíbrio

Centralize somente aquilo que realmente é compartilhado entre os testes.
