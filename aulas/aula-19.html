Comandos de Navegação

Aprenda a navegar entre páginas, voltar, avançar, recarregar aplicações e controlar o histórico do navegador utilizando Cypress.

Objetivos da aula

Nas aulas anteriores aprendemos a localizar elementos, utilizar seletores e realizar interações com a aplicação.

Agora vamos aprender como controlar a navegação do navegador durante nossos testes automatizados.

➡️

🔄

Recarregar

Recarregar a página utilizando comandos do Cypress.

O que é navegação?

Navegação representa o processo de acessar diferentes páginas ou estados de uma aplicação durante a interação com o navegador.

Em um teste E2E, é comum precisarmos acessar uma página, realizar uma ação, navegar para outra página e depois validar o resultado.

🌐 Página inicial → acesso à aplicação.

🖱️ Interação → usuário realiza uma ação.

➡️ Nova página → aplicação realiza uma navegação.

✅ Validação → teste verifica o resultado.

1. Utilizando cy.visit()

O comando cy.visit() é utilizado para acessar uma URL durante o teste.

Podemos informar uma URL completa: 

cy.visit('https://exemplo.com')

Quando uma baseUrl está configurada, também podemos utilizar um caminho relativo: 

cy.visit('/')

Ou: 

cy.visit('/login')
Boa prática:

Quando o projeto possui uma baseUrl configurada, prefira utilizar caminhos relativos nos testes.

2. Navegando entre páginas

Podemos utilizar diferentes chamadas de cy.visit() para acessar páginas distintas. 

cy.visit('/')

cy.visit('/login')

cy.visit('/produtos')

cy.visit('/contato')

Cada chamada realiza uma navegação para o endereço informado.

🏠

/

Página inicial da aplicação.

🔐

/login

Página de autenticação.

🛍️

/produtos

Página de produtos.

📧

/contato

Página de contato.

3. Validando a URL atual

Durante um teste, podemos verificar se o navegador está na página esperada.

Para isso, podemos utilizar o comando cy.url(). 

cy.visit('/login')

cy.url()
.should('include', '/login')

Também podemos verificar uma URL específica: 

cy.url()
.should('eq', 'http://localhost:3000/login')
Atenção:

A validação com include pode ser útil quando apenas uma parte da URL é relevante para o cenário.

4. Utilizando cy.go()

O comando cy.go() permite navegar pelo histórico do navegador.

Para voltar uma página: 

cy.go('back')

Também podemos utilizar o número -1: 

cy.go(-1)

Para avançar: 

cy.go('forward')

Ou: 

cy.go(1)

⬅️ cy.go(-1) → volta uma entrada no histórico.

➡️ cy.go(1) → avança uma entrada no histórico.

5. Utilizando cy.go('back')

O comando abaixo retorna para a página anterior: 

cy.go('back')

Imagine o seguinte fluxo: 

Página inicial
  ↓

Página de produtos
↓
Página de detalhes

Depois de acessar a página de detalhes, podemos voltar: 

cy.go('back')

O navegador retorna para a página anterior do histórico.

6. Utilizando cy.go('forward')

Depois de voltar no histórico, podemos avançar novamente utilizando: 

cy.go('forward')

Exemplo: 

cy.visit('/produtos')

cy.visit('/produto/1')

cy.go('back')

cy.go('forward')

O histórico do navegador é utilizado para controlar o movimento entre as páginas.

7. Utilizando cy.back()

O Cypress também disponibiliza o comando cy.back() para retornar uma entrada no histórico do navegador. 

cy.back()

Ele pode ser utilizado quando queremos expressar diretamente a intenção de voltar para a página anterior.

Por exemplo: 

cy.visit('/produtos')

cy.get('[data-cy="produto-1"]')
.click()

cy.back()
Observação:

O comando representa uma navegação no histórico. Ele não deve ser confundido com uma nova chamada de cy.visit().

8. Utilizando cy.reload()

O comando cy.reload() recarrega a página atual. 

cy.reload()

Podemos utilizá-lo quando queremos verificar o comportamento da aplicação depois de um reload. 

cy.visit('/dashboard')

cy.reload()

cy.get('h1')
.should('be.visible')
🔄

Recarregar

Atualiza o documento da página atual.

🧪

Validar estado

Permite verificar como a aplicação se comporta depois de uma atualização.

9. Recarregando sem utilizar o cache

O cy.reload() também aceita opções relacionadas ao comportamento de recarregamento.

Podemos solicitar um reload utilizando a estratégia de recarregamento ignorando o cache: 

cy.reload('onload', {
timeout: 10000

})

O primeiro argumento define o tipo de espera pelo evento de carregamento, enquanto o objeto de opções pode definir configurações como timeout.

Importante:

Na maioria dos testes, o uso simples de cy.reload() é suficiente. Utilize opções adicionais somente quando o cenário realmente exigir.

10. Entendendo o histórico do navegador

Os comandos de voltar e avançar trabalham com o histórico de navegação do navegador.

Podemos representar um fluxo da seguinte maneira: 

/inicio

↓
/produtos
↓
/produto/1

Se estivermos em /produto/1 e executarmos: 

cy.go('back')

retornaremos para: 

/produtos

Se executarmos: 

cy.go('forward')

poderemos retornar para: 

/produto/1

11. Exemplo prático de navegação

Vamos imaginar uma aplicação com uma página inicial, uma página de produtos e uma página de detalhes. 

describe('Navegação', () => {

it('deve navegar entre páginas', () => {

    cy.visit('/')

    cy.get('[data-cy="produtos"]')
        .click()

    cy.url()
        .should('include', '/produtos')

    cy.get('[data-cy="produto-1"]')
        .click()

    cy.url()
        .should('include', '/produto/1')

    cy.go('back')

    cy.url()
        .should('include', '/produtos')

})

})

Esse teste combina interação, navegação e validação da URL.

12. Navegação após uma interação

Um cenário bastante comum em testes E2E é clicar em um elemento e verificar se a aplicação navegou para a página esperada. 

cy.visit('/')

cy.get('[data-cy="login"]')
.click()

cy.url()
.should('include', '/login')

Também podemos validar elementos da nova página: 

cy.get('h1')
.should('contain', 'Login')
Boa prática:

Depois de uma ação que deveria provocar navegação, valide algum aspecto observável da nova página, como URL, título ou elemento principal.

13. cy.url() e cy.location()

O cy.url() é uma forma simples de obter a URL atual da página. 

cy.url()
.should('include', '/dashboard')

O Cypress também disponibiliza o comando cy.location(), que permite acessar partes específicas da localização atual. 

cy.location('pathname')
.should('eq', '/dashboard')

Também podemos acessar outras propriedades, como hostname e pathname.

🔗

cy.url()

Retorna a URL atual da página.

📍

cy.location()

Permite consultar propriedades específicas da localização atual.

14. Testando redirecionamentos

Aplicações frequentemente redirecionam o usuário depois de determinadas ações.

Por exemplo, depois de realizar login, o usuário pode ser direcionado para um dashboard. 

cy.visit('/login')

cy.get('[data-cy="email"]')
.type('usuario@exemplo.com')

cy.get('[data-cy="senha"]')
.type('senha123')

cy.get('[data-cy="entrar"]')
.click()

cy.url()
.should('include', '/dashboard')

O objetivo do teste não é apenas clicar no botão. Também precisamos validar se a aplicação chegou ao estado esperado.

15. Navegação para URLs externas

O cy.visit() também pode acessar uma URL completa. 

cy.visit('https://example.cypress.io')

Entretanto, testes E2E normalmente devem se concentrar no comportamento da aplicação que está sob teste.

Boa prática:

Evite transformar dependências externas em requisitos obrigatórios para a execução da sua suíte. Quando apropriado, considere interceptação ou mocks para controlar dependências externas.

16. Navegação utilizando baseUrl

Quando configuramos uma baseUrl, os testes podem utilizar caminhos relativos. 

e2e: {

baseUrl: 'http://localhost:3000'

}

Então podemos escrever: 

cy.visit('/')

cy.visit('/login')

cy.visit('/produtos')

Em vez de repetir: 

cy.visit('http://localhost:3000/')

cy.visit('http://localhost:3000/login')

cy.visit('http://localhost:3000/produtos')

Centralizar a URL da aplicação ajuda a reduzir repetição e facilita a manutenção dos testes.

17. Quando utilizar cada comando?

Comando Objetivo
cy.visit() Acessar uma URL.
cy.go('back') Voltar no histórico do navegador.
cy.go('forward') Avançar no histórico do navegador.
cy.back() Retornar uma entrada no histórico.
cy.reload() Recarregar a página atual.
cy.url() Consultar a URL atual.
cy.location() Consultar propriedades da localização.

Erros comuns em testes de navegação

❌

Não validar a navegação

Clicar em um elemento sem verificar se a aplicação chegou ao destino esperado.

❌

Repetir URLs completas

Espalhar a URL da aplicação por diversos testes mesmo quando existe uma baseUrl.

❌

Depender de histórico incorreto

Utilizar back ou forward sem considerar o fluxo de navegação realizado pelo teste.

❌

Usar reload sem necessidade

Recarregar a página sem que isso faça parte do comportamento que está sendo validado.

Boas práticas de navegação

🎯

Valide o destino

Depois de uma navegação importante, valide a URL ou algum elemento da página.

🌐

Utilize baseUrl

Centralize o endereço principal da aplicação na configuração do Cypress.

🧪

Simule fluxos reais

Construa cenários que representem ações realizadas por usuários.

🧹

Evite navegação desnecessária

Mantenha cada teste focado no comportamento que precisa ser validado.

Exercício prático

Crie um teste que execute o seguinte fluxo:

1️⃣ Acesse a página inicial.

2️⃣ Navegue para a página de produtos.

3️⃣ Valide a URL.

4️⃣ Acesse um produto.

5️⃣ Valide a página de detalhes.

6️⃣ Volte para a página anterior.

7️⃣ Valide novamente a URL.

8️⃣ Recarregue a página.

9️⃣ Valide se o conteúdo principal continua disponível.

Um exemplo de estrutura: 

describe('Navegação de produtos', () => {

it('deve navegar corretamente', () => {

    cy.visit('/')

    // navegar para produtos

    // validar URL

    // acessar produto

    // validar página

    // voltar

    // validar URL

    // recarregar

    // validar conteúdo

})

})
