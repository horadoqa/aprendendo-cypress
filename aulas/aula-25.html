AULA 25 • VALIDANDO ESTADOS

Validando Estados

Aprenda a validar estados de elementos utilizando asserções do Cypress, verificando se componentes estão visíveis, habilitados, desabilitados, selecionados ou marcados.

Objetivos da aula

Nas aulas anteriores aprendemos a localizar elementos, interagir com eles e validar textos, atributos e propriedades da aplicação.

Agora vamos aprender a validar o estado dos elementos da interface, verificando se eles estão disponíveis para interação e se apresentam o comportamento esperado.

👁️

Validar visibilidade

Verificar se um elemento está visível ou escondido na página.

🟢

Validar elementos habilitados

Verificar se um elemento está disponível para interação.

🚫

Validar elementos desabilitados

Garantir que componentes bloqueados estejam realmente desabilitados.

☑️

Validar seleção

Validar checkboxes, radio buttons e opções selecionadas.

O que são estados de elementos?

Um elemento da interface pode apresentar diferentes estados dependendo da situação da aplicação.

Um botão, por exemplo, pode estar habilitado, desabilitado, visível ou oculto.

👁️ Visível → o elemento está sendo exibido na interface.

🚫 Oculto → o elemento não está visível para o usuário.

🟢 Habilitado → o elemento pode receber determinada interação.

🔴 Desabilitado → o elemento não está disponível para interação.

☑️ Selecionado → o elemento possui uma seleção ativa.

1. Validando visibilidade

Uma das validações mais utilizadas em testes E2E é verificar se determinado elemento está visível.

Para isso, podemos utilizar a asserção: 

cy.get('button')
.should('be.visible')

Nesse exemplo, o Cypress localiza um botão e verifica se ele está visível na página.

Exemplo: 
<button id="salvar">
Salvar

Teste: 

cy.get('#salvar')
.should('be.visible')

2. Validando elementos ocultos

Também podemos verificar se um elemento não está visível utilizando not.be.visible. 

cy.get('.modal')
.should('not.be.visible')

Essa validação é útil quando esperamos que uma mensagem, modal ou componente esteja escondido.

👁️

be.visible

Espera que o elemento esteja visível.

🙈

not.be.visible

Espera que o elemento não esteja visível.

3. Validando existência

Além da visibilidade, podemos verificar se um elemento existe no DOM. 

cy.get('#mensagem')
.should('exist')

Essa validação verifica a existência do elemento, mas não significa necessariamente que ele esteja visível para o usuário.

Importante:

exist e be.visible representam verificações diferentes.

Um elemento pode existir no DOM e estar oculto visualmente.

4. Validando que um elemento não existe

Também podemos verificar que determinado elemento não está presente no DOM. 

cy.get('.mensagem-erro')
.should('not.exist')

Essa validação pode ser útil depois de uma ação que deveria remover um componente da página.

Por exemplo, depois de fechar um modal: 

cy.get('#fechar')
.click()

cy.get('.modal')
.should('not.exist')

5. Validando elementos habilitados

Podemos verificar se um elemento está habilitado utilizando be.enabled. 

cy.get('button')
.should('be.enabled')

Essa validação é especialmente útil para botões, inputs e outros controles que podem ser desabilitados em determinadas situações.

Exemplo: 
<button id="continuar">
Continuar


cy.get('#continuar')
.should('be.enabled')

6. Validando elementos desabilitados

Para verificar se um elemento está desabilitado, podemos utilizar be.disabled. 

cy.get('#continuar')
.should('be.disabled')

Isso é útil em cenários nos quais um botão deve permanecer indisponível até que determinada condição seja atendida.

🟢

be.enabled

Valida que o elemento está habilitado.

🔴

be.disabled

Valida que o elemento está desabilitado.

7. Validando checkboxes marcados

Para checkboxes, podemos verificar se uma opção está marcada utilizando be.checked. 

cy.get('#termos')
.should('be.checked')

Exemplo de elemento: 

<input
type="checkbox"
id="termos"

>

Podemos combinar a interação com a validação: 

cy.get('#termos')
.check()

cy.get('#termos')
.should('be.checked')

8. Validando checkboxes desmarcados

Também podemos verificar se um checkbox não está marcado. 

cy.get('#termos')
.should('not.be.checked')

Essa validação pode ser utilizada para garantir que um formulário comece com determinadas opções desmarcadas.

☑️ be.checked → checkbox marcado.

☐ not.be.checked → checkbox desmarcado.

9. Validando opções selecionadas

Em elementos como selects, podemos verificar se uma determinada opção está selecionada. 

cy.get('option:selected')
.should('have.value', 'sp')

Também podemos validar o texto da opção selecionada: 

cy.get('option:selected')
.should('contain.text', 'São Paulo')
Exemplo: 
<select id="estado">

<option value="rj">
    Rio de Janeiro
</option>

<option value="sp">
    São Paulo
</option>

10. Validando radio buttons

Radio buttons também podem ser validados para verificar qual opção está marcada. 

cy.get('input[value="pix"]')
.should('be.checked')

Podemos primeiro selecionar a opção e depois validar o estado: 

cy.get('input[value="pix"]')
.check()

cy.get('input[value="pix"]')
.should('be.checked')

A mesma asserção be.checked pode ser utilizada para validar checkboxes e radio buttons.

11. Validando foco

Também podemos validar se determinado elemento recebeu foco utilizando have.focus. 

cy.get('#email')
.focus()

cy.get('#email')
.should('have.focus')

Esse tipo de validação pode ser útil em formulários que direcionam automaticamente o foco para um campo.

Exemplo:

Depois de abrir um formulário de login, podemos verificar se o campo de e-mail recebeu foco automaticamente.

12. Combinando validações de estado

Podemos realizar várias validações em sequência para verificar o comportamento completo de um componente. 

cy.get('#salvar')
.should('be.visible')
.should('be.enabled')

Também podemos escrever as validações em uma única cadeia: 

cy.get('#salvar')
.should('be.visible')
.and('be.enabled')

O and() permite adicionar outra asserção ao mesmo elemento.

13. Exemplo prático

Imagine um formulário de cadastro no qual o botão "Cadastrar" deve permanecer desabilitado enquanto os dados obrigatórios não forem preenchidos.

Podemos validar o comportamento: 

cy.get('#cadastrar')
.should('be.visible')
.and('be.disabled')

Depois de preencher os campos: 

cy.get('#nome')
.type('Maria')

cy.get('#email')
.type('maria@email.com')

cy.get('#senha')
.type('Senha123')

Podemos então validar que o botão foi habilitado: 

cy.get('#cadastrar')
.should('be.enabled')
Observe o cenário:

Antes do preenchimento → botão desabilitado.

Depois do preenchimento → botão habilitado.

Esse tipo de teste valida o comportamento da interface de acordo com as condições do formulário.

14. Principais validações de estado

Asserção Objetivo
be.visible Verifica se o elemento está visível.
not.be.visible Verifica se o elemento não está visível.
exist Verifica se o elemento existe no DOM.
not.exist Verifica se o elemento não existe no DOM.
be.enabled Verifica se o elemento está habilitado.
be.disabled Verifica se o elemento está desabilitado.
be.checked Verifica se checkbox ou radio está marcado.
not.be.checked Verifica se checkbox ou radio está desmarcado.
have.focus Verifica se o elemento possui foco.

Erros comuns ao validar estados

❌

Confundir exist com visible

Um elemento pode existir no DOM sem estar visível para o usuário.

❌

Validar o elemento errado

Utilize seletores que identifiquem exatamente o componente que deve ser validado.

❌

Ignorar o comportamento esperado

A asserção deve representar uma regra real da aplicação.

❌

Usar esperas fixas

Evite utilizar cy.wait() apenas para aguardar uma mudança de estado.

Boas práticas

🎯

Valide comportamentos reais

Crie asserções relacionadas às regras e comportamentos esperados da aplicação.

🔎

Use seletores confiáveis

Prefira seletores estáveis para localizar os elementos que serão validados.

🧪

Combine ação e validação

Sempre que fizer sentido, valide o estado antes e depois de uma interação.

🚫

Evite esperas desnecessárias

Aproveite as esperas automáticas do Cypress para tornar os testes mais confiáveis.
