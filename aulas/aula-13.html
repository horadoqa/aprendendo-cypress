O que é o cy.visit()?

O cy.visit() é um comando do Cypress utilizado para navegar até uma determinada URL.

Ele normalmente é utilizado no início de um teste quando precisamos acessar uma página da aplicação que será testada. 

cy.visit('http://localhost:3000')

🌐 cy.visit() → navega para uma URL.

🧪 Teste → executa comandos depois que a página é acessada.

🎯 Objetivo → colocar o navegador na página que será testada.

1. Sintaxe básica

A sintaxe básica do comando é simples: 

cy.visit('URL')

Por exemplo: 

cy.visit('https://example.com')

Nesse caso, o Cypress navegará até o endereço informado.

1️⃣

cy

Representa o objeto utilizado para acessar os comandos do Cypress.

2️⃣

visit

Comando responsável por navegar para uma URL.

3️⃣

URL

Endereço da página que deverá ser acessada.

2. Utilizando uma URL completa

Podemos informar uma URL completa diretamente no comando cy.visit(). 

cy.visit('https://example.com')

Também podemos acessar uma aplicação local: 

cy.visit('http://localhost:3000')

Ou uma página específica: 

cy.visit('http://localhost:3000/login')
Importante:

Quando trabalhamos com uma aplicação local, o endereço utilizado precisa corresponder ao endereço em que a aplicação realmente está executando.

3. Utilizando a baseUrl

Na Aula 8, aprendemos que podemos configurar uma baseUrl no arquivo cypress.config.js.

Por exemplo: 

e2e: {

baseUrl: 'http://localhost:3000'

}

Depois de configurar a baseUrl, podemos utilizar caminhos relativos no cy.visit(). 

cy.visit('/')

Para acessar uma página de login: 

cy.visit('/login')

Para acessar uma página de produtos: 

cy.visit('/produtos')

🌐 baseUrl: http://localhost:3000

🔗 /login → http://localhost:3000/login

🔗 /produtos → http://localhost:3000/produtos

4. Criando o primeiro teste com cy.visit()

Podemos utilizar o cy.visit() dentro de um teste Cypress. 

describe('Navegação', () => {

it('deve acessar a página inicial', () => {

    cy.visit('/')

})

})

Quando esse teste for executado, o Cypress abrirá a aplicação definida pela baseUrl.

Fluxo:

1️⃣ Inicia o teste.

2️⃣ Executa o cy.visit().

3️⃣ Navega para a URL.

4️⃣ Continua a execução dos comandos seguintes.

5. cy.visit() com uma validação

O cy.visit() normalmente será apenas o primeiro passo do teste. Depois da navegação, podemos validar a página. 

describe('Página inicial', () => {

it('deve carregar a página inicial', () => {

    cy.visit('/')

    cy.get('h1')
        .should('be.visible')

})

})

Nesse exemplo, o teste realiza duas etapas:

🌐

Navegação

O cy.visit() acessa a página inicial.

🔎

Localização

O cy.get() localiza o elemento h1.

✅

Validação

O should() verifica se o elemento está visível.

6. Navegando entre diferentes páginas

Podemos utilizar o cy.visit() para acessar diferentes rotas da aplicação. 

cy.visit('/')

cy.visit('/login')

cy.visit('/produtos')

cy.visit('/contato')

Cada chamada do comando realiza uma nova navegação.

Atenção:

Em um teste real, normalmente não precisamos visitar várias páginas apenas para testar navegação. O fluxo deve representar o comportamento que queremos validar.

7. Exemplo: acessando uma página de login

Imagine que nossa aplicação possui uma página de login em /login.

Podemos criar o seguinte teste: 

describe('Login', () => {

it('deve acessar a página de login', () => {

    cy.visit('/login')

    cy.get('h1')
        .should('contain', 'Login')

})

})

Nesse caso, o Cypress acessa a rota /login e depois valida o conteúdo da página.

8. Trabalhando com rotas

O cy.visit() também é bastante utilizado para testar diferentes rotas de uma aplicação web. 

describe('Rotas da aplicação', () => {

it('deve acessar a página de produtos', () => {

    cy.visit('/produtos')

})

})

Podemos criar testes específicos para cada fluxo importante da aplicação.

🏠

Página inicial

/

🔐

Login

/login

🛒

Produtos

/produtos

👤

Perfil

/perfil

9. Trabalhando com query strings

O cy.visit() também pode receber URLs que possuem parâmetros de consulta.

Por exemplo: 

cy.visit('/produtos?categoria=notebook')

Nesse caso, a aplicação receberá a URL: 

http://localhost:3000/produtos?categoria=notebook
Exemplo prático:

Podemos utilizar parâmetros na URL para testar filtros, buscas ou diferentes estados da aplicação.

10. Trabalhando com parâmetros na URL

Algumas aplicações utilizam identificadores diretamente no caminho da URL.

Por exemplo: 

/produtos/123

Podemos acessar essa página utilizando: 

cy.visit('/produtos/123')

Esse tipo de URL é comum em páginas que representam um recurso específico.

🆔

ID

Identificador do recurso acessado.

🔗

Rota

Caminho utilizado para chegar ao recurso.

11. Utilizando opções no cy.visit()

O cy.visit() também aceita opções adicionais quando precisamos de um comportamento específico.

Um exemplo é definir um tempo de espera para o carregamento da página: 

cy.visit('/login', {

timeout: 10000

})

Nesse exemplo, o comando recebe um objeto de configuração como segundo argumento.

Boa prática:

Utilize opções adicionais somente quando houver uma necessidade real. Evite configurar valores diferentes em todos os testes sem entender o motivo.

12. Validando a URL depois do visit()

Depois de utilizar o cy.visit(), podemos validar se o navegador está na URL esperada. 

cy.visit('/login')

cy.url()
.should('include', '/login')

Também podemos validar a URL completa quando isso fizer sentido para o teste. 

cy.url()
.should('eq', 'http://localhost:3000/login')

🌐 cy.visit() → realiza a navegação.

🔎 cy.url() → permite consultar a URL atual.

✅ should() → valida se a URL corresponde ao esperado.

13. Criando um teste completo

Podemos combinar navegação e validações em um único teste. 

describe('Página de login', () => {

it('deve acessar a página de login', () => {

    cy.visit('/login')

    cy.url()
        .should('include', '/login')

    cy.get('h1')
        .should('be.visible')

})

})

O fluxo do teste pode ser entendido da seguinte forma:

1️⃣ Acessar a aplicação.

2️⃣ Navegar para /login.

3️⃣ Verificar a URL.

4️⃣ Verificar se o título da página está visível.

14. Utilizando cy.visit() com beforeEach()

Quando vários testes precisam começar na mesma página, podemos utilizar o hook beforeEach(). 

describe('Página de produtos', () => {

beforeEach(() => {

    cy.visit('/produtos')

})

it('deve exibir os produtos', () => {

    cy.get('.produto')
        .should('be.visible')

})

it('deve exibir o título', () => {

    cy.get('h1')
        .should('be.visible')

})

})

Nesse exemplo, o cy.visit() será executado antes de cada teste.

Vantagem:

Evitamos repetir a mesma navegação em todos os testes que precisam iniciar na mesma página.

Erros comuns ao utilizar cy.visit()

❌

URL incorreta

Informar uma URL que não existe ou não corresponde à aplicação em execução.

❌

Aplicação desligada

Tentar acessar localhost quando o servidor da aplicação não está executando.

❌

BaseUrl incorreta

Configurar uma baseUrl diferente do endereço utilizado pela aplicação.

❌

Repetir navegação sem necessidade

Utilizar vários cy.visit() sem que isso faça parte do cenário que está sendo testado.

Boas práticas com cy.visit()

🌐

Utilize baseUrl

Centralize o endereço principal da aplicação no arquivo de configuração.

🎯

Teste um comportamento por vez

Evite criar testes com navegações que não possuem relação com o cenário validado.

🔎

Valide a navegação

Quando fizer sentido, valide a URL ou elementos da página após a navegação.

♻️

Evite duplicação

Utilize hooks como beforeEach() quando vários testes precisarem da mesma preparação.
