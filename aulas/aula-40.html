AULA 40 • TESTES REUTILIZÁVEIS

Testes Reutilizáveis

Aprenda a reduzir duplicação, reutilizar comportamentos e organizar testes Cypress de forma mais simples, consistente e fácil de manter.

Objetivos da aula

Em uma suíte de testes maior, é comum encontrarmos os mesmos comandos, dados e comportamentos repetidos em diferentes arquivos.

Nesta aula vamos aprender estratégias para transformar esses comportamentos em estruturas reutilizáveis.

♻️

Evitar duplicação

Identificar trechos de código que aparecem repetidamente nos testes.

🧩

Criar reutilização

Transformar comportamentos comuns em estruturas que podem ser utilizadas novamente.

🧪

Melhorar os testes

Tornar os cenários mais objetivos e fáceis de compreender.

🛠️

Facilitar manutenção

Reduzir o impacto de alterações na aplicação sobre a suíte de testes.

O que são testes reutilizáveis?

Testes reutilizáveis são testes ou partes de testes estruturados de forma que determinados comportamentos possam ser utilizados em diferentes cenários.

A ideia não é simplesmente copiar e colar um teste. O objetivo é identificar comportamentos que possuem uma responsabilidade bem definida e que podem ser reaproveitados. 

login()

criarUsuario()

adicionarProduto()

finalizarCompra()

♻️ Reutilização → evita repetir a mesma implementação em vários testes.

🎯 Responsabilidade → cada estrutura deve possuir uma finalidade clara.

🛠️ Manutenção → alterações podem ser concentradas em um único lugar.

1. O problema da duplicação

Imagine que vários testes precisem realizar o mesmo processo de login.

Uma abordagem pouco reutilizável seria repetir todo o código em cada cenário: 

it('deve acessar o perfil', () => {

cy.visit('/login')

cy.get('#email')
.type('usuario@teste.com')

cy.get('#senha')
.type('123456')

cy.get('#login')
.click()

cy.get('#perfil')
.click()

})

Outro teste poderia repetir exatamente o mesmo processo: 

it('deve acessar pedidos', () => {

cy.visit('/login')

cy.get('#email')
.type('usuario@teste.com')

cy.get('#senha')
.type('123456')

cy.get('#login')
.click()

cy.get('#pedidos')
.click()

})

Quanto maior a suíte, maior pode ser o custo de manter trechos duplicados.

2. Reutilizando lógica com funções

Uma das formas de reutilizar comportamento em JavaScript é criar uma função. 

function login() {

cy.visit('/login')

cy.get('#email')
.type('usuario@teste.com')

cy.get('#senha')
.type('123456')

cy.get('#login')
.click()

}

Depois podemos chamar essa função em diferentes testes: 

login()

cy.get('#perfil')
.click()

Outro cenário pode utilizar o mesmo comportamento: 

login()

cy.get('#pedidos')
.click()

Funções podem ser úteis quando queremos encapsular uma lógica específica e reaproveitá-la em diferentes pontos.

3. Reutilização com parâmetros

Uma função pode receber parâmetros para tornar seu comportamento mais flexível. 

function login(email, senha) {

cy.visit('/login')

cy.get('#email')
.type(email)

cy.get('#senha')
.type(senha)

cy.get('#login')
.click()

}

Agora podemos utilizar diferentes usuários: 

login(
'usuario@teste.com',
'123456'

)

Ou: 

login(
'administrador@teste.com',
'admin123'

)
Vantagem:

O comportamento continua sendo o mesmo, mas os dados podem variar de acordo com o cenário.

4. Reutilizando comportamentos com Custom Commands

Em projetos Cypress, comportamentos recorrentes também podem ser transformados em Custom Commands.

Por exemplo, podemos criar um comando de login: 

Cypress.Commands.add(
'login',
(email, senha) => {

cy.visit('/login')

cy.get('#email')
    .type(email)

cy.get('#senha')
    .type(senha)

cy.get('#login')
    .click()

})

O teste pode então utilizar o comando: 

cy.login(
'usuario@teste.com',
'123456'

)

Custom Commands são especialmente úteis para comportamentos recorrentes que fazem sentido como comandos da aplicação de teste.

5. Reutilização com Page Objects

Outra estratégia é encapsular elementos e ações de uma página em uma classe ou objeto. 

class LoginPage {

visitar() {

    cy.visit('/login')

}

preencherEmail(email) {

    cy.get('#email')
        .type(email)

}

preencherSenha(senha) {

    cy.get('#senha')
        .type(senha)

}

clicarLogin() {

    cy.get('#login')
        .click()

}

}

O teste pode utilizar esses comportamentos: 

const loginPage = new LoginPage()

loginPage.visitar()

loginPage.preencherEmail(
'usuario@teste.com'
)

loginPage.preencherSenha(
'123456'
)

loginPage.clicarLogin()

O objetivo é separar detalhes de interação da lógica principal dos cenários.

6. Reutilizando dados com fixtures

Além de reutilizar comportamentos, também podemos reutilizar dados de teste.

Por exemplo: 

{

"email": "usuario@teste.com",
"senha": "123456"

}

O teste pode carregar esses dados: 

cy.fixture('usuario.json')
.then((usuario) => {

cy.login(
    usuario.email,
    usuario.senha
)

})

Dessa maneira, os dados e a lógica do teste permanecem separados.

7. Reutilizando preparação com hooks

Hooks como beforeEach() podem ser utilizados para preparar o estado necessário antes de diferentes testes. 

beforeEach(() => {

cy.login(
'usuario@teste.com',
'123456'
)

})

Os testes podem então começar diretamente pelo comportamento que desejam validar: 

it('deve acessar o perfil', () => {

cy.get('#perfil')
.click()

})
it('deve acessar os pedidos', () => {

cy.get('#pedidos')
.click()

})

Hooks podem reduzir repetição quando existe uma preparação realmente compartilhada entre cenários.

8. Reutilizando cenários com dados diferentes

Podemos utilizar arrays de objetos para executar uma mesma estrutura de teste com diferentes dados. 

const usuarios = [

{
    email: 'usuario1@teste.com',
    senha: '123456'
},

{
    email: 'usuario2@teste.com',
    senha: '654321'
}

]

Depois podemos percorrer os dados: 

usuarios.forEach((usuario) => {

it(`deve realizar login com ${usuario.email}`, () => {

    cy.login(
        usuario.email,
        usuario.senha
    )

})

})

A estrutura do cenário é reutilizada enquanto os dados variam entre as execuções.

9. Antes e depois da reutilização

Considere três testes que precisam realizar login.

Sem reutilização: 

cy.visit('/login')

cy.get('#email').type('usuario@teste.com')
cy.get('#senha').type('123456')
cy.get('#login').click()

cy.visit('/login')
cy.get('#email').type('usuario@teste.com')
cy.get('#senha').type('123456')
cy.get('#login').click()

Com reutilização: 

cy.login(
'usuario@teste.com',
'123456'

)
📉

Menos código

O teste possui menos detalhes repetidos.

🎯

Mais foco

O cenário destaca o comportamento que realmente está sendo validado.

🛠️

Manutenção

Uma alteração pode ser concentrada na implementação reutilizada.

10. Quando criar uma estrutura reutilizável?

Nem todo trecho de código precisa ser transformado em uma função, comando ou abstração.

Antes de criar uma estrutura reutilizável, observe se o comportamento realmente aparece em diferentes cenários.

🔁

Repetição real

O comportamento aparece em vários testes e possui a mesma finalidade.

🎯

Responsabilidade clara

O trecho pode ser descrito por uma ação ou responsabilidade específica.

🧩

Interface estável

O comportamento possui uma forma consistente de ser utilizado pelos testes.

⚠️

Evite abstração excessiva

Não transforme pequenos trechos únicos em abstrações difíceis de entender.

11. Cuidado com abstrações excessivas

Reutilização deve facilitar a manutenção, não esconder completamente o comportamento do teste.

Uma função extremamente genérica pode acabar tornando o teste mais difícil de compreender. 

executarAcao(
'login',
'usuario',
'modo-rapido',
'validar',
'dashboard'

)

Muitas opções dentro de uma única abstração podem esconder o que realmente está acontecendo.

Princípio importante:

Prefira abstrações simples, claras e específicas para comportamentos que realmente precisam ser reutilizados.

12. Uma possível organização do projeto

Um projeto Cypress pode separar diferentes tipos de responsabilidades: 

cypress/

├── e2e/
│ ├── login.cy.js
│ ├── perfil.cy.js
│ └── pedidos.cy.js
│
├── fixtures/
│ ├── usuario.json
│ └── produtos.json
│
└── support/
├── commands.js
└── e2e.js

pages/

├── LoginPage.js
├── PerfilPage.js
└── PedidosPage.js

A estrutura exata pode variar conforme o projeto. O importante é manter responsabilidades relacionadas organizadas e fáceis de localizar.

13. Exemplo completo

Vamos combinar Custom Command, fixture e um teste reutilizável.

Fixture: 

{

"email": "usuario@teste.com",
"senha": "123456"
}

Custom Command: 

Cypress.Commands.add(
'login',
(email, senha) => {

cy.visit('/login')

cy.get('#email')
    .type(email)

cy.get('#senha')
    .type(senha)

cy.get('#login')
    .click()

})

Teste: 

describe('Área autenticada', () => {

beforeEach(() => {

cy.fixture('usuario.json')
    .as('usuario')

})

it('deve acessar o perfil', () => {

cy.get('@usuario')
    .then((usuario) => {

        cy.login(
            usuario.email,
            usuario.senha
        )

    })

cy.get('#perfil')
    .click()

})

it('deve acessar os pedidos', () => {

cy.get('@usuario')
    .then((usuario) => {

        cy.login(
            usuario.email,
            usuario.senha
        )

    })

cy.get('#pedidos')
    .click()

})

})

Observe como cada responsabilidade foi separada:

📄 Fixture → armazena os dados.

🧩 Custom Command → encapsula o comportamento de login.

🧪 Spec → descreve os cenários que queremos validar.

Benefícios dos testes reutilizáveis

♻️

Reutilização

O mesmo comportamento pode ser utilizado em diferentes cenários.

🧹

Menos duplicação

Reduzimos trechos repetidos dentro das specs.

🔧

Manutenção centralizada

Alterações em comportamentos compartilhados podem ser feitas em um único lugar.

📖

Legibilidade

Os testes podem ficar mais focados no comportamento que está sendo validado.

Erros comuns

❌

Copiar e colar

Repetir o mesmo comportamento em muitos arquivos sem avaliar a possibilidade de reutilização.

❌

Funções gigantes

Criar uma função que executa várias responsabilidades diferentes.

❌

Abstração excessiva

Esconder tantos detalhes que o teste se torna difícil de compreender.

❌

Dados misturados

Misturar dados de teste com comportamentos reutilizáveis sem uma separação clara.

Boas práticas

🎯

Tenha uma responsabilidade

Cada função, comando ou estrutura reutilizável deve possuir uma finalidade clara.

🧩

Use parâmetros

Permita que comportamentos reutilizáveis recebam dados quando necessário.

📝

Mantenha nomes claros

Os nomes devem explicar facilmente o comportamento executado.

⚖️

Busque equilíbrio

Reutilize quando fizer sentido sem transformar o projeto em uma camada excessiva de abstrações.

Resumindo

♻️ Reutilização → permite aproveitar comportamentos em diferentes cenários.

🧹 Menos duplicação → reduz código repetido dentro da suíte.

🧩 Custom Commands → encapsulam comportamentos recorrentes do Cypress.

📄 Fixtures → permitem separar dados da lógica dos testes.

🏗️ Page Objects → podem organizar elementos e ações relacionados a uma página.

🔁 Parâmetros → permitem utilizar o mesmo comportamento com diferentes dados.

⚖️ Equilíbrio → reutilização deve facilitar, e não dificultar, a compreensão dos testes.
