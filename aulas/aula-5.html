O que precisamos antes de começar?

Para instalar e executar o Cypress em um projeto, precisamos preparar algumas ferramentas básicas.

🟢

Node.js

Ambiente necessário para executar aplicações JavaScript no lado do sistema.

📦

npm

Gerenciador de pacotes utilizado para instalar dependências do projeto.

💻

Editor de código

Ferramenta utilizada para criar e editar os arquivos dos testes.

🌐

Navegador

Será utilizado pelo Cypress para executar os testes de aplicações web.

1. O que é Node.js?

O Node.js é um ambiente de execução que permite executar JavaScript fora do navegador.

No contexto deste curso, ele será importante porque o projeto Cypress utiliza o ecossistema do Node.js e seu gerenciador de pacotes.

De forma simples:

Node.js → ambiente de execução.

npm → gerenciador de pacotes.

Cypress → ferramenta de testes instalada no projeto.

Verificando a instalação do Node.js

Depois de instalar o Node.js, podemos verificar se ele está disponível no terminal. 

node --version

Também podemos verificar a versão do npm: 

npm --version
Importante:

Os números de versão podem mudar ao longo do tempo. Por isso, o importante neste momento é confirmar que os comandos estão disponíveis no ambiente.

2. Criando um projeto

O Cypress pode ser instalado dentro de um projeto Node.js.

Primeiro, vamos criar uma pasta para o nosso projeto. 

mkdir curso-cypress

Depois, entramos na pasta: 

cd curso-cypress

Agora podemos inicializar um projeto Node.js: 

npm init -y

O comando npm init -y cria um arquivo chamado package.json utilizando as configurações padrão.

O que é o package.json?

O arquivo package.json contém informações importantes sobre um projeto Node.js.

Ele pode armazenar informações como nome do projeto, scripts, versão e dependências. 

{
    "name": "curso-cypress",
    "version": "1.0.0",
    "scripts": {},
    "dependencies": {}
}
Para guardar:

package.json → descreve e configura o projeto Node.js.

3. Instalando o Cypress

Com o projeto criado, podemos adicionar o Cypress como uma dependência de desenvolvimento. 

npm install cypress --save-dev

A instalação adicionará o Cypress ao projeto e registrará a dependência no arquivo package.json.

--save-dev indica que o pacote é uma dependência utilizada durante o desenvolvimento e os testes do projeto.

O que é a pasta node_modules?

Durante a instalação das dependências, o npm cria a pasta node_modules.

Nela ficam os pacotes instalados e suas dependências.

📦

package.json

Define as dependências e configurações do projeto.

📦

package-lock.json

Registra informações das versões e da árvore de dependências instalada.

🗂️

node_modules

Contém os pacotes instalados pelo npm.

4. Abrindo o Cypress

Depois da instalação, podemos abrir a interface do Cypress através do terminal. 

npx cypress open

O comando npx permite executar um pacote disponível no projeto.

Fluxo:

Projeto → npm → Cypress → Interface do Cypress.

O que acontece na primeira abertura?

Ao abrir o Cypress pela primeira vez em um projeto, a ferramenta apresenta opções para configurar o ambiente de testes.

🌐

E2E Testing

Configuração voltada para testes de fluxos completos de aplicações.

🧩

Component Testing

Configuração voltada para testes de componentes suportados.

Neste curso, nosso foco inicial será a automação de aplicações web através dos testes E2E.

Estrutura inicial do projeto

Depois da configuração, o projeto passa a possuir arquivos e diretórios relacionados aos testes.

│

│

Essa estrutura pode variar de acordo com a versão do Cypress e as configurações utilizadas no projeto.

Pasta cypress/e2e

A pasta cypress/e2e é utilizada para armazenar os arquivos dos testes E2E.

Por exemplo: 

cypress/
└── e2e/
    ├── login.cy.js
    ├── cadastro.cy.js
    └── produtos.cy.js
Convenção:

Arquivos de teste do Cypress normalmente utilizam a extensão .cy.js ou .cy.ts, dependendo da linguagem utilizada.

Pasta cypress/support

A pasta support pode armazenar arquivos utilizados para configurações e recursos compartilhados pelos testes.

⚙️

Configuração

Podemos centralizar comportamentos e configurações utilizadas pelos testes.

🧩

Comandos personalizados

Podemos criar comandos personalizados para reutilizar ações.

♻️

Reutilização

Recursos compartilhados ajudam a evitar duplicação desnecessária.

Pasta cypress/fixtures

A pasta fixtures pode ser utilizada para armazenar dados que serão utilizados pelos testes.

Por exemplo, podemos criar um arquivo JSON: 

{
    "email": "usuario@email.com",
    "senha": "123456"
}

Esses dados podem posteriormente ser carregados pelos testes conforme a necessidade.

Arquivo cypress.config.js

O arquivo cypress.config.js é utilizado para configurações do Cypress.

Podemos, por exemplo, definir uma URL base para a aplicação que será testada. 

const { defineConfig } = require('cypress')

module.exports = defineConfig({

    e2e: {

        baseUrl: 'http://localhost:3000'

    }

})

Com uma baseUrl configurada, podemos utilizar caminhos relativos nos testes.

O que é baseUrl?

A baseUrl representa a URL base da aplicação que será testada.

Por exemplo: 

baseUrl: 'http://localhost:3000'

Podemos então escrever: 

cy.visit('/login')

Em vez de repetir: 

cy.visit(
    'http://localhost:3000/login'
)

A configuração da URL base ajuda a deixar os testes mais simples e centraliza uma informação importante do ambiente.

Criando um script para o Cypress

Também podemos adicionar comandos personalizados ao package.json. 

{
    "scripts": {
        "cy:open": "cypress open",
        "cy:run": "cypress run"
    }
}

Depois podemos executar: 

npm run cy:open

Ou executar os testes em modo headless: 

npm run cy:run

Cypress Open × Cypress Run

Comando Objetivo Uso comum
cypress open Abre a interface do Cypress. Desenvolvimento e investigação dos testes.
cypress run Executa os testes através da linha de comando. Automação, CI/CD e execução sem a interface.

Criando nosso primeiro arquivo de teste

Podemos criar um arquivo chamado: 

cypress/e2e/primeiro-teste.cy.js

Dentro dele podemos escrever: 

describe('Minha primeira suíte', () => {

    it('deve acessar a aplicação', () => {

        cy.visit('/')

    })

})

Esse será o primeiro passo para começarmos a construir nossa suíte de testes.

O que são describe() e it()?

📁

describe()

Organiza um conjunto de testes relacionados a determinado contexto ou funcionalidade.

🧪

it()

Define um caso de teste específico. 

describe('Login', () => {

    it('deve realizar login', () => {

        // passos do teste

    })

})

Um fluxo inicial completo

Vamos combinar os conceitos aprendidos até aqui. 

describe('Página inicial', () => {

    it('deve carregar a aplicação', () => {

        cy.visit('/')

        cy.get('h1')
            .should('be.visible')

    })

})

1. O teste é organizado dentro de describe().

2. O caso de teste é definido por it().

3. cy.visit() acessa a aplicação.

4. cy.get() localiza o elemento.

5. should() realiza a verificação.

Erros comuns

❌ Instalar o Cypress globalmente

Em projetos, o Cypress normalmente deve ser instalado como dependência do próprio projeto, permitindo controlar sua versão junto ao código.

❌ Não inicializar o projeto

Antes de instalar dependências do projeto, precisamos possuir um projeto Node.js adequadamente configurado.

❌ Alterar node_modules manualmente

Dependências devem ser gerenciadas pelo npm e pelos arquivos de configuração do projeto.

❌ Confundir cypress open com cypress run

O primeiro abre a interface do Cypress, enquanto o segundo executa os testes através da linha de comando.

❌ Versionar node_modules

A pasta node_modules normalmente não deve ser adicionada ao controle de versão. As dependências podem ser restauradas através do package.json e package-lock.json.
