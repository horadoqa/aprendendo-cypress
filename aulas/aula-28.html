O que é cy.fixture()?

O cy.fixture() é um comando do Cypress utilizado para carregar dados armazenados na pasta cypress/fixtures.

Esses dados normalmente são utilizados como massa de teste durante a execução das specs. 

cy.fixture('usuario.json')

📁 Fixture → arquivo que contém dados de teste.

📥 cy.fixture() → comando utilizado para carregar esses dados.

🧪 Teste → utiliza os dados carregados durante a execução.

1. Onde ficam os fixtures?

Por padrão, os arquivos de fixture ficam dentro da pasta: 

cypress/fixtures/

Um projeto pode possuir uma estrutura semelhante a esta: 

curso-cypress/

├── cypress/
│
│ ├── e2e/
│ │ └── login.cy.js
│ │
│ ├── fixtures/
│ │ └── usuario.json
│ │
│ └── support/
│
├── cypress.config.js
├── package.json
└── package-lock.json

O arquivo usuario.json será utilizado como fonte de dados para nossos testes.

2. Criando nosso primeiro fixture

Vamos criar um arquivo chamado: 

cypress/fixtures/usuario.json

Dentro dele podemos armazenar informações de um usuário de teste: 

{
"nome": "Maria",
"email": "maria@teste.com",
"senha": "123456"

}

Agora temos um conjunto de dados separado do arquivo da spec.

👤

Nome

Identificação do usuário utilizado no teste.

📧

E-mail

Endereço de e-mail utilizado como massa de teste.

🔑

Senha

Senha utilizada pelo cenário de teste.

3. Carregando um fixture

Para carregar o arquivo, utilizamos o comando cy.fixture(). 

cy.fixture('usuario.json')

O Cypress procura o arquivo dentro da pasta configurada para fixtures.

Por isso, não precisamos informar o caminho completo: 

cy.fixture('usuario.json')

Em vez de: 

cy.fixture('cypress/fixtures/usuario.json')
Boa prática:

Utilize o nome do fixture em vez de repetir o caminho completo da pasta.

4. Acessando os dados com then()

O cy.fixture() retorna os dados carregados para a cadeia de comandos do Cypress.

Podemos acessar essas informações utilizando .then(). 

cy.fixture('usuario.json').then((usuario) => {

cy.log(usuario.nome)

})

Nesse exemplo, o objeto carregado foi armazenado na variável usuario.

Podemos acessar suas propriedades: 

usuario.nome

usuario.email

usuario.senha

O valor recebido pelo then() representa o conteúdo carregado pelo fixture.

5. Utilizando fixture em um login

Uma aplicação bastante comum para fixtures é armazenar credenciais de usuários de teste.

Considere o arquivo: 

{
"email": "usuario@teste.com",
"senha": "123456"

}

Podemos utilizar essas informações no teste: 

cy.fixture('usuario.json').then((usuario) => {

cy.visit('/login')

cy.get('[data-testid="email"]')
    .type(usuario.email)

cy.get('[data-testid="senha"]')
    .type(usuario.senha)

cy.get('[data-testid="login"]')
    .click()

})

O teste não precisa armazenar diretamente os dados do usuário dentro da spec.

Os dados foram separados em um arquivo próprio.

6. Utilizando fixtures com assertions

Os dados carregados também podem ser utilizados para realizar validações. 

cy.fixture('usuario.json').then((usuario) => {

cy.visit('/perfil')

cy.get('[data-testid="nome"]')
    .should('contain', usuario.nome)

})

Nesse caso, o valor esperado vem diretamente do arquivo de fixture.

📄

Dados esperados

O fixture contém os valores esperados pelo teste.

🧪

Aplicação

A aplicação apresenta os dados durante a execução do cenário.

✅

Assertion

O teste compara o resultado com os dados esperados.

7. Trabalhando com objetos maiores

Um fixture pode possuir estruturas mais completas. 

{
"usuario": {
    "nome": "Maria",
    "email": "maria@teste.com"
},

"endereco": {
    "cidade": "São Paulo",
    "estado": "SP"
}

}

Podemos acessar propriedades aninhadas: 

cy.fixture('cliente.json').then((cliente) => {

cy.log(cliente.usuario.nome)

cy.log(cliente.endereco.cidade)

})

Estruturas maiores podem ser úteis quando o cenário precisa de vários dados relacionados.

8. Fixtures com listas

Também podemos armazenar arrays em arquivos JSON. 

{
"produtos": [
    {
        "nome": "Notebook",
        "preco": 3500
    },
    {
        "nome": "Mouse",
        "preco": 150
    }
]

}

Podemos acessar os itens durante o teste: 

cy.fixture('produtos.json').then((dados) => {

cy.log(dados.produtos[0].nome)

cy.log(dados.produtos[1].nome)

})

Arrays são úteis quando precisamos trabalhar com vários registros de uma mesma entidade.

9. Tipos de arquivos utilizados como fixtures

Fixtures não precisam ser limitados a arquivos JSON. O Cypress também suporta outros formatos.

Formato Exemplo Utilização
JSON usuario.json Dados estruturados.
CSV usuarios.csv Dados tabulares.
TXT texto.txt Conteúdo textual.
Imagens imagem.png Arquivos utilizados em cenários específicos.

10. Especificando a extensão

Em determinadas situações, podemos informar explicitamente o nome do arquivo com sua extensão. 

cy.fixture('dados.json')

Para arquivos com outros formatos, a extensão ajuda a identificar o arquivo que será carregado. 

cy.fixture('usuarios.csv')

cy.fixture('texto.txt')
Boa prática:

Utilize nomes de arquivos claros e consistentes para facilitar a manutenção dos testes.

11. Fixtures como massa de teste

Uma das principais vantagens dos fixtures é separar os dados da lógica do teste.

Sem fixture: 

cy.get('#nome')
.type('Maria')

cy.get('#email')
.type('maria@teste.com')

Utilizando fixture: 

cy.fixture('usuario.json').then((usuario) => {

cy.get('#nome')
    .type(usuario.nome)

cy.get('#email')
    .type(usuario.email)

})

A segunda abordagem permite alterar os dados sem precisar modificar a lógica principal do teste.

12. Utilizando alias com fixtures

Também podemos criar um alias para os dados carregados. 

cy.fixture('usuario.json')
.as('usuario')

Depois podemos acessar o alias durante o teste: 

cy.get('@usuario').then((usuario) => {

cy.log(usuario.nome)

})

Aliases podem ajudar quando os mesmos dados precisam ser acessados em diferentes etapas de um cenário.

13. Carregando fixture com beforeEach()

Fixtures podem ser carregados dentro de hooks quando vários testes precisam dos mesmos dados. 

beforeEach(() => {

cy.fixture('usuario.json')
    .as('usuario')

})

Depois, os testes podem utilizar o alias: 

it('deve realizar login', () => {

cy.get('@usuario').then((usuario) => {

    cy.visit('/login')

    cy.get('#email')
        .type(usuario.email)

    cy.get('#senha')
        .type(usuario.senha)

})

})

Essa abordagem pode ser útil quando diversos cenários compartilham a mesma massa de dados.

14. Organizando vários fixtures

Projetos maiores podem possuir diversos arquivos de dados. 

cypress/

├── fixtures/
│
├── usuario.json
├── administrador.json
├── produtos.json
├── clientes.json
└── pedidos.json

Outra possibilidade é organizar os dados em subpastas: 

cypress/

└── fixtures/

├── usuarios/
│   ├── comum.json
│   └── administrador.json
│
└── produtos/
    ├── eletronicos.json
    └── moveis.json

Em projetos grandes, uma boa organização dos fixtures facilita a localização e manutenção dos dados.

15. Exemplo completo

Vamos combinar os conceitos estudados em um cenário de login.

Fixture: 

{
"email": "usuario@teste.com",
"senha": "123456"

}

Teste: 

describe('Login', () => {

beforeEach(() => {

    cy.fixture('usuario.json')
        .as('usuario')

})

it('deve realizar login com sucesso', () => {

    cy.get('@usuario').then((usuario) => {

        cy.visit('/login')

        cy.get('#email')
            .type(usuario.email)

        cy.get('#senha')
            .type(usuario.senha)

        cy.get('#login')
            .click()

        cy.url()
            .should('include', 'dashboard')

    })

})

})

Observe que o teste contém a lógica do cenário, enquanto os dados do usuário ficam separados no fixture.

Erros comuns ao utilizar cy.fixture()

❌

Nome incorreto

Informar um nome de arquivo que não existe na pasta de fixtures.

❌

JSON inválido

Utilizar uma estrutura JSON com erros de sintaxe.

❌

Propriedade incorreta

Tentar acessar uma propriedade que não existe no objeto carregado.

❌

Dados sensíveis

Armazenar senhas reais, tokens ou outras informações sensíveis diretamente no fixture.

Boas práticas com fixtures

📁

Organize os arquivos

Utilize nomes claros e uma estrutura de pastas coerente.

🎯

Use dados específicos

Mantenha os dados relacionados aos cenários que realmente precisam deles.

♻️

Evite duplicação

Reutilize fixtures quando os mesmos dados forem necessários em diferentes testes.

🔐

Proteja dados sensíveis

Não utilize credenciais reais ou informações confidenciais nos arquivos do projeto.
