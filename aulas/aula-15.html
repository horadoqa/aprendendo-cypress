O que é um seletor?

Um seletor é uma forma de identificar um ou mais elementos dentro de uma página HTML.

O Cypress utiliza seletores para localizar os elementos com os quais o teste precisa interagir.

Por exemplo, considere o seguinte botão: 

<button id="login">
Entrar

Podemos localizar esse elemento utilizando seu id: 

cy.get('#login')

🔎 Seletor → identifica um elemento HTML.

🧪 Cypress → utiliza o seletor para localizar o elemento.

🖱️ Comando → permite interagir com o elemento encontrado.

1. Seletores e HTML

Para trabalhar corretamente com seletores, é importante entender um pouco da estrutura HTML.

Observe o exemplo: 

<input
id="email"
class="form-input"
type="email"
name="email"

>

Esse elemento possui diferentes informações que podem ser utilizadas para sua localização.

🆔

id

Identifica o elemento através de um identificador único.

🎨

class

Identifica elementos através de uma classe CSS.

🏷️

name

Representa o nome associado ao elemento.

⚙️

type

Indica o tipo do elemento HTML.

2. Selecionando pelo id

O atributo id pode ser utilizado para identificar um elemento específico.

HTML: 

<input id="email" type="email">

Cypress: 

cy.get('#email')

Podemos combinar o comando com uma interação: 

cy.get('#email')
.type('usuario@email.com')
Boa prática:

Um id utilizado como seletor deve ser estável e representar de forma clara o elemento que será utilizado pelo teste.

3. Selecionando por class

Também podemos utilizar classes CSS para localizar elementos.

HTML: 

<button class="btn-login">
Entrar

Cypress: 

cy.get('.btn-login')

O ponto . indica que estamos procurando uma classe CSS. 

cy.get('.btn-login')
.click()
Atenção:

Classes criadas apenas para estilização podem mudar com frequência. Por isso, nem sempre são bons seletores para automação.

4. Selecionando pela tag HTML

Também podemos utilizar diretamente o nome da tag HTML.

Por exemplo: 

cy.get('button')

Esse seletor encontra elementos button presentes na página.

Outro exemplo: 

cy.get('input')
Problema:

Seletores baseados apenas na tag podem retornar vários elementos. Por isso, normalmente é melhor utilizar um seletor mais específico.

5. Selecionando por atributos

Podemos utilizar atributos HTML para criar seletores mais específicos.

Considere: 

<input
type="email"
name="email"

>

Podemos localizar pelo atributo name: 

cy.get('[name="email"]')

Também podemos utilizar o atributo type: 

cy.get('[type="email"]')
🏷️

name

Pode ser utilizado para identificar campos de formulários.

⚙️

type

Pode diferenciar tipos de elementos, como email, password e button.

🔗

href

Pode ser utilizado para identificar links específicos.

6. Seletores data-testid

Uma estratégia muito utilizada em automação é adicionar atributos específicos para testes.

Por exemplo: 

<button data-testid="login-button">
Entrar

O Cypress pode localizar o elemento através desse atributo: 

cy.get('[data-testid="login-button"]')

Essa abordagem separa a identificação utilizada pelos testes das classes utilizadas para estilização.

Boa prática:

Atributos como data-testid podem ser úteis quando a aplicação não possui identificadores estáveis adequados para os testes.

7. Criando atributos específicos para testes

O nome do atributo pode ser definido de acordo com a estratégia adotada pelo projeto.

Por exemplo: 

<button data-cy="login-button">
Entrar

No Cypress: 

cy.get('[data-cy="login-button"]')
.click()

Outra possibilidade seria: 

<input data-test="email">
cy.get('[data-test="email"]')
.type('usuario@email.com')

O mais importante é definir uma convenção consistente e utilizá-la em todo o projeto.

8. Seletores compostos

Podemos combinar diferentes características para tornar um seletor mais específico.

Por exemplo: 

cy.get('input[type="email"]')

Nesse caso, estamos procurando elementos input cujo atributo type seja email.

Também podemos combinar uma classe e um atributo: 

cy.get('.form-input[type="email"]')
Importante:

Quanto mais complexo for um seletor, maior pode ser sua sensibilidade a alterações na estrutura da aplicação. Use apenas a especificidade necessária para identificar o elemento.

9. Selecionando elementos dentro de outros elementos

Os seletores CSS também permitem representar relacionamentos entre elementos.

Considere: 

<form class="login-form">

<input type="email">

<input type="password">

Podemos localizar o campo de email dentro do formulário: 

cy.get('.login-form input[type="email"]')

Dessa forma, o seletor considera a relação entre o formulário e o campo.

10. Localizando elementos pelo texto

O Cypress também possui o comando cy.contains(), que permite localizar elementos pelo conteúdo de texto.

Por exemplo: 

cy.contains('Entrar')

Podemos utilizá-lo para encontrar um botão: 

cy.contains('button', 'Entrar')
.click()
Quando utilizar?

O cy.contains() pode ser útil quando o texto exibido na interface representa uma informação importante para o comportamento do teste.

11. O problema de utilizar posições

Uma prática que deve ser utilizada com cuidado é localizar elementos apenas pela posição.

Por exemplo: 

cy.get('button').eq(0).click()

Esse código considera que o botão desejado sempre será o primeiro botão da página.

Se outro botão for adicionado antes dele, o teste poderá passar a interagir com o elemento errado.

Prefira: 
cy.get('[data-cy="login-button"]')
.click()

quando existir um identificador estável para o elemento.

12. O que são seletores frágeis?

Um seletor frágil é aquele que pode deixar de funcionar facilmente quando a aplicação sofre pequenas alterações.

Por exemplo: 

cy.get('div.container > div:nth-child(2) > button')

Esse seletor depende fortemente da estrutura interna do HTML.

Se um novo elemento for inserido na estrutura, o seletor poderá deixar de representar o botão esperado.

Regra prática:

Quanto mais um seletor depender de detalhes internos e instáveis da interface, maior tende a ser o custo de manutenção do teste.

13. O que são seletores estáveis?

Um seletor estável utiliza uma característica do elemento que possui baixa probabilidade de sofrer alterações sem uma mudança real no comportamento da aplicação.

Um exemplo: 

<button data-cy="submit-login">
Entrar


cy.get('[data-cy="submit-login"]')
.click()
🛡️

Menos manutenção

Alterações visuais podem não exigir alterações nos testes.

🎯

Mais precisão

O teste identifica diretamente o elemento que deseja utilizar.

🔧

Fácil manutenção

O código dos testes tende a ser mais simples de entender e atualizar.

Considere o seguinte elemento: 

<button
id="btn-login"
class="btn primary"
data-cy="login-button"

>
Entrar

A escolha depende do contexto da aplicação e da estabilidade da característica utilizada para localizar o elemento.

15. Utilizando o DevTools para encontrar seletores

O navegador possui ferramentas que ajudam a investigar a estrutura HTML da aplicação.

Para abrir o DevTools, normalmente podemos utilizar F12 ou clicar com o botão direito sobre um elemento e selecionar a opção para inspecioná-lo.

Ao inspecionar um elemento, podemos visualizar seus atributos e sua estrutura HTML. 

<button
data-cy="login-button"
type="submit"

>
Entrar

A partir dessas informações, podemos construir o seletor utilizado no teste. 

cy.get('[data-cy="login-button"]')
Dica:

Não escolha automaticamente o primeiro seletor gerado pelas ferramentas do navegador. Analise se ele continuará válido quando a aplicação sofrer alterações.

16. Estratégia de seletores

Uma suíte de testes bem estruturada pode adotar uma estratégia clara para identificação dos elementos.

1️⃣

Identificador específico

Utilize um identificador estável quando ele estiver disponível.

2️⃣

Atributo de teste

Utilize data-cy, data-testid ou uma convenção equivalente.

3️⃣

Atributos semânticos

Considere atributos que representem o propósito do elemento.

4️⃣

Texto

Utilize texto quando ele fizer parte importante do comportamento esperado.

17. Exemplo prático

Considere uma página de login: 

<form>

<input
    data-cy="email"
    type="email"
>

<input
    data-cy="password"
    type="password"
>

<button
    data-cy="login-button"
    type="submit"
>
    Entrar
</button>

Podemos criar um teste utilizando os atributos definidos para automação: 

describe('Login', () => {

it('deve realizar login', () => {

cy.visit('/login')

cy.get('[data-cy="email"]')
    .type('usuario@email.com')

cy.get('[data-cy="password"]')
    .type('123456')

cy.get('[data-cy="login-button"]')
    .click()

})

})

Nesse exemplo, os testes não dependem das classes utilizadas pelo CSS da aplicação.

Os atributos data-cy foram utilizados especificamente para identificar os elementos durante a automação.

Erros comuns com seletores

❌

Utilizar classes de CSS

Depender de classes que existem apenas para controlar o visual da aplicação.

❌

Utilizar posições

Depender de índices como primeiro, segundo ou terceiro elemento.

❌

Seletores muito complexos

Criar seletores que dependem de vários níveis da estrutura HTML.

❌

Ignorar a estratégia do projeto

Criar seletores diferentes sem seguir uma convenção definida pela equipe.

Boas práticas para seletores

🎯

Prefira seletores estáveis

Utilize características que tenham significado e baixa chance de mudança.

🧪

Crie atributos de teste

Utilize data-cy, data-testid ou outra convenção definida pelo projeto.

🧹

Evite complexidade desnecessária

Utilize apenas a especificidade necessária para localizar o elemento.

📐

Padronize a estratégia

Mantenha uma convenção de seletores consistente no projeto.
