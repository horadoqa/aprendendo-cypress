AULA 7 • INSTALAÇÃO DO CYPRESS

Instalação do Cypress

Aprenda a preparar o ambiente, instalar o Cypress utilizando npm e executar a aplicação pela primeira vez.

Objetivos da aula

Agora que já conhecemos os conceitos básicos de testes e entendemos como funciona um teste Cypress, chegou o momento de preparar nosso ambiente.

Nesta aula vamos instalar o Cypress em um projeto Node.js e verificar se a instalação está funcionando corretamente.

🖥️

Preparar o ambiente

Conhecer os requisitos necessários para trabalhar com Cypress.

📦

Instalar o Cypress

Instalar o Cypress utilizando o gerenciador de pacotes npm.

⚙️

Criar o projeto

Inicializar um projeto Node.js para organizar os testes automatizados.

🚀

Executar o Cypress

Abrir a interface do Cypress e verificar se o ambiente está funcionando.

O que precisamos antes de instalar?

O Cypress é instalado como uma dependência do projeto. Por isso, antes de começar, precisamos ter um ambiente JavaScript preparado.

Para acompanhar esta aula, vamos utilizar:

🟢

Node.js

Ambiente necessário para executar aplicações JavaScript fora do navegador e utilizar o npm.

📦

npm

Gerenciador de pacotes utilizado para instalar o Cypress e outras dependências.

💻

Editor de código

Um editor como Visual Studio Code para criar e editar os arquivos do projeto.

1. Verificando o Node.js

O primeiro passo é verificar se o Node.js está instalado no computador.

Abra o terminal e execute: 

node --version

Se o Node.js estiver instalado, o terminal exibirá uma versão semelhante a: 

v22.x.x
Importante:

O número da versão pode ser diferente no seu computador. O importante neste momento é que o comando seja reconhecido pelo terminal.

2. Verificando o npm

O npm normalmente é instalado junto com o Node.js.

Para verificar se ele está disponível, execute: 

npm --version

O terminal deverá apresentar o número da versão instalada.

🟢 node --version → verifica o Node.js.

📦 npm --version → verifica o gerenciador de pacotes npm.

3. Criando um projeto para os testes

O Cypress será instalado dentro de um projeto. Por isso, vamos criar uma pasta para nossa aplicação de testes.

No terminal, podemos executar: 

mkdir curso-cypress

Depois, entramos na pasta: 

cd curso-cypress

A partir deste momento, os comandos executados pelo terminal serão realizados dentro da pasta do projeto.

4. Inicializando o projeto Node.js

Agora vamos criar o arquivo package.json, que será utilizado para armazenar informações e dependências do projeto.

Execute: 

npm init -y

O parâmetro -y aceita automaticamente as configurações padrão durante a inicialização.

Depois do comando, teremos uma estrutura semelhante a: 

curso-cypress/

└── package.json
O que é o package.json?

É um arquivo importante para projetos Node.js. Ele registra informações do projeto, scripts e dependências utilizadas pela aplicação.

5. Instalando o Cypress

Agora podemos instalar o Cypress como uma dependência de desenvolvimento.

Execute: 

npm install cypress --save-dev

Também é possível utilizar a forma abreviada: 

npm install cypress -D

📦 npm install → instala uma dependência.

🧪 cypress → pacote que queremos instalar.

🛠️ --save-dev → registra o Cypress como dependência de desenvolvimento.

6. O que é uma dependência de desenvolvimento?

Dependências de desenvolvimento são ferramentas utilizadas durante o processo de desenvolvimento, testes e manutenção do projeto.

O Cypress normalmente é utilizado para executar testes, portanto é comum instalá-lo como uma dependência de desenvolvimento. 

npm install cypress --save-dev

Depois da instalação, o package.json terá uma seção semelhante a: 

{
"devDependencies": {
    "cypress": "..."
}

}
📦

Dependência

Pacote necessário para o funcionamento da aplicação.

🛠️

DevDependency

Ferramenta utilizada durante desenvolvimento e testes.

7. A pasta node_modules

Durante a instalação, o npm cria a pasta node_modules. 

curso-cypress/

├── node_modules/
└── package.json

Essa pasta contém os pacotes instalados e suas dependências.

Importante:

A pasta node_modules normalmente não deve ser versionada no Git. Em projetos reais, ela costuma ser adicionada ao arquivo .gitignore.

8. O arquivo package-lock.json

Ao instalar o Cypress, o npm também pode criar ou atualizar o arquivo package-lock.json. 

curso-cypress/

├── node_modules/
├── package-lock.json
└── package.json

O arquivo lock registra informações detalhadas sobre as versões das dependências instaladas e suas dependências relacionadas.

package.json → descreve as dependências do projeto.

package-lock.json → registra a árvore de dependências instalada.

9. Verificando a instalação

Depois da instalação, podemos verificar se o Cypress está disponível no projeto.

Uma forma simples é executar: 

npx cypress --version

O comando deverá apresentar a versão do Cypress instalada no projeto.

Por que utilizar npx?

O npx permite executar pacotes instalados no projeto sem a necessidade de instalar o Cypress globalmente.

10. Abrindo o Cypress

Agora que o Cypress está instalado, podemos abrir sua interface utilizando: 

npx cypress open

O Cypress abrirá sua aplicação de gerenciamento, permitindo configurar e executar os testes.

🚀 npx cypress open → abre a interface do Cypress.

🧪 A partir dela podemos criar e executar nossos testes.

11. Configurando testes E2E

Ao abrir o Cypress pela primeira vez em um projeto, podemos configurar o tipo de teste que desejamos utilizar.

Para este curso, nosso foco principal será End-to-End Testing, também conhecido como teste E2E.

🌐

E2E

Valida fluxos completos da aplicação através da perspectiva do usuário.

🧪

Testes automatizados

Permitem repetir cenários de forma automatizada e consistente.

🔎

Validações

Permitem verificar se a aplicação apresenta o comportamento esperado.

12. Estrutura inicial do projeto

Depois de configurar o Cypress para testes E2E, o projeto passará a possuir arquivos e pastas específicos para os testes.

Uma estrutura inicial pode ser semelhante a: 

curso-cypress/

├── cypress/
│ └── e2e/
├── node_modules/
├── cypress.config.js
├── package-lock.json
└── package.json

📁 cypress/ → contém arquivos relacionados aos testes.

🧪 cypress/e2e/ → local onde serão organizados os testes E2E.

⚙️ cypress.config.js → arquivo de configuração do Cypress.

📦 package.json → informações e dependências do projeto.

13. O arquivo cypress.config.js

O Cypress utiliza um arquivo de configuração para definir diferentes comportamentos do projeto.

Um exemplo inicial pode ser: 

const { defineConfig } = require('cypress')

module.exports = defineConfig({

e2e: {

}

})

Ao longo do curso vamos aprender a utilizar esse arquivo para configurar opções como baseUrl, viewport, retries e outras funcionalidades.

Não precisamos configurar tudo agora.

Neste momento, nosso objetivo é apenas entender que o Cypress possui um arquivo central de configuração.

14. Nossa primeira execução

Depois de instalar e configurar o Cypress, podemos abrir a aplicação novamente: 

npx cypress open

A partir da interface, podemos selecionar E2E Testing e iniciar a configuração.

Depois, o Cypress apresentará a área onde os testes poderão ser criados e executados.

O objetivo desta etapa é confirmar que o ambiente está preparado para as próximas aulas.

A partir daqui começaremos a trabalhar com a estrutura de arquivos, configurações e testes de forma mais detalhada.

15. Executando pelo terminal

Além da interface gráfica, também podemos executar o Cypress diretamente pelo terminal. 

npx cypress run

Essa forma de execução é especialmente importante quando trabalhamos com ambientes automatizados, como pipelines de CI/CD.

🖥️

cypress open

Abre a interface gráfica para desenvolver e acompanhar os testes.

⚡

cypress run

Executa os testes pelo terminal, sem depender da interface gráfica.

16. Criando scripts no package.json

Podemos criar scripts npm para facilitar a execução dos comandos utilizados frequentemente.

Por exemplo: 

{
"scripts": {
    "cy:open": "cypress open",
    "cy:run": "cypress run"
}

}

Depois podemos executar: 

npm run cy:open

Ou: 

npm run cy:run

Scripts ajudam a padronizar os comandos utilizados pela equipe e tornam a execução mais simples.

17. Preciso instalar o Cypress globalmente?

Não é necessário instalar o Cypress globalmente para utilizá-lo em um projeto.

A abordagem recomendada para um projeto é instalar o Cypress como dependência de desenvolvimento: 

npm install cypress --save-dev

Depois, podemos utilizar o Cypress através do npx ou dos scripts definidos no package.json.

📦 Projeto → possui sua própria versão do Cypress.

🔒 Isso ajuda a manter o ambiente do projeto controlado e reproduzível.

18. E se eu apagar a pasta node_modules?

A pasta node_modules pode ser recriada a qualquer momento a partir das dependências registradas no projeto.

Para instalar novamente as dependências, podemos utilizar: 

npm install

O npm analisará o package.json e o arquivo de lock para instalar novamente as dependências necessárias.

Isso é especialmente útil quando outra pessoa baixa o projeto pela primeira vez ou quando precisamos reconstruir o ambiente.

19. Criando o .gitignore

Em um projeto que utiliza Git, devemos evitar versionar arquivos e pastas que não precisam ser armazenados no repositório.

Um exemplo de .gitignore pode conter: 

node_modules/

.DS_Store

A pasta node_modules pode ser recriada utilizando npm install, por isso normalmente não precisamos armazená-la no repositório.

Boa prática:

Versione os arquivos necessários para reconstruir o ambiente, como package.json e package-lock.json, em vez da pasta inteira de dependências.

Erros comuns durante a instalação

❌

Node.js não instalado

Se o comando node não for reconhecido, verifique se o Node.js está instalado e disponível no PATH do sistema.

❌

Executar fora do projeto

Verifique se o terminal está aberto na pasta correta antes de instalar o Cypress.

❌

Problemas de dependências

Quando necessário, remova a instalação local e execute novamente o npm install.

❌

Confundir npx com npm

npm é utilizado para gerenciar pacotes, enquanto npx pode executar pacotes disponíveis no projeto.

Boas práticas

📦

Instale por projeto

Mantenha o Cypress como dependência do projeto em vez de depender de uma instalação global.

🔒

Controle as dependências

Mantenha os arquivos de configuração e gerenciamento de dependências versionados.

📝

Documente os comandos

Utilize scripts npm para facilitar a execução dos comandos utilizados pela equipe.

🔄

Mantenha o ambiente reproduzível

O projeto deve permitir que outro desenvolvedor instale as mesmas dependências utilizando npm.
