O que é Page Object?

Page Object é um padrão de organização utilizado para representar uma página ou parte da aplicação dentro do código de automação.

A ideia principal é separar os detalhes de interação com a interface da lógica que descreve o cenário de teste. 

class LoginPage {

visitar() {

    cy.visit('/login')

}

preencherEmail(email) {

    cy.get('#email')
        .type(email)

}

}

📄 Page Object → representa uma página ou componente da aplicação.

🎯 Elementos → contém referências aos elementos utilizados durante a interação.

⚙️ Métodos → representam ações que podem ser executadas naquela página.

1. O problema da duplicação

Imagine que vários testes precisam realizar login. Sem uma estratégia de organização, podemos repetir os mesmos seletores em diferentes arquivos. 

cy.visit('/login')

cy.get('#email')
.type('usuario@teste.com')

cy.get('#senha')
.type('123456')

cy.get('#login')
.click()

O mesmo código pode acabar aparecendo em vários cenários.

Se o seletor #email mudar para outro identificador, vários testes poderão precisar ser alterados.

2. Centralizando comportamentos

Com um Page Object, podemos centralizar os elementos e ações relacionados à página. 

class LoginPage {

visitar() {

    cy.visit('/login')

}

preencherEmail(email) {

    cy.get('#email')
        .type(email)

}

preencherSenha(senha) {

    cy.get('#senha')
        .type(senha)

}

clicarLogin() {

    cy.get('#login')
        .click()

}

}

export default LoginPage

Agora o teste pode utilizar os métodos da página em vez de conhecer todos os detalhes dos seletores.

3. Estrutura de pastas

Podemos criar uma pasta específica para armazenar os Page Objects. 

curso-cypress/

Uma estrutura organizada facilita a localização dos arquivos responsáveis por representar cada página.

4. Criando o primeiro Page Object

Vamos criar um arquivo chamado: 

cypress/pages/LoginPage.js

Dentro dele podemos representar a página de login: 

class LoginPage {

visitar() {

    cy.visit('/login')

}

preencherEmail(email) {

    cy.get('#email')
        .type(email)

}

preencherSenha(senha) {

    cy.get('#senha')
        .type(senha)

}

clicarLogin() {

    cy.get('#login')
        .click()

}

}

export default LoginPage

O objeto possui métodos que representam as ações disponíveis na página.

5. Importando o Page Object

Depois de criar o Page Object, precisamos importá-lo no arquivo da spec. 

import LoginPage from '../pages/LoginPage'

Podemos então criar uma instância: 

const loginPage = new LoginPage()

Agora o teste possui acesso aos métodos definidos na classe.

6. Utilizando o Page Object no teste

O cenário de login pode ficar mais simples: 

import LoginPage from '../pages/LoginPage'

const loginPage = new LoginPage()

describe('Login', () => {

it('deve realizar login com sucesso', () => {

    loginPage.visitar()

    loginPage.preencherEmail(
        'usuario@teste.com'
    )

    loginPage.preencherSenha(
        '123456'
    )

    loginPage.clicarLogin()

})

})

O teste agora descreve melhor o comportamento esperado e possui menos detalhes de implementação.

7. Criando métodos de alto nível

Também podemos combinar várias ações em um único método. 

class LoginPage {

visitar() {

    cy.visit('/login')

}

login(email, senha) {

    cy.get('#email')
        .type(email)

    cy.get('#senha')
        .type(senha)

    cy.get('#login')
        .click()

}

}

export default LoginPage

O teste pode então utilizar apenas: 

loginPage.visitar()

loginPage.login(
'usuario@teste.com',
'123456'
)

Métodos de alto nível podem representar ações completas do usuário, como realizar login, cadastrar um produto ou finalizar uma compra.

8. Centralizando seletores

Uma das vantagens do Page Object é concentrar os seletores relacionados à página. 

class LoginPage {

elementos = {

    email: '#email',

    senha: '#senha',

    login: '#login'

}

}

Podemos utilizar esses seletores nos métodos: 

preencherEmail(email) {

cy.get(this.elementos.email)
    .type(email)

}

preencherSenha(senha) {

cy.get(this.elementos.senha)
    .type(senha)

}

clicarLogin() {

cy.get(this.elementos.login)
    .click()

}

Dessa maneira, uma alteração de seletor pode ser concentrada no Page Object.

9. Page Objects com data-testid

Quando a aplicação utiliza atributos próprios para automação, podemos centralizar esses seletores. 

class LoginPage {

elementos = {

    email: '[data-testid="email"]',

    senha: '[data-testid="senha"]',

    login: '[data-testid="login"]'

}

}

Os métodos continuam utilizando os seletores definidos no objeto: 

login(email, senha) {

cy.get(this.elementos.email)
    .type(email)

cy.get(this.elementos.senha)
    .type(senha)

cy.get(this.elementos.login)
    .click()

}

A estratégia de seletores deve ser consistente em todo o projeto.

10. Page Object com fixtures

Podemos combinar Page Objects com fixtures para separar comportamento e dados.

Fixture: 

{
"email": "usuario@teste.com",
"senha": "123456"

}

Teste: 

cy.fixture('usuario.json')
.then((usuario) => {

    loginPage.visitar()

    loginPage.login(
        usuario.email,
        usuario.senha
    )

})

O fixture armazena os dados, enquanto o Page Object concentra as interações com a página.

11. Page Objects com hooks

Page Objects também podem ser utilizados em conjunto com hooks. 

const loginPage = new LoginPage()

beforeEach(() => {

loginPage.visitar()

})

it('deve realizar login', () => {

loginPage.login(
    'usuario@teste.com',
    '123456'
)

})

O hook prepara a página e o teste executa o cenário.

12. Trabalhando com várias páginas

Uma aplicação pode possuir vários Page Objects. 

cypress/

└── pages/

├── LoginPage.js

├── DashboardPage.js

├── ProdutoPage.js

├── CarrinhoPage.js

└── CheckoutPage.js

Cada classe representa uma área ou página da aplicação.

🔐

LoginPage

Responsável pelas interações da página de autenticação.

🏠

DashboardPage

Representa os elementos e ações do dashboard.

🛒

CarrinhoPage

Centraliza as ações relacionadas ao carrinho.

💳

CheckoutPage

Representa o processo de finalização da compra.

13. Page Object e fluxo do usuário

Podemos combinar diferentes Page Objects para representar um fluxo completo. 

loginPage.login(
'usuario@teste.com',
'123456'

)

produtoPage.selecionarProduto(
'Notebook'
)

carrinhoPage.abrir()

carrinhoPage.finalizarCompra()

checkoutPage.confirmar()

O cenário passa a representar o comportamento do usuário enquanto os detalhes de implementação permanecem nas classes.

O objetivo não é simplesmente reduzir linhas de código, mas criar uma separação clara entre comportamento do teste e detalhes da interface.

14. Assertions dentro ou fora do Page Object?

Uma decisão importante é definir onde colocar as validações.

Uma abordagem é manter o Page Object responsável principalmente pelas interações: 

login() {

cy.get('#email')
    .type(email)

cy.get('#senha')
    .type(senha)

cy.get('#login')
    .click()

}

E manter a validação no teste: 

loginPage.login(email, senha)

cy.url()
.should('include', 'dashboard')

Essa separação pode deixar o cenário mais explícito, especialmente quando diferentes testes precisam validar resultados diferentes após a mesma ação.

15. Exemplo completo

Vamos criar um Page Object completo para uma página de login. 

class LoginPage {

elementos = {

    email: '[data-testid="email"]',

    senha: '[data-testid="senha"]',

    login: '[data-testid="login"]',

    mensagem: '[data-testid="mensagem"]'

}

visitar() {

    cy.visit('/login')

}

preencherEmail(email) {

    cy.get(this.elementos.email)
        .type(email)

}

preencherSenha(senha) {

    cy.get(this.elementos.senha)
        .type(senha)

}

clicarLogin() {

    cy.get(this.elementos.login)
        .click()

}

login(email, senha) {

    this.preencherEmail(email)

    this.preencherSenha(senha)

    this.clicarLogin()

}

}

export default LoginPage

E agora podemos utilizá-lo na spec: 

import LoginPage from '../pages/LoginPage'

const loginPage = new LoginPage()

describe('Login', () => {

it('deve realizar login com sucesso', () => {

    loginPage.visitar()

    loginPage.login(
        'usuario@teste.com',
        '123456'
    )

    cy.url()
        .should('include', 'dashboard')

})

})

A spec descreve o cenário, enquanto o Page Object concentra os detalhes necessários para interagir com a página.

Vantagens do Page Object

♻️

Reutilização

Os mesmos comportamentos podem ser utilizados em diferentes cenários.

🛠️

Manutenção

Alterações nos elementos podem ficar concentradas em um único local.

📖

Legibilidade

Os testes podem representar melhor as ações realizadas pelo usuário.

🧩

Organização

Os detalhes da interface ficam separados da lógica dos cenários.

Cuidados ao utilizar Page Objects

⚠️

Evite classes gigantes

Não concentre toda a aplicação em um único Page Object.

🚫

Evite métodos genéricos demais

Os métodos devem representar comportamentos claros e relacionados à página.

🔍

Mantenha nomes claros

Utilize nomes que expliquem a ação realizada pelo método.

🧠

Não esconda tudo

O teste ainda deve deixar claro qual comportamento está sendo validado.

Page Object x Custom Command

Page Objects e Custom Commands podem parecer semelhantes, mas possuem objetivos diferentes.

Recurso Objetivo Exemplo
Page Object Organizar uma página ou área da aplicação. LoginPage.
Custom Command Criar um comando reutilizável do Cypress. cy.login().

Os dois padrões podem coexistir em um mesmo projeto, desde que cada um tenha uma responsabilidade clara.

Boas práticas com Page Objects

🎯

Uma responsabilidade

Organize cada Page Object em torno de uma página ou área relacionada.

🔎

Seletores centralizados

Mantenha os seletores da página organizados e fáceis de localizar.

📝

Métodos claros

Utilize nomes que representem as ações realizadas pelo usuário.

♻️

Reutilização

Extraia comportamentos realmente compartilhados entre diferentes cenários.
