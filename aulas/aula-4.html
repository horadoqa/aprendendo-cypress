O que é Cypress?

O Cypress é uma ferramenta de testes voltada principalmente para aplicações web.

Ele permite escrever testes utilizando JavaScript ou TypeScript e executar esses testes em um ambiente que permite observar as interações com a aplicação.

De forma simples:

O Cypress permite escrever código que descreve ações e verificações que queremos realizar em uma aplicação web.

Em vez de executar manualmente uma sequência como abrir uma página, preencher um formulário e clicar em um botão, podemos transformar essas ações em código automatizado.

Pensando como o Cypress

Imagine que precisamos testar uma tela de login.

Manualmente, poderíamos realizar os seguintes passos:

🌐

1. Abrir a página

Acessar a tela de login da aplicação.

✉️

2. Preencher e-mail

Informar o e-mail do usuário.

🔑

3. Preencher senha

Informar a senha.

🖱️

4. Clicar

Acionar o botão de login.

✅

5. Verificar

Confirmar que o login foi realizado.

Transformando ações em código

O Cypress permite representar ações da aplicação através de comandos.

Um exemplo simples: 

cy.visit('/login')

cy.get('[data-testid="email"]')
    .type('usuario@email.com')

cy.get('[data-testid="senha"]')
    .type('123456')

cy.get('[data-testid="entrar"]')
    .click()

Cada comando representa uma operação que o teste precisa realizar.

cy.visit() → acessa uma página.

cy.get() → encontra um elemento da aplicação.

.type() → insere informações em um campo.

.click() → realiza um clique.

Cypress não é uma linguagem de programação

É importante diferenciar as tecnologias utilizadas no processo.

🧪

Cypress

É a ferramenta utilizada para criar e executar testes.

🟨

JavaScript

É uma das linguagens que podemos utilizar para escrever os testes.

🔷

TypeScript

Também pode ser utilizado para escrever testes com Cypress.

Não confunda:

❌ Cypress não é uma linguagem.

❌ Cypress não é JavaScript.

✅ Cypress é uma ferramenta de testes que pode ser utilizada com JavaScript ou TypeScript.

Como o Cypress funciona?

Para entender o Cypress, podemos imaginar uma comunicação entre três elementos principais:

🧑‍💻

1. Teste

O código define as ações e verificações que queremos executar.

🧪

2. Cypress

A ferramenta interpreta e executa os comandos do teste.

🌐

3. Aplicação

A aplicação recebe as ações e apresenta seus comportamentos.

Fluxo básico de execução

🧑‍💻 Teste → define uma ação.

↓

🧪 Cypress → executa o comando.

↓

🌐 Aplicação → recebe a interação.

↓

🔍 Cypress → verifica o resultado.

↓

✅ Teste → apresenta o resultado.

O que são comandos do Cypress?

Os comandos são uma das partes mais importantes da experiência de desenvolvimento com Cypress.

Eles permitem realizar ações sobre a aplicação e obter informações sobre seus elementos.

cy.visit()

Acessa uma URL. 

cy.visit('/login')

cy.get()

Busca um elemento utilizando um seletor. 

cy.get('button')

.click()

Realiza uma interação de clique. 

cy.get('button')
    .click()

.type()

Digita um valor em um campo. 

cy.get('input')
    .type('Cypress')

O que são Assertions?

Uma assertion é uma verificação utilizada para confirmar se o comportamento observado corresponde ao resultado esperado.

Por exemplo, depois de realizar um login, podemos verificar se determinada mensagem apareceu. 

cy.get('[data-testid="mensagem"]')
    .should('be.visible')
A ideia é:

Ação → comportamento da aplicação → resultado esperado.

Exemplos de verificações

Elemento visível 

cy.get('.menu')
    .should('be.visible')

Texto 

cy.get('h1')
    .should('contain', 'Dashboard')

Valor 

cy.get('input')
    .should('have.value', 'Cypress')

URL 

cy.url()
    .should('include', 'dashboard')

Como o Cypress encontra elementos?

Para interagir com um elemento da página, precisamos identificá-lo.

Para isso, utilizamos seletores.

Tag 

cy.get('button')

Seleciona elementos pela tag HTML.

Classe 

cy.get('.botao')

Seleciona elementos através de uma classe.

ID 

cy.get('#login')

Seleciona um elemento pelo identificador.

data-testid 

cy.get('[data-testid="login"]')

Permite utilizar um atributo criado especificamente para facilitar a identificação.

Por que utilizar data-testid?

Em testes automatizados, é importante utilizar seletores que sejam suficientemente estáveis.

Uma possibilidade é adicionar um atributo data-testid ao elemento. 

<button
    data-testid="entrar"
>
    Entrar
</button>

O teste pode então localizar o botão: 

cy.get('[data-testid="entrar"]')
    .click()
Importante:

Não existe um único seletor obrigatório para todos os testes. A escolha deve considerar a estrutura e a estabilidade da aplicação.

Uma característica importante: espera automática

Aplicações web modernas possuem comportamentos assíncronos. Elementos podem aparecer depois que uma página é carregada.

O Cypress possui mecanismos de espera e repetição de determinadas operações e verificações, reduzindo a necessidade de inserir esperas fixas em muitos casos.

Evite pensar assim: 
// Esperar alguns segundos
// e depois tentar encontrar o elemento

Em muitos casos, podemos deixar o Cypress aguardar o estado esperado do elemento. 

cy.get('[data-testid="resultado"]')
    .should('be.visible')

Observando a execução do teste

Uma característica marcante da experiência de desenvolvimento do Cypress é a possibilidade de observar a execução dos testes e seus comandos.

▶️

Execução

Os comandos são executados na aplicação.

🔍

Inspeção

Podemos observar o estado da aplicação durante o teste.

❌

Falha

Quando uma verificação falha, o resultado ajuda na investigação do problema.

Nosso primeiro exemplo completo

Podemos combinar alguns dos conceitos apresentados nesta aula. 

describe('Login', () => {

    it('deve acessar o sistema', () => {

        cy.visit('/login')

        cy.get('[data-testid="email"]')
            .type('usuario@email.com')

        cy.get('[data-testid="senha"]')
            .type('123456')

        cy.get('[data-testid="entrar"]')
            .click()

        cy.url()
            .should('include', 'dashboard')

    })

})

O teste está fazendo:

1. Acessa a página de login.

2. Preenche o e-mail.

3. Preenche a senha.

4. Clica no botão.

5. Verifica a URL.

Cypress e outras ferramentas

Existem diversas ferramentas de automação de testes. Cada uma possui características, APIs e formas de funcionamento próprias.

Conceito Cypress Objetivo
Testes web ✅ Automatizar comportamentos de aplicações web.
JavaScript / TypeScript ✅ Escrever testes e lógica de automação.
Assertions ✅ Verificar resultados esperados.
Requisições HTTP ✅ Trabalhar com APIs e respostas HTTP.

Características importantes do Cypress

💻

Experiência de desenvolvimento

Possui uma interface voltada para acompanhar a execução e investigar testes.

🔎

Debug

Oferece recursos que ajudam a investigar falhas durante a execução.

🧪

Sintaxe baseada em JavaScript

Entendendo o escopo da ferramenta

Nenhuma ferramenta de testes resolve todos os problemas de qualidade de software sozinha.

Cypress deve ser utilizado dentro de uma estratégia de testes que considere os diferentes níveis, riscos e necessidades da aplicação.

Por isso:

🧩 Testes unitários continuam importantes.

🔗 Testes de integração continuam importantes.

🌐 Testes E2E podem verificar fluxos completos.

🧪 O Cypress pode fazer parte dessa estratégia.

Conceitos que você deve guardar

Command

Comando utilizado para realizar uma operação através da API do Cypress.

Selector

Forma utilizada para localizar um elemento da aplicação.

Assertion

Verificação que confirma um resultado esperado.

Test

Conjunto de ações e verificações que valida determinado comportamento.

Erros comuns

❌ "Cypress é uma linguagem"

Cypress é uma ferramenta. Os testes podem ser escritos utilizando JavaScript ou TypeScript.

❌ "cy.get() é uma assertion"

cy.get() é utilizado para localizar elementos. Uma assertion pode ser realizada com métodos como .should().

❌ "Todo teste precisa de cy.wait()"

O Cypress possui mecanismos de espera e repetição automáticos. Esperas fixas devem ser utilizadas com cuidado.

❌ "Cypress substitui toda a estratégia de testes"

Cypress é uma ferramenta dentro de uma estratégia maior de qualidade e testes.
