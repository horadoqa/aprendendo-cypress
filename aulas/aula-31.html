O que é cy.request()?

O cy.request() é um comando do Cypress utilizado para realizar requisições HTTP diretamente contra uma API.

Diferentemente de comandos como cy.get(), que interagem com elementos da interface, o cy.request() trabalha diretamente com o servidor. 

cy.request('GET', '/usuarios')

🌐 API → recebe a requisição enviada pelo teste.

📤 Request → contém método, URL, headers e, quando necessário, dados enviados.

📥 Response → contém status, headers e body retornados pela API.

1. Sintaxe básica

A forma mais simples de utilizar o cy.request() é informar a URL que queremos acessar. 

cy.request('/usuarios')

Quando nenhum método é informado, o Cypress utiliza uma requisição GET.

Também podemos informar explicitamente o método: 

cy.request(
'GET',
'/usuarios'

)
Importante:

O método HTTP define qual operação será realizada pelo servidor.

2. Realizando uma requisição GET

O método GET normalmente é utilizado para consultar informações. 

cy.request('GET', '/usuarios')

Podemos acessar a resposta utilizando .then(). 

cy.request('GET', '/usuarios')
.then((response) => {

    cy.log(response.status)

    cy.log(response.body)

})
🔎

Consulta

Utilizado para buscar informações disponíveis na API.

📊

Response

A resposta pode conter dados e informações sobre a requisição.

🧪

Validação

Podemos utilizar a resposta para criar assertions.

3. Acessando o status da resposta

Uma das informações mais importantes de uma resposta HTTP é o status code.

Podemos acessar essa informação através de response.status. 

cy.request('GET', '/usuarios')
.then((response) => {

    cy.log(response.status)

})

Também podemos validar diretamente o status: 

cy.request('GET', '/usuarios')
.its('status')
.should('eq', 200)

Um status 200 normalmente indica que uma requisição foi processada com sucesso.

O significado exato depende do endpoint e da operação realizada.

4. Acessando o body

O body contém os dados retornados pela API. 

cy.request('GET', '/usuarios/1')
.then((response) => {

    cy.log(response.body)

})

Se a API retornar um objeto semelhante a: 

{
"id": 1,
"nome": "Maria",
"email": "maria@teste.com"

}

Podemos acessar suas propriedades: 

cy.request('GET', '/usuarios/1')
.then((response) => {

    cy.log(response.body.nome)

    cy.log(response.body.email)

})

5. Validando uma resposta

O cy.request() pode ser utilizado junto com assertions para verificar se a API retornou o resultado esperado. 

cy.request('GET', '/usuarios/1')
.then((response) => {

    expect(response.status).to.eq(200)

    expect(response.body.nome)
        .to.eq('Maria')

})
🔢

Status

Verificamos o código HTTP retornado pela API.

📦

Body

Validamos os dados presentes no corpo da resposta.

🏷️

Headers

Também podemos validar informações presentes nos headers.

6. Enviando uma requisição POST

O método POST é utilizado em APIs para enviar dados ao servidor, frequentemente para criar um novo recurso.

Podemos enviar um objeto utilizando a propriedade body. 

cy.request({
method: 'POST',
url: '/usuarios',
body: {
    nome: 'Maria',
    email: 'maria@teste.com'
}

})

Depois podemos verificar a resposta: 

cy.request({
method: 'POST',
url: '/usuarios',
body: {
    nome: 'Maria',
    email: 'maria@teste.com'
}

}).then((response) => {

expect(response.status).to.eq(201)

})

O status 201 é frequentemente utilizado quando um novo recurso foi criado.

7. Enviando uma requisição PUT

O método PUT pode ser utilizado para atualizar um recurso. 

cy.request({
method: 'PUT',
url: '/usuarios/1',
body: {
    nome: 'Maria Silva',
    email: 'maria.silva@teste.com'
}

})

Podemos validar o resultado da operação: 

cy.request({
method: 'PUT',
url: '/usuarios/1',
body: {
    nome: 'Maria Silva'
}

}).then((response) => {

expect(response.status).to.be.oneOf([200, 204])

})
Observação:

O status retornado depende do contrato da API. O exemplo acima considera respostas comuns para uma atualização.

8. Enviando uma requisição PATCH

O método PATCH normalmente é utilizado para realizar uma atualização parcial em um recurso. 

cy.request({
method: 'PATCH',
url: '/usuarios/1',
body: {
    nome: 'Maria Silva'
}

})

Podemos validar a resposta: 

cy.request({
method: 'PATCH',
url: '/usuarios/1',
body: {
    nome: 'Maria Silva'
}

}).then((response) => {

expect(response.status).to.be.oneOf([200, 204])

})

9. Enviando uma requisição DELETE

O método DELETE normalmente é utilizado para remover um recurso. 

cy.request({
method: 'DELETE',
url: '/usuarios/1'

})

Podemos validar o status retornado: 

cy.request({
method: 'DELETE',
url: '/usuarios/1'

}).then((response) => {

expect(response.status).to.be.oneOf([200, 204])

})

Assim como nos demais métodos, o status esperado deve ser definido de acordo com o contrato da API.

10. Utilizando o objeto de configuração

Para requisições mais completas, podemos utilizar um objeto contendo as configurações da chamada. 

cy.request({

method: 'GET',

url: '/usuarios'

})

Essa estrutura facilita a utilização de propriedades como método, URL, headers, body e parâmetros. 

cy.request({

method: 'POST',

url: '/usuarios',

body: {

    nome: 'Maria',

    email: 'maria@teste.com'

}

})

A sintaxe com objeto é especialmente útil quando a requisição possui várias configurações.

11. Enviando headers

Algumas APIs exigem headers específicos para processar uma requisição. 

cy.request({

method: 'GET',

url: '/usuarios',

headers: {

    Authorization: 'Bearer token-de-teste'

}

})

Também podemos trabalhar com headers relacionados ao formato do conteúdo enviado. 

cy.request({

method: 'POST',

url: '/usuarios',

headers: {

    'Content-Type': 'application/json'

},

body: {

    nome: 'Maria',

    email: 'maria@teste.com'

}

})
Atenção:

Evite colocar tokens reais diretamente no código do teste. Para credenciais e segredos, prefira mecanismos apropriados de configuração e secrets.

12. Enviando query parameters

Algumas APIs utilizam parâmetros na URL para filtrar ou modificar uma consulta.

Podemos utilizar a propriedade qs. 

cy.request({

method: 'GET',

url: '/usuarios',

qs: {

    pagina: 1,

    limite: 10

}

})

O Cypress monta os parâmetros na URL da requisição. 

/usuarios?pagina=1&limite=10

A propriedade qs ajuda a manter os parâmetros separados da URL principal.

13. Trabalhando com diferentes tipos de body

O conteúdo enviado no body depende do contrato estabelecido pela API.

Um exemplo utilizando JSON: 

cy.request({

method: 'POST',

url: '/produtos',

body: {

    nome: 'Notebook',

    preco: 3500

}

})

O body também pode utilizar dados armazenados em variáveis: 

const produto = {

nome: 'Notebook',

preco: 3500

}

cy.request({

method: 'POST',

url: '/produtos',

body: produto

})

14. Conhecendo o objeto response

Quando o Cypress executa uma requisição, podemos trabalhar com o objeto de resposta retornado. 

cy.request('GET', '/usuarios/1')
.then((response) => {

    cy.log(response.status)

    cy.log(response.headers)

    cy.log(response.body)

})
Propriedade Descrição
status Código HTTP retornado pela API.
headers Cabeçalhos retornados na resposta.
body Dados retornados pela API.
duration Tempo da requisição, quando disponível.

15. Validando dados do response

Podemos combinar cy.request() com várias assertions. 

cy.request('GET', '/usuarios/1')
.then((response) => {

    expect(response.status)
        .to.eq(200)

    expect(response.body)
        .to.have.property('nome')

    expect(response.body.nome)
        .to.eq('Maria')

})

Dessa forma, podemos validar tanto a estrutura quanto os valores retornados.

🔢

Status

Verifica o resultado HTTP da operação.

🧩

Propriedade

Verifica se determinado campo existe no objeto retornado.

🎯

Valor

Confirma se o conteúdo retornado corresponde ao esperado.

16. Encadeando requisições

Uma requisição pode utilizar informações retornadas por outra requisição.

Por exemplo, podemos criar um usuário e depois consultar o recurso criado. 

cy.request({

method: 'POST',

url: '/usuarios',

body: {

    nome: 'Maria',

    email: 'maria@teste.com'

}

}).then((response) => {

const id = response.body.id

cy.request('GET', `/usuarios/${id}`)

})

Esse tipo de fluxo permite construir cenários de API nos quais uma operação depende do resultado de outra.

17. Utilizando cy.request() em autenticação

O cy.request() também pode ser utilizado para realizar operações de autenticação diretamente pela API. 

cy.request({

method: 'POST',

url: '/login',

body: {

    email: 'usuario@teste.com',

    senha: '123456'

}

}).then((response) => {

expect(response.status)
    .to.eq(200)

})

A resposta pode conter informações utilizadas posteriormente pelo teste, como um identificador de sessão ou token.

Boa prática:

Em projetos reais, evite colocar credenciais sensíveis diretamente no código-fonte.

18. Utilizando baseUrl

Quando o projeto possui uma baseUrl configurada, podemos utilizar caminhos relativos nas requisições. 

cy.request('GET', '/usuarios')

Por exemplo, se a configuração possuir: 

baseUrl: 'https://api.exemplo.com'

A requisição será direcionada para: 

https://api.exemplo.com/usuarios

Utilizar baseUrl evita repetir o endereço completo da API em todos os testes.

19. Trabalhando com respostas de erro

Por padrão, o Cypress pode considerar determinados status HTTP como falha da requisição.

Quando queremos testar explicitamente uma resposta de erro, podemos utilizar a opção failOnStatusCode. 

cy.request({

method: 'GET',

url: '/usuarios/9999',

failOnStatusCode: false

}).then((response) => {

expect(response.status)
    .to.eq(404)

})

Essa abordagem é especialmente útil para testar cenários negativos, como recursos inexistentes, requisições inválidas ou acessos não autorizados.

20. Exemplo completo

Vamos combinar os conceitos estudados em um cenário simples de criação e consulta de usuário. 

describe('API de usuários', () => {

it('deve criar e consultar um usuário', () => {

    cy.request({

        method: 'POST',

        url: '/usuarios',

        body: {

            nome: 'Maria',

            email: 'maria@teste.com'

        }

    }).then((response) => {

        expect(response.status)
            .to.eq(201)

        const id = response.body.id

        cy.request(
            'GET',
            `/usuarios/${id}`
        )

    }).then((response) => {

        expect(response.status)
            .to.eq(200)

        expect(response.body.nome)
            .to.eq('Maria')

        expect(response.body.email)
            .to.eq('maria@teste.com')

    })

})

})

Nesse cenário, o primeiro request cria o usuário. O ID retornado é utilizado para realizar uma segunda requisição e consultar o recurso criado.

Erros comuns ao utilizar cy.request()

❌

URL incorreta

Informar um endpoint incorreto ou inexistente.

❌

Método incorreto

Utilizar um método HTTP diferente do esperado pelo endpoint.

❌

Body incorreto

Enviar campos ausentes, inválidos ou com formato diferente do contrato da API.

❌

Ignorar o response

Executar a requisição sem validar se o resultado corresponde ao esperado.

Boas práticas com cy.request()

🎯

Valide a resposta

Não limite o teste ao envio da requisição. Valide o resultado retornado pela API.

📋

Respeite o contrato

Utilize os métodos, parâmetros e estruturas definidos pela API.

🔐

Proteja credenciais

Não mantenha tokens, senhas ou secrets reais diretamente no código dos testes.

♻️

Reutilize dados

Combine cy.request() com fixtures, variáveis e aliases quando fizer sentido.
