O que é um teste no Cypress?

Um teste no Cypress é um código que descreve ações que devem ser executadas em uma aplicação e condições que precisam ser verificadas.

Podemos representar um fluxo simples desta forma:

🌐 Acessar uma página

↓

🔎 Localizar um elemento

↓

🖱️ Realizar uma ação

↓

✅ Verificar o resultado

1. Criando o primeiro arquivo

Dentro da pasta cypress/e2e, vamos criar um arquivo chamado: 

primeiro-teste.cy.js

A estrutura ficará assim: 

cypress/
└── e2e/
    └── primeiro-teste.cy.js
Importante:

A extensão .cy.js identifica um arquivo JavaScript destinado aos testes do Cypress.

Nosso primeiro teste

Vamos começar com um exemplo simples: 

describe('Minha primeira suíte', () => {

    it('deve acessar a página inicial', () => {

        cy.visit('/')

    })

})

Mesmo sendo um código pequeno, temos vários conceitos importantes aqui.

2. O que é describe()?

O describe() é utilizado para organizar um conjunto de testes relacionados.

Podemos utilizá-lo para representar uma funcionalidade, uma página ou um determinado contexto. 

describe('Login', () => {

    // testes relacionados ao login

})
📁

Organização

Agrupa testes relacionados.

🧪

Suíte de testes

Representa um contexto ou conjunto de cenários.

3. O que é it()?

O it() representa um caso de teste.

É dentro dele que escrevemos as ações e validações que queremos executar. 

it('deve exibir a página inicial', () => {

    // passos do teste

})

Podemos pensar da seguinte maneira:

describe() → grupo de testes.

it() → um teste dentro desse grupo.

4. O objeto cy

O Cypress disponibiliza o objeto global cy, utilizado para executar comandos durante os testes.

Alguns comandos que veremos ao longo do curso são:

🌐

cy.visit()

Acessa uma página da aplicação.

🔎

cy.get()

Localiza elementos utilizando seletores.

🖱️

cy.click()

Executa uma ação de clique em um elemento.

⌨️

cy.type()

Digita informações em elementos de entrada.

5. Acessando uma página com cy.visit()

O comando cy.visit() permite navegar para uma URL durante o teste. 

cy.visit('/')

Caso a aplicação esteja configurada com uma baseUrl, o Cypress utilizará essa URL como referência.

Também podemos acessar uma URL completa: 

cy.visit('https://example.com')
Exemplo:

Se a baseUrl for http://localhost:3000, então: 

cy.visit('/login')

acessará: 

http://localhost:3000/login

6. Fazendo nossa primeira validação

Um teste não deve apenas executar ações. Também precisamos verificar se o resultado esperado aconteceu.

Para isso, utilizamos assertions. 

cy.get('h1')
    .should('be.visible')

Nesse exemplo:

cy.get('h1') → localiza um elemento h1.

should('be.visible') → verifica se o elemento está visível.

Primeiro teste completo

Agora podemos combinar navegação, localização de elementos e validação. 

describe('Página inicial', () => {

    it('deve carregar corretamente', () => {

        cy.visit('/')

        cy.get('h1')
            .should('be.visible')

    })

})

O fluxo do teste é:

1. Abrir a aplicação.

2. Localizar o título.

3. Verificar se o título está visível.

7. Localizando elementos com cy.get()

O cy.get() é um dos comandos mais utilizados no Cypress.

Ele permite localizar elementos utilizando seletores CSS. 

cy.get('#login')
cy.get('.botao-login')
cy.get('input')
Seletor Localização
#login Elemento com id="login".
.botao-login Elemento com a classe botao-login.
input Elementos HTML do tipo input.
button Elementos HTML do tipo button.

8. Clicando em elementos

Para simular um clique, podemos utilizar o comando .click(). 

cy.get('button')
    .click()

Podemos também localizar o elemento através de um identificador: 

cy.get('#entrar')
    .click()

O Cypress localiza o elemento e executa a ação de clique como parte do fluxo do teste.

9. Digitando informações

Para preencher campos de formulário, podemos utilizar .type(). 

cy.get('#email')
    .type('usuario@email.com')

Outro exemplo: 

cy.get('#senha')
    .type('123456')

Podemos combinar o preenchimento com um clique: 

cy.get('#email')
    .type('usuario@email.com')

cy.get('#senha')
    .type('123456')

cy.get('#entrar')
    .click()

Exemplo: teste de login

Imagine uma página contendo um formulário de login: 

<input id="email">

<input id="senha" type="password">

<button id="entrar">
    Entrar
</button>

Podemos automatizar o preenchimento: 

describe('Login', () => {

    it('deve preencher o formulário', () => {

        cy.visit('/login')

        cy.get('#email')
            .type('usuario@email.com')

        cy.get('#senha')
            .type('123456')

        cy.get('#entrar')
            .click()

    })

})

10. Assertions

Assertions são verificações utilizadas para confirmar se o comportamento observado corresponde ao esperado.

👁️

be.visible

Verifica se o elemento está visível.

🔤

contain

Verifica se um elemento contém determinado texto.

✔️

exist

Verifica se o elemento existe.

📝

have.value

Verifica o valor de um elemento de formulário.

Exemplos de assertions

Verificando visibilidade: 

cy.get('h1')
    .should('be.visible')

Verificando texto: 

cy.get('h1')
    .should('contain', 'Bem-vindo')

Verificando existência: 

cy.get('#mensagem')
    .should('exist')

Verificando valor: 

cy.get('#email')
    .should('have.value', 'usuario@email.com')

Criando vários testes

Uma mesma suíte pode possuir vários casos de teste. 

describe('Página de login', () => {

    it('deve exibir o formulário', () => {

        cy.visit('/login')

        cy.get('#email')
            .should('be.visible')

    })


    it('deve exibir o botão entrar', () => {

        cy.visit('/login')

        cy.get('#entrar')
            .should('be.visible')

    })

})

Cada it() representa um cenário que pode ser executado e reportado individualmente.

Executando o teste

Podemos abrir o Cypress utilizando: 

npx cypress open

Depois, selecionamos o tipo de teste configurado e o arquivo que queremos executar.

Também podemos executar pela linha de comando: 

npx cypress run

Durante a execução, o Cypress apresenta informações sobre os testes aprovados e aqueles que apresentaram falhas.

Quando um teste passa?

Um teste passa quando as condições definidas no cenário são atendidas. 

it('deve exibir o título', () => {

    cy.visit('/')

    cy.get('h1')
        .should('be.visible')

})

Se o elemento h1 estiver presente e visível, a assertion será atendida.

E quando o teste falha?

Um teste falha quando uma condição esperada não é atendida ou quando ocorre um erro durante a execução.

Por exemplo: 

cy.get('h1')
    .should('contain', 'Texto que não existe')

Se o título não possuir esse conteúdo, a assertion não será atendida e o Cypress registrará a falha.

Um teste falhando não significa necessariamente que o Cypress está com problema.

A falha pode indicar que o comportamento observado não corresponde ao comportamento esperado definido pelo teste.

11. A cadeia de comandos

Um dos recursos que tornam os testes Cypress expressivos é a possibilidade de encadear comandos. 

cy.get('#email')
    .should('be.visible')
    .type('usuario@email.com')

Nesse exemplo:

cy.get() → localiza o campo.

should() → verifica a condição.

type() → digita o conteúdo.

Fluxo completo de um teste 

describe('Login', () => {

    it('deve realizar o preenchimento', () => {

        cy.visit('/login')

        cy.get('#email')
            .should('be.visible')
            .type('usuario@email.com')

        cy.get('#senha')
            .should('be.visible')
            .type('123456')

        cy.get('#entrar')
            .click()

        cy.get('h1')
            .should('contain', 'Dashboard')

    })

})

🌐 Visit → acessa a aplicação.

🔎 Get → localiza elementos.

⌨️ Type → preenche informações.

🖱️ Click → executa uma ação.

✅ Should → verifica o resultado.

Boas práticas desde o primeiro teste

🏷️

Dê nomes claros

O nome do teste deve explicar o comportamento que está sendo validado.

🎯

Teste um comportamento

Evite transformar um único teste em uma sequência excessivamente grande de cenários.

🔎

Use seletores adequados

Prefira seletores estáveis e pensados para automação.

✅

Valide resultados

Um teste deve verificar se o comportamento esperado realmente aconteceu.

Erros comuns

❌ Criar um teste sem assertion

Apenas executar cliques e navegações não garante que o comportamento esperado aconteceu.

❌ Usar seletores frágeis

Seletores baseados em estruturas que mudam frequentemente podem tornar os testes menos resistentes às alterações da aplicação.

❌ Colocar muitos cenários em um teste

Testes excessivamente grandes podem dificultar a identificação da causa de uma falha.

❌ Confundir ação com validação

Clicar em um botão é uma ação. Confirmar o resultado após o clique é uma validação.

Resumindo

🧱 describe() → organiza uma suíte de testes.

🧪 it() → representa um caso de teste.

🌐 cy.visit() → acessa uma página.

🔎 cy.get() → localiza elementos.

⌨️ type() → digita informações.

🖱️ click() → executa um clique.

✅ should() → realiza uma verificação.

📊 Assertion → valida se o resultado esperado foi alcançado.

Agora você já conhece a estrutura básica de um teste Cypress e consegue criar um fluxo simples de navegação, interação e validação.
