AULA 1 • FUNDAMENTOS DE TESTES

Introdução aos Testes de Software

Entenda o que são testes de software, por que testar, quais são os principais tipos de testes e onde a automação entra nesse processo.

Objetivos da aula

Antes de aprender Cypress, precisamos entender os fundamentos de testes de software e o papel da automação dentro do processo de qualidade.

Nesta aula, você vai aprender a diferenciar:

🧪

Testes de Software

Atividades realizadas para verificar se um software atende aos comportamentos esperados.

👨‍💻

Testes Manuais

Testes executados por uma pessoa seguindo cenários e procedimentos definidos.

🤖

Automação de Testes

Utilização de código e ferramentas para executar verificações automaticamente.

O que são testes de software?

Testes de software são atividades realizadas para verificar o comportamento de uma aplicação e obter informações sobre sua qualidade.

Um teste pode verificar desde uma pequena função até o comportamento completo de uma aplicação, incluindo a interação do usuário com uma interface.

De forma simples:

Testar significa verificar se o software apresenta o comportamento esperado para determinadas condições.

Os testes também ajudam a identificar problemas antes que eles cheguem aos usuários e fornecem informações importantes para o processo de desenvolvimento e manutenção do software.

1. Por que testar software?

Aplicações possuem regras de negócio, interfaces, integrações e diferentes fluxos de utilização. Alterações em uma parte do sistema podem afetar outras funcionalidades.

Os testes ajudam a verificar se esses comportamentos continuam funcionando conforme o esperado.

🔍

Encontrar problemas

Identificar comportamentos inesperados durante o desenvolvimento e manutenção.

🛡️

Reduzir riscos

Verificar comportamentos importantes antes da disponibilização de uma versão.

🔄

Validar alterações

Verificar se mudanças realizadas não alteraram comportamentos esperados.

📋

Obter evidências

Registrar resultados das verificações realizadas durante o processo de teste.

Exemplo de uma aplicação

Imagine uma aplicação de login. O usuário informa seu e-mail e senha e seleciona o botão "Entrar".

Podemos criar diferentes cenários para verificar o comportamento dessa funcionalidade.

Cenário Entrada Resultado esperado
Login válido E-mail e senha corretos Usuário acessa a aplicação
Senha inválida E-mail correto e senha incorreta Mensagem de erro
E-mail inválido E-mail inexistente Mensagem de erro
Campos vazios Sem informações Validação dos campos

Cada uma dessas situações pode se transformar em um cenário de teste.

2. O que é um teste manual?

Um teste manual é executado por uma pessoa, que realiza as ações necessárias e verifica os resultados apresentados pela aplicação.

Por exemplo, para testar um login manualmente, uma pessoa poderia:

1. Abrir a página de login.

2. Informar o e-mail.

3. Informar a senha.

4. Clicar no botão "Entrar".

5. Verificar o resultado apresentado.

O teste manual é importante e continua sendo utilizado em diferentes situações. Porém, alguns cenários são executados muitas vezes durante o desenvolvimento.

3. O que é automação de testes?

Automação de testes consiste em utilizar software, código e ferramentas para executar verificações automaticamente.

Em vez de uma pessoa realizar manualmente todas as etapas de um cenário, podemos escrever um teste que execute essas ações e valide o resultado.

Exemplo:

Em um teste automatizado, o código pode abrir uma página, preencher um formulário, clicar em um botão e verificar se determinada mensagem apareceu.

Teste manual × teste automatizado

Característica Manual Automatizado
Execução Realizada por uma pessoa Realizada por código
Repetição Pode exigir execução novamente Pode ser executado novamente através do teste
Velocidade Depende da execução humana Pode executar várias verificações rapidamente
Manutenção Depende do procedimento utilizado O código do teste precisa ser mantido
Programação Não necessariamente Normalmente envolve código
Importante:

Automação não significa substituir todos os testes manuais. Cada abordagem possui aplicações diferentes dentro de uma estratégia de testes.

4. Tipos de testes

Existem diferentes níveis e tipos de testes. Eles podem verificar partes diferentes de uma aplicação.

🧩

Teste Unitário

Verifica uma unidade pequena do código, como uma função ou método.

🔗

Teste de Integração

Verifica a interação entre diferentes componentes de um sistema.

🌐

Teste End-to-End

Verifica um fluxo completo da aplicação do ponto de vista do usuário.

🔌

Teste de API

Verifica requisições, respostas e comportamentos de uma API.

5. O que é um teste End-to-End?

O teste End-to-End (E2E) verifica um fluxo completo da aplicação, simulando uma sequência de ações próxima à utilização real do sistema.

Por exemplo, em uma loja virtual podemos testar:

🔎

1. Pesquisar

O usuário pesquisa um produto.

🛒

2. Adicionar

O produto é adicionado ao carrinho.

💳

3. Comprar

O usuário realiza o processo de compra.

✅

4. Confirmar

A aplicação apresenta a confirmação do pedido.

Esse tipo de cenário é especialmente relevante para ferramentas de automação de testes de aplicações web, como o Cypress.

6. Onde entra o Cypress?

O Cypress é uma ferramenta utilizada para testes automatizados de aplicações web.

Durante o curso, vamos utilizá-lo para criar testes que interagem com uma aplicação e verificam se ela apresenta os comportamentos esperados.

Imagine o fluxo:

👤 Usuário → acessa a aplicação

🤖 Cypress → executa as ações do teste

🖱️ Interface → recebe as interações

✅ Assertions → verificam os resultados

Um primeiro exemplo com Cypress

Mais adiante no curso, veremos comandos como cy.visit() e cy.get().

Um teste simples pode ter uma estrutura semelhante a esta: 

describe('Página de login', () => {

    it('deve permitir realizar login', () => {

        cy.visit('/login')

        cy.get('[data-testid="email"]')
            .type('usuario@email.com')

        cy.get('[data-testid="senha"]')
            .type('123456')

        cy.get('[data-testid="entrar"]')
            .click()

        cy.contains('Bem-vindo')
            .should('be.visible')

    })

})

Não é necessário memorizar esse código agora. O objetivo é apenas visualizar como um cenário que seria executado manualmente pode ser descrito através de código.

7. O que são Assertions?

Uma assertion é uma verificação utilizada para confirmar se uma condição esperada foi atendida.

Por exemplo, podemos verificar se um botão está visível: 

cy.get('button')
    .should('be.visible')

Nesse caso, o teste espera que o botão esteja visível na página.

Pense assim:

Ação → executar alguma coisa.

Assertion → verificar se o resultado esperado aconteceu.

Fluxo básico de um teste automatizado

🌐

1. Preparar

Acessar a aplicação e preparar o cenário.

🖱️

2. Interagir

Clicar, digitar, selecionar e executar ações na aplicação.

🔍

3. Validar

Verificar se o comportamento esperado aconteceu.

📊

4. Resultado

Registrar se o cenário passou ou falhou.

Conceitos importantes

Conceito Descrição Exemplo
Teste Verificação de um comportamento esperado. Validar o login.
Teste Manual Executado por uma pessoa. Preencher o formulário manualmente.
Automação Execução de verificações através de código e ferramentas. Cypress.
E2E Teste de um fluxo completo. Login → produto → checkout.
Assertion Verificação de uma condição esperada. Elemento deve estar visível.

Erros comuns

❌ "Automatizar tudo"

Automação não significa que todo cenário precisa obrigatoriamente ser automatizado. A estratégia deve considerar o objetivo de cada teste.

❌ "Teste automatizado não falha"

Testes automatizados também podem apresentar falhas, falsos positivos, falsos negativos ou problemas de manutenção.

❌ "Cypress substitui conhecimento de testes"

Cypress é uma ferramenta. Conhecer fundamentos de testes continua sendo importante para criar cenários relevantes.

❌ "Basta verificar se a página abriu"

Um teste precisa validar comportamentos relevantes da aplicação, e não apenas verificar se uma página foi carregada.

Resumindo

🧪 Testes de software → verificam comportamentos esperados da aplicação.

👨‍💻 Testes manuais → são executados por uma pessoa.

🤖 Automação → utiliza código e ferramentas para executar verificações automaticamente.

🌐 Testes E2E → verificam fluxos completos da aplicação.

🔍 Assertions → verificam se o resultado esperado aconteceu.

🧰 Cypress → será a ferramenta utilizada nesta trilha para aprender automação de aplicações web.
