O que são seletores?

Um seletor é uma forma de identificar um elemento dentro da página HTML.

No Cypress, utilizamos seletores principalmente através do comando cy.get(). 

cy.get('#login')

Nesse exemplo, o Cypress procura um elemento que possua o atributo id="login".

🎯 Seletor → identifica um elemento da página.

🔎 cy.get() → localiza o elemento utilizando um seletor.

🧪 Teste → utiliza o elemento encontrado para realizar uma ação ou validação.

1. O problema dos seletores frágeis

Nem todo seletor é igualmente confiável.

Seletores baseados em detalhes visuais ou na estrutura interna da página podem quebrar quando a interface sofre alterações.

Por exemplo: 

cy.get('.btn-primary')

cy.get('.container > div:nth-child(2)')

cy.get('button')

Esses seletores podem depender de classes, posições ou estruturas que podem ser alteradas durante o desenvolvimento da aplicação.

Problema:

Uma alteração visual que não muda o comportamento da aplicação pode fazer o teste deixar de encontrar o elemento.

2. Principais tipos de seletores

Existem diversas formas de localizar elementos utilizando CSS.

Tipo Exemplo Característica
ID #login Identifica um elemento pelo atributo id.
Classe .btn-primary Utiliza uma classe CSS.
Tag button Localiza elementos pelo nome da tag.
Atributo [type="email"] Utiliza atributos HTML.
Data attribute [data-testid="login"] Atributo criado para identificar elementos de forma explícita.

3. O que são data attributes?

HTML permite a criação de atributos personalizados utilizando o prefixo data-.

Por exemplo: 

<button
    data-testid="login"
>
    Entrar
</button>

O atributo data-testid não representa uma característica visual do botão.

Ele pode ser utilizado como uma identificação específica para testes.

A principal vantagem é separar a identificação utilizada pela automação das classes utilizadas para estilização.

4. Utilizando data-testid

Podemos criar um elemento com um identificador específico para o teste: 

<input
    type="email"
    data-testid="email"
>

No Cypress: 

cy.get('[data-testid="email"]')

Podemos então realizar ações sobre o elemento: 

cy.get('[data-testid="email"]')
    .type('usuario@teste.com')
🏷️

Identificação

O elemento recebe um identificador específico para automação.

🔎

Localização

O Cypress utiliza o atributo para encontrar o elemento.

🧪

Automação

O teste pode interagir com o elemento utilizando um seletor dedicado.

5. Utilizando data-cy

Outra convenção comum em projetos Cypress é utilizar o atributo data-cy. 

<button
    data-cy="login"
>
    Entrar
</button>

No teste: 

cy.get('[data-cy="login"]')
    .click()

O nome do atributo utilizado é uma decisão de arquitetura do projeto. O mais importante é definir uma convenção e utilizá-la de forma consistente.

Exemplo de convenção:

Elementos utilizados pela automação podem receber atributos data-cy seguindo um padrão definido pela equipe.

6. data-test, data-testid e data-cy

Existem diferentes convenções para atributos destinados aos testes.

Atributo Exemplo Uso
data-test [data-test="login"] Identificação dedicada à automação.
data-testid [data-testid="login"] Identificação específica para testes.
data-cy [data-cy="login"] Convenção frequentemente utilizada em projetos Cypress.

O importante é evitar misturar diferentes padrões sem uma justificativa. Uma convenção consistente facilita a manutenção dos testes.

7. Criando um formulário preparado para testes

Imagine um formulário de login: 

<form>

    <input
        type="email"
        data-testid="email"
    >

    <input
        type="password"
        data-testid="senha"
    >

    <button
        data-testid="login"
    >
        Entrar
    </button>

</form>

Podemos escrever o teste: 

cy.get('[data-testid="email"]')
    .type('usuario@teste.com')

cy.get('[data-testid="senha"]')
    .type('123456')

cy.get('[data-testid="login"]')
    .click()

O teste não depende da classe CSS utilizada para estilizar o formulário.

8. Classe CSS versus data attribute

Considere o seguinte botão: 

<button
    class="btn btn-primary"
    data-testid="login"
>
    Entrar
</button>

Poderíamos localizar o elemento pela classe: 

cy.get('.btn-primary')

Ou pelo atributo dedicado: 

cy.get('[data-testid="login"]')
🎨

Classe CSS

Normalmente está relacionada à apresentação visual do elemento.

🧪

Data attribute

Pode ser utilizado especificamente para identificação durante a automação.

9. Selecionar pelo texto

O Cypress também permite localizar elementos pelo texto utilizando comandos como contains(). 

cy.contains('Entrar')

Essa abordagem pode ser útil quando o texto representa exatamente o comportamento que queremos validar.

Porém, se o texto mudar por motivos de tradução, conteúdo ou alteração de interface, o teste pode precisar ser atualizado.

Importante:

A escolha do seletor deve considerar a finalidade do teste e a estabilidade esperada do elemento.

10. Evitando seletores dependentes da estrutura

Um seletor como este depende diretamente da estrutura HTML: 

cy.get('.container > div:nth-child(2) > button')

Se um novo elemento for inserido na estrutura, o seletor pode deixar de apontar para o elemento esperado.

Uma alternativa é utilizar um atributo específico: 

cy.get('[data-testid="salvar"]')

Quanto mais um seletor depender de detalhes internos da estrutura da página, maior pode ser o impacto de alterações estruturais no teste.

11. Criando uma boa nomenclatura

Os valores dos atributos também precisam seguir uma convenção.

Exemplos: 

data-testid="login"

data-testid="email"

data-testid="senha"

data-testid="botao-salvar"

data-testid="mensagem-sucesso"

Evite nomes pouco claros: 

data-testid="elemento1"

data-testid="teste"

data-testid="botao"

O nome deve ajudar a identificar a finalidade do elemento sem depender da aparência visual da interface.

12. Definindo um padrão para o projeto

Uma equipe pode definir uma convenção para todos os elementos utilizados pela automação.

Por exemplo: 

data-testid="login-email"

data-testid="login-senha"

data-testid="login-submit"

data-testid="login-error"

O prefixo login identifica o contexto e a segunda parte identifica a finalidade do elemento.

🧩

Contexto

Identifique a funcionalidade ou componente ao qual o elemento pertence.

🏷️

Finalidade

Descreva o papel do elemento dentro daquela funcionalidade.

📐

Consistência

Utilize o mesmo padrão em diferentes telas e funcionalidades.

13. Seletores em componentes reutilizáveis

Componentes reutilizáveis também podem possuir atributos destinados aos testes.

Por exemplo, um componente de botão: 

<button
    data-testid="salvar"
>
    Salvar
</button>

Em diferentes páginas, o teste pode utilizar o mesmo padrão: 

cy.get('[data-testid="salvar"]')
    .click()

Componentes bem identificados facilitam a automação e reduzem a necessidade de criar seletores complexos.

14. Seletores e Page Objects

Os seletores também podem ser centralizados em Page Objects. 

class LoginPage {

    email() {

        return cy.get('[data-testid="email"]')

    }

    senha() {

        return cy.get('[data-testid="senha"]')

    }

    login() {

        return cy.get('[data-testid="login"]')

    }

}

O teste pode então utilizar os métodos: 

loginPage.email()
    .type('usuario@teste.com')

loginPage.senha()
    .type('123456')

loginPage.login()
    .click()

Dessa forma, alterações nos seletores podem ser centralizadas em um único local, dependendo da arquitetura adotada pelo projeto.

15. Seletores em tabelas e listas

Atributos de teste também podem ajudar a identificar registros específicos em tabelas e listas. 

<tr data-testid="usuario-123">

    <td>
        Maria
    </td>

    <td>
        maria@teste.com
    </td>

</tr>

O teste pode localizar o registro: 

cy.get('[data-testid="usuario-123"]')

Também podemos combinar atributos e outros seletores quando necessário: 

cy.get('[data-testid="usuario-123"]')
    .should('contain', 'Maria')

16. Cuidado com valores dinâmicos

Em aplicações que geram identificadores dinamicamente, é importante avaliar se o valor utilizado no seletor será previsível durante o teste.

Por exemplo: 

data-testid="usuario-987654"

Se o número mudar a cada execução, o teste não poderá depender diretamente desse valor.

Uma alternativa pode ser utilizar uma identificação estável: 

data-testid="usuario"
Regra prática:

Evite construir testes dependentes de valores dinâmicos quando existir uma identificação estável para o mesmo elemento.

Boas práticas para seletores

🎯

Prefira estabilidade

Escolha identificadores que não dependam de detalhes visuais da aplicação.

🏷️

Use data attributes

Considere atributos dedicados para os elementos importantes da automação.

📐

Defina convenções

Utilize uma nomenclatura consistente em todo o projeto.

🚫

Evite seletores frágeis

Evite depender excessivamente de classes, posições e estruturas internas.

Exemplo completo

Vamos preparar uma tela de login utilizando atributos dedicados à automação.

HTML: 

<form data-testid="login-form">

    <input
        type="email"
        data-testid="login-email"
    >

    <input
        type="password"
        data-testid="login-senha"
    >

    <button
        type="submit"
        data-testid="login-submit"
    >
        Entrar
    </button>

</form>

Teste Cypress: 

describe('Login', () => {

    it('deve realizar login', () => {

        cy.visit('/login')

        cy.get('[data-testid="login-email"]')
            .type('usuario@teste.com')

        cy.get('[data-testid="login-senha"]')
            .type('123456')

        cy.get('[data-testid="login-submit"]')
            .click()

    })

})

O teste utiliza identificadores específicos para localizar cada elemento da tela.

Dessa forma, a automação fica menos dependente das classes e da estrutura visual da página.

Comparando estratégias

Estratégia Exemplo Dependência
Classe .btn-primary Estilização CSS.
Texto cy.contains('Entrar') Conteúdo apresentado ao usuário.
Estrutura div > div > button Estrutura HTML.
Data attribute [data-testid="login"] Identificação dedicada ao elemento.

Não existe um único seletor que seja adequado para todos os cenários. A estratégia deve considerar a finalidade do teste, a aplicação e as convenções utilizadas pelo projeto.

Erros comuns com seletores

❌

Depender de classes visuais

Utilizar classes exclusivamente criadas para estilização como principal seletor.

❌

Usar posições

Depender de nth-child ou posições fixas dentro da estrutura HTML.

❌

Nomes inconsistentes

Utilizar diferentes padrões de nomenclatura sem uma convenção definida.

❌

Identificadores dinâmicos

Criar testes dependentes de valores que mudam entre execuções.
