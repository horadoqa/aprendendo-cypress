O que é o Cypress App?

O Cypress App é a interface gráfica do Cypress utilizada para trabalhar com os testes durante o desenvolvimento.

Por meio dele podemos abrir um projeto, escolher o tipo de teste, visualizar os arquivos disponíveis e executar uma especificação.

🖥️ Cypress App → interface gráfica para desenvolvimento e execução dos testes.

🧪 Spec → arquivo que contém os testes.

▶️ Execução → permite acompanhar visualmente o teste no navegador.

1. Abrindo o Cypress App

Para abrir a interface do Cypress em um projeto, utilizamos o comando: 

npx cypress open

O comando inicia a interface gráfica do Cypress e permite selecionar como os testes serão executados.

Importante:

O comando deve ser executado dentro do diretório do projeto que possui o Cypress instalado. 

cd curso-cypress

npx cypress open

2. Escolhendo o tipo de teste

Ao abrir o Cypress App, podemos encontrar opções relacionadas aos tipos de testes disponíveis no projeto.

🌐

E2E Testing

Utilizado para testes End-to-End que simulam comportamentos completos da aplicação.

🧩

Component Testing

Utilizado para testar componentes individualmente.

Nesta trilha vamos trabalhar principalmente com End-to-End Testing.

3. Selecionando E2E Testing

Para nosso curso, vamos selecionar a opção E2E Testing.

O Cypress apresentará informações relacionadas à configuração necessária para executar os testes End-to-End. 

E2E Testing

    ↓

Configuração do projeto

    ↓

Seleção do navegador

    ↓

Lista de testes

Depois dessa etapa, teremos acesso à tela que apresenta os arquivos de teste disponíveis.

4. Escolhendo o navegador

O Cypress permite executar os testes em navegadores compatíveis instalados no ambiente.

🌐

Chrome

Um dos navegadores utilizados com frequência durante o desenvolvimento dos testes.

🦊

Firefox

Navegador que também pode ser utilizado para execução dos testes.

🧭

Edge

Outra opção de navegador baseada em Chromium.

Boa prática:

Durante o desenvolvimento, é interessante conhecer o comportamento dos testes em diferentes navegadores quando isso fizer parte dos requisitos do projeto.

5. O que é uma Spec?

Uma spec é um arquivo que contém uma ou mais definições de teste.

Em um projeto Cypress, podemos organizar os testes dentro da pasta: 

cypress/

└── e2e/

    ├── login.cy.js
    ├── produtos.cy.js
    └── checkout.cy.js

Cada arquivo pode representar um conjunto de cenários relacionados a determinada funcionalidade.

🔐

login.cy.js

Testes relacionados ao processo de login.

🛒

produtos.cy.js

Testes relacionados à consulta e utilização de produtos.

💳

checkout.cy.js

Testes relacionados ao fluxo de checkout.

6. Selecionando uma Spec

Depois de abrir o Cypress App e selecionar E2E, o Cypress apresenta os arquivos de teste encontrados no projeto.

Podemos selecionar uma spec para iniciar sua execução. 

cypress/e2e/

    login.cy.js
    produtos.cy.js
    checkout.cy.js

Ao selecionar: 

login.cy.js

o Cypress abre o navegador e executa os testes definidos nesse arquivo.

🧪 Spec → arquivo selecionado.

🌐 Navegador → ambiente onde o teste é executado.

📋 Runner → interface que apresenta o resultado da execução.

7. Conhecendo o Test Runner

O Test Runner é a interface onde podemos acompanhar visualmente a execução dos testes.

Durante a execução, o Cypress apresenta informações sobre os comandos realizados e o resultado das asserções. 

Suite de testes

    ✓ deve abrir a página

    ✓ deve exibir o título

    ✓ deve permitir realizar login
▶️

Execução

Permite acompanhar os comandos conforme eles são executados.

✅

Teste aprovado

Indica que o cenário foi executado com sucesso.

❌

Teste com falha

Permite identificar onde ocorreu o problema durante a execução.

8. Visualizando os comandos

Durante a execução, o Cypress apresenta os comandos realizados pelo teste.

Um teste simples pode executar: 

cy.visit('/')

cy.get('h1')

    .should('be.visible')

No Test Runner, podemos acompanhar a execução dessas etapas de forma visual.

🌐 cy.visit() → navega até uma página.

🔎 cy.get() → encontra um elemento.

✅ should() → verifica uma condição.

9. Utilizando o Cypress para investigar falhas

Uma das vantagens do Cypress App durante o desenvolvimento é a possibilidade de observar visualmente o comportamento do teste.

Quando uma etapa falha, podemos analisar o comando que apresentou o problema e observar o estado da aplicação naquele momento.

🔎

Localizar a falha

Identifique qual comando ou asserção apresentou o problema.

🖥️

Observar a aplicação

Analise o estado da interface durante a execução do teste.

🧩

Investigar a causa

Utilize as informações disponíveis para entender a origem da falha.

10. Reexecutando os testes

Durante o desenvolvimento, podemos alterar o código da aplicação ou dos testes e executar novamente a spec para verificar o resultado.

Esse ciclo faz parte do processo de desenvolvimento de testes automatizados: 

Alterar teste

    ↓

Executar

    ↓

Observar resultado

    ↓

Identificar problema

    ↓

Corrigir

    ↓

Executar novamente

🔄 O Cypress App facilita esse ciclo porque permite acompanhar visualmente o comportamento do teste durante o desenvolvimento.

11. Cypress Open x Cypress Run

O Cypress possui duas formas importantes de executar os testes.

Comando Objetivo
npx cypress open Abre a interface gráfica para desenvolvimento e execução interativa.
npx cypress run Executa os testes pela linha de comando, normalmente em modo headless.

🖥️ open → normalmente utilizado durante o desenvolvimento.

⚙️ run → muito utilizado em automações e pipelines.

12. O que é execução headless?

Na execução headless, o teste é executado sem a apresentação visual tradicional do navegador para o usuário.

Esse tipo de execução é especialmente importante em ambientes automatizados, como pipelines de CI/CD. 

npx cypress run
🖥️

Modo interativo

Ideal para desenvolvimento, investigação e acompanhamento visual dos testes.

⚙️

Modo headless

Adequado para execuções automatizadas em ambientes de CI/CD.

Erros comuns ao utilizar o Cypress App

❌

Executar fora do projeto

Rodar o comando do Cypress em um diretório que não possui o projeto configurado.

❌

Não encontrar as specs

Arquivos podem não estar no diretório ou padrão esperado pelo Cypress.

❌

Ignorar mensagens de erro

Falhas apresentadas pelo Test Runner devem ser analisadas para identificar sua causa.

❌

Confundir open e run

Cada comando possui uma finalidade diferente dentro do fluxo de automação.

Investigue as falhas

Não utilize a execução repetida apenas para ignorar problemas nos testes.

⚙️

Conheça os dois modos

Entenda quando utilizar a execução interativa e quando utilizar a linha de comando.
