Cypress Configuration

O que é Cypress Configuration?

Cypress Configuration é o conjunto de configurações utilizadas para definir como o Cypress deverá executar os testes de um determinado projeto.

Essas configurações ficam normalmente centralizadas no arquivo: 

cypress.config.js

⚙️ Configuração → define o comportamento do Cypress.

🧪 Testes → utilizam essas configurações durante a execução.

📁 Projeto → mantém as configurações centralizadas.

1. O arquivo cypress.config.js

O arquivo cypress.config.js é o principal arquivo utilizado para configurar o Cypress.

Uma estrutura básica pode ser: 

const { defineConfig } = require('cypress')

module.exports = defineConfig({

e2e: {

}

})

O objeto passado para defineConfig() contém as configurações do projeto.

Importante:

Não é necessário configurar todas as opções disponíveis. Utilize apenas as configurações necessárias para o projeto.

2. Entendendo o defineConfig()

O defineConfig() é utilizado para declarar as configurações do Cypress. 

const { defineConfig } = require('cypress')

module.exports = defineConfig({

e2e: {

}

})

A configuração é exportada pelo module.exports, permitindo que o Cypress utilize essas informações durante a execução.

📦

defineConfig()

Define as configurações que serão utilizadas pelo Cypress.

📤

module.exports

Exporta a configuração para que ela possa ser utilizada pelo Cypress.

3. Configuração de testes E2E

Como nosso curso trabalha principalmente com testes End-to-End, utilizaremos a propriedade e2e. 

module.exports = defineConfig({

e2e: {

    baseUrl: 'http://localhost:3000'

}

})

As configurações relacionadas aos testes E2E podem ser colocadas dentro desse objeto.

🧪 e2e → concentra configurações específicas dos testes End-to-End.

4. Configurando a baseUrl

A propriedade baseUrl define o endereço principal da aplicação que será testada. 

module.exports = defineConfig({

e2e: {

    baseUrl: 'http://localhost:3000'

}

})

Depois de configurar a baseUrl, podemos utilizar caminhos relativos: 

cy.visit('/')
cy.visit('/login')
cy.visit('/produtos')

Se a baseUrl for: 

http://localhost:3000

então: 

cy.visit('/login')

acessará: 

http://localhost:3000/login

5. Configurando o viewport

O Cypress permite configurar a largura e a altura do viewport utilizado durante a execução dos testes. 

module.exports = defineConfig({

viewportWidth: 1280,

viewportHeight: 720,

e2e: {

    baseUrl: 'http://localhost:3000'

}

})
↔️

viewportWidth

Define a largura do viewport.

↕️

viewportHeight

Define a altura do viewport.

6. Configurando o defaultCommandTimeout

O defaultCommandTimeout define o tempo padrão que determinados comandos do Cypress aguardam uma condição antes de falhar. 

module.exports = defineConfig({

defaultCommandTimeout: 10000,

e2e: {

    baseUrl: 'http://localhost:3000'

}

})

Nesse exemplo, o valor utilizado é de 10 segundos.

Boa prática:

Evite aumentar o timeout apenas para esconder problemas de sincronização ou lentidão da aplicação. Investigue primeiro a causa da demora.

7. Configurando retries

O Cypress permite configurar novas tentativas para testes que falharem. 

module.exports = defineConfig({

retries: {

    runMode: 2,

    openMode: 0

},

e2e: {

    baseUrl: 'http://localhost:3000'

}

})
Configuração Utilização
runMode Número de tentativas adicionais quando os testes são executados em modo não interativo.
openMode Número de tentativas adicionais quando os testes são executados no modo interativo.
Atenção:

Retries não corrigem a causa de um teste instável. Utilize esse recurso com critério e investigue falhas intermitentes.

8. Configurando vídeos

Em execuções realizadas pelo Cypress em modo não interativo, o projeto pode utilizar gravações de vídeo para auxiliar na análise das execuções.

Uma configuração possível é: 

module.exports = defineConfig({

video: true,

e2e: {

    baseUrl: 'http://localhost:3000'

}

})

🎥 video → controla a gravação de vídeos das execuções quando suportada pelo fluxo de execução utilizado.

9. Screenshots

Screenshots podem ser utilizados para registrar visualmente o estado da aplicação durante um teste.

Também podemos solicitar um screenshot diretamente durante um teste: 

cy.screenshot('pagina-inicial')

O screenshot pode ser especialmente útil quando precisamos analisar uma falha ou registrar uma determinada etapa do teste.

📸 cy.screenshot() → captura uma imagem da página durante o teste.

10. Configuração de tipos de teste

O Cypress permite configurar diferentes tipos de testes. Neste curso, nosso foco principal é o teste End-to-End. 

module.exports = defineConfig({

e2e: {

    baseUrl: 'http://localhost:3000'

}

})

A propriedade e2e indica que estamos configurando o comportamento relacionado aos testes End-to-End.

🌐

Testes E2E

Validam fluxos completos da aplicação através da perspectiva do usuário.

🧩

Component Testing

Permite testar componentes da interface de maneira isolada.

11. setupNodeEvents()

O Cypress também permite configurar eventos executados no contexto do Node.js através do setupNodeEvents(). 

const { defineConfig } = require('cypress')

module.exports = defineConfig({

e2e: {

    setupNodeEvents(on, config) {

    }

}

})

Essa função pode ser utilizada quando precisamos configurar determinados comportamentos que dependem do processo Node.js.

Importante:

Não precisamos utilizar setupNodeEvents() em todos os projetos. Ele deve ser utilizado quando existir uma necessidade específica.

12. Variáveis de ambiente

Podemos definir valores de ambiente dentro da configuração do Cypress. 

module.exports = defineConfig({

e2e: {

    env: {

        ambiente: 'teste'

    }

}

})

Essas informações podem ser utilizadas pelos testes de acordo com a necessidade do projeto.

Atenção:

Evite colocar credenciais, senhas ou tokens diretamente no arquivo de configuração versionado.

13. Criando uma configuração completa

Podemos combinar diferentes opções em um mesmo arquivo de configuração. 

const { defineConfig } = require('cypress')

module.exports = defineConfig({

viewportWidth: 1280,

viewportHeight: 720,

defaultCommandTimeout: 10000,

retries: {

    runMode: 2,

    openMode: 0

},

video: true,

e2e: {

    baseUrl: 'http://localhost:3000',

    env: {

        ambiente: 'teste'

    },

    setupNodeEvents(on, config) {

    }

}

})

Essa configuração reúne diversos conceitos estudados durante a aula.

🌐 baseUrl → endereço principal da aplicação.

↔️ viewportWidth → largura do viewport.

↕️ viewportHeight → altura do viewport.

⏱️ defaultCommandTimeout → tempo padrão de espera dos comandos.

🔄 retries → configura novas tentativas.

🎥 video → configura gravações de vídeo quando aplicável.

🧩 env → disponibiliza configurações específicas para os testes.

14. Configuração aplicada a um teste

Considere a seguinte configuração: 

e2e: {

baseUrl: 'http://localhost:3000'

}

Podemos escrever um teste simples: 

describe('Página inicial', () => {

it('deve carregar a página', () => {

    cy.visit('/')

    cy.get('h1')
        .should('be.visible')

})

})

Nesse caso, o teste utiliza a baseUrl configurada no projeto sem precisar repetir a URL completa.

15. Trabalhando com diferentes ambientes

Projetos reais podem possuir diferentes ambientes para execução dos testes.

💻

Desenvolvimento

Ambiente utilizado durante o desenvolvimento da aplicação.

🧪

Homologação

Ambiente utilizado para validações antes da publicação.

🚀

Produção

Ambiente onde a aplicação está disponível para os usuários.

A configuração deve ser planejada de acordo com a estratégia de execução dos testes e com a infraestrutura utilizada pelo projeto.

Boas práticas de configuração

🎯

Configure apenas o necessário

Evite configurações que não possuem uma finalidade clara no projeto.

📁

Centralize configurações

Utilize o arquivo de configuração para informações que devem ser compartilhadas.

🔐

Proteja informações sensíveis

Não versione credenciais, senhas ou tokens diretamente no projeto.

🧹

Evite configurações desnecessárias

Mantenha o arquivo simples e fácil de entender.

Erros comuns

❌

baseUrl incorreta

Configurar uma URL que não corresponde ao ambiente onde a aplicação está executando.

❌

Timeout muito alto

Aumentar o timeout sem investigar a causa da lentidão ou falha.

❌

Excesso de retries

Utilizar várias tentativas para mascarar testes instáveis.

❌

Credenciais no código

Armazenar senhas ou tokens diretamente no arquivo versionado.
