AULA 3 • FUNDAMENTOS DE TESTES

Tipos de Testes de Software

Conheça os principais tipos de testes, entenda seus objetivos e descubra onde os testes automatizados com Cypress se encaixam.

Objetivos da aula

Na aula anterior, vimos a diferença entre testes manuais e automatizados.

Agora vamos entender que existem diferentes tipos de testes e que cada um possui objetivos diferentes.

🧩

Testes Unitários

Verificam pequenas unidades de código de forma isolada.

🔗

Testes de Integração

Verificam a interação entre diferentes componentes ou partes do sistema.

🌐

Testes E2E

Validam fluxos completos da aplicação sob a perspectiva de um usuário ou sistema.

Por que existem diferentes tipos de testes?

Uma aplicação possui várias partes. Podemos ter funções, componentes, APIs, bancos de dados, páginas e integrações com outros sistemas.

Um único tipo de teste não precisa verificar todos esses elementos da mesma maneira.

🧩 Unidade: verifica uma pequena parte do código.

🔗 Integração: verifica a comunicação entre partes.

🌐 E2E: verifica um fluxo completo.

Pensar nesses diferentes níveis ajuda a construir uma estratégia de testes mais organizada.

1. Testes Unitários

Testes unitários verificam pequenas unidades de código de maneira isolada.

Uma unidade pode ser uma função, método ou outro pequeno componente lógico do sistema.

Exemplo:

Imagine uma função responsável por calcular o valor total de uma compra.

Podemos fornecer alguns valores para a função e verificar se o resultado calculado está correto. 

function calcularTotal(preco, quantidade) {
    return preco * quantidade
}

calcularTotal(10, 3)

// Resultado esperado:
// 30

Nesse exemplo, podemos testar especificamente o comportamento da função sem precisar abrir uma página da aplicação.

Características dos testes unitários

🎯

Escopo pequeno

Normalmente verificam uma unidade específica do código.

⚡

Execução rápida

Como possuem escopo reduzido, normalmente podem ser executados rapidamente.

🧪

Isolamento

Procuram testar a unidade sem depender desnecessariamente de outras partes do sistema.

🔍

Feedback rápido

Podem indicar rapidamente problemas em pequenas partes do código.

2. Testes de Integração

Testes de integração verificam como diferentes partes de um sistema trabalham juntas.

Em uma aplicação, uma funcionalidade pode depender de vários componentes ou serviços.

Exemplo:

Uma API pode receber uma requisição, executar uma regra de negócio e consultar dados em outro componente.

Um teste de integração pode verificar a comunicação entre essas partes.

Exemplo de integração

🌐

API

Recebe uma requisição enviada pelo cliente.

⚙️

Regra de negócio

Processa as informações recebidas.

🗄️

Banco de dados

Armazena ou consulta informações.

🔄

Integração

O teste verifica a comunicação entre essas partes.

3. Testes End-to-End (E2E)

E2E significa End-to-End, ou "de ponta a ponta".

Esse tipo de teste procura validar um fluxo completo da aplicação, envolvendo diferentes partes do sistema.

Exemplo:

Um usuário acessa a aplicação, realiza login, pesquisa um produto, adiciona o produto ao carrinho e finaliza uma compra.

O teste pode verificar esse fluxo completo.

Exemplo de fluxo E2E

🔐

1. Login

O usuário informa suas credenciais.

🔎

2. Pesquisa

O usuário pesquisa um produto.

🛒

3. Carrinho

O produto é adicionado ao carrinho.

💳

4. Checkout

O usuário conclui o processo de compra.

Onde o Cypress entra?

O Cypress é uma ferramenta voltada principalmente para testes de aplicações web.

Ao longo deste curso, veremos como utilizá-lo para criar testes automatizados que interagem com uma aplicação e verificam seus comportamentos.

🌐 Aplicação Web

↓

🤖 Cypress → executa ações e realiza verificações.

↓

✅ Resultado do teste

Cypress e testes E2E

Um dos usos mais conhecidos do Cypress é a automação de fluxos de aplicações web.

Podemos, por exemplo, criar um teste que simula um fluxo de login. 

describe('Login', () => {

    it('deve realizar login com sucesso', () => {

        cy.visit('/login')

        cy.get('[data-testid="email"]')
            .type('usuario@email.com')

        cy.get('[data-testid="senha"]')
            .type('123456')

        cy.get('[data-testid="entrar"]')
            .click()

        cy.url()
            .should('include', 'dashboard')

    })

})

O código acima será estudado em detalhes nas próximas aulas. Neste momento, o objetivo é identificar que estamos automatizando um fluxo da aplicação.

Unitário × Integração × E2E

Tipo O que verifica? Escopo Exemplo
Unitário Uma pequena unidade de código. Pequeno. Função de cálculo.
Integração Comunicação entre componentes. Médio. API + serviço + banco.
E2E Fluxo completo da aplicação. Grande. Login + compra.

A Pirâmide de Testes

Uma forma conhecida de representar uma estratégia de testes é através da Pirâmide de Testes.

BASE

Testes Unitários

Normalmente possuem escopo pequeno e podem fornecer feedback rapidamente.

MEIO

Testes de Integração

Verificam a interação entre diferentes componentes.

TOPO

Testes E2E

Verificam fluxos mais completos e podem envolver várias partes da aplicação.

Importante:

A pirâmide é um modelo conceitual. A estratégia real de testes pode variar de acordo com o sistema, riscos, arquitetura e necessidades do projeto.

Outros tipos e abordagens de testes

Além da classificação por nível, existem outras formas de classificar testes.

🔄

Regressão

Verifica se alterações introduziram problemas em comportamentos que anteriormente funcionavam.

🧭

Exploratório

Utiliza exploração e aprendizado durante a própria execução dos testes.

💨

Smoke Test

Conjunto de verificações iniciais para avaliar se uma versão possui condições básicas para continuar sendo testada.

🐞

Teste de Defeito

Pode ser criado para reproduzir e verificar um comportamento que apresentou problema.

Testes de regressão

Imagine que uma aplicação possui uma funcionalidade de login que já funciona corretamente.

Uma nova alteração é realizada no sistema. Essa alteração pode afetar outras partes da aplicação.

Antes da alteração: login funcionando.

↓

Alteração: nova funcionalidade adicionada.

↓

Regressão: verificar novamente o comportamento existente.

Testes automatizados podem ser utilizados como parte dessa estratégia.

Smoke Tests

Smoke tests são verificações iniciais utilizadas para avaliar se os principais comportamentos de uma versão estão funcionando o suficiente para permitir testes posteriores.

🔐

Login

Verificar se o usuário consegue acessar a aplicação.

🏠

Página inicial

Verificar se a aplicação consegue carregar a página principal.

🔎

Pesquisa

Verificar se uma funcionalidade essencial está disponível.

Como pensar sobre o tipo de teste?

Uma maneira simples de começar é perguntar: o que exatamente quero verificar?

Quero testar uma função

Um teste unitário pode ser apropriado para verificar essa unidade de código.

Quero testar uma integração

Um teste de integração pode verificar a comunicação entre componentes.

Quero testar um fluxo completo

Um teste E2E pode verificar o comportamento de ponta a ponta.

Erros comuns

❌ "Todo teste precisa ser E2E"

Diferentes níveis de teste possuem objetivos diferentes. Uma estratégia pode combinar diferentes tipos.

❌ "Cypress serve apenas para E2E"

O Cypress possui recursos para diferentes formas de teste em aplicações web. Neste curso, começaremos pelos fundamentos e pela automação de fluxos web.

❌ "Teste automatizado significa teste E2E"

Automação é uma forma de executar testes. Testes automatizados podem existir em diferentes níveis.

❌ "Quanto maior o teste, melhor"

O tamanho do teste não determina sozinho sua qualidade. O teste precisa ter um objetivo claro e verificável.
