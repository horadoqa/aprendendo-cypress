AULA 21 • ASSERTIONS

Assertions no Cypress

Aprenda o que são assertions, como utilizá-las no Cypress e como validar se a aplicação está apresentando o comportamento esperado.

Objetivos da aula

Nas aulas anteriores aprendemos a localizar elementos, interagir com a página e utilizar comandos como cy.visit(), cy.get(), click() e type().

Agora vamos aprender a validar os resultados dessas ações utilizando assertions.

✅

Entender Assertions

Compreender o conceito de asserção e sua importância nos testes automatizados.

🔎

Validar elementos

Verificar se elementos estão presentes e apresentam o comportamento esperado.

📝

Validar informações

Validar textos, atributos, valores e estados dos elementos.

🧪

Criar testes confiáveis

Transformar ações executadas pelo teste em verificações reais.

O que é uma Assertion?

Uma assertion é uma verificação realizada durante o teste para confirmar se uma determinada condição é verdadeira.

Em outras palavras, a assertion responde a uma pergunta:

🤔 O resultado obtido é o resultado esperado?

Por exemplo, podemos verificar se um título está visível na página: 

cy.get('h1')
    .should('be.visible')

Nesse caso, o teste espera encontrar o elemento h1 e verifica se ele está visível.

Ação x Validação

Um teste automatizado normalmente possui ações realizadas pelo usuário e validações que verificam o resultado dessas ações.

🖱️

Ação

O teste executa uma interação, como clicar em um botão. 

cy.get('button')
    .click()
✅

Validação

O teste verifica se o resultado esperado aconteceu. 

cy.get('.mensagem')
    .should('be.visible')

🧪 Teste completo: realizar uma ação e verificar o resultado esperado.

1. Utilizando should()

O comando should() é uma das formas mais utilizadas para criar assertions no Cypress. 

cy.get('h1')
    .should('be.visible')

Nesse exemplo estamos dizendo:

🔎 Localize o elemento h1.

✅ Verifique se ele está visível.

Caso a condição não seja atendida, o teste será considerado como falho.

2. Validando visibilidade

Uma das assertions mais utilizadas é be.visible. 

cy.get('.login-form')
    .should('be.visible')

Esse teste verifica se o formulário de login está visível para o usuário.

Também podemos validar um botão: 

cy.get('button[type="submit"]')
    .should('be.visible')
Quando utilizar?

Utilize essa assertion quando a visibilidade do elemento fizer parte do comportamento esperado da aplicação.

3. Validando existência

A assertion exist verifica se o elemento existe no DOM. 

cy.get('.menu')
    .should('exist')

A diferença importante é que um elemento pode existir no DOM sem necessariamente estar visível.

🌐

exist

Verifica se o elemento existe no DOM. 

should('exist')
👁️

be.visible

Verifica se o elemento está visível. 

should('be.visible')

4. Validando que um elemento não existe

Também podemos validar que determinado elemento não existe no DOM. 

cy.get('.mensagem-erro')
    .should('not.exist')

Esse tipo de validação pode ser útil quando uma mensagem ou componente não deveria aparecer.

❌ not.exist → o elemento não deve existir no DOM.

5. Validando elementos habilitados

Podemos verificar se um elemento está habilitado utilizando be.enabled. 

cy.get('button')
    .should('be.enabled')

Esse tipo de assertion é útil principalmente para botões e campos de formulário.

Também podemos verificar o contrário: 

cy.get('button')
    .should('be.disabled')
🟢

be.enabled

Verifica se o elemento está habilitado.

🔴

be.disabled

Verifica se o elemento está desabilitado.

6. Validando checkbox e radio button

Para elementos como checkbox e radio button, podemos verificar se estão selecionados. 

cy.get('input[type="checkbox"]')
    .should('be.checked')

Também podemos validar quando o elemento não está selecionado: 

cy.get('input[type="checkbox"]')
    .should('not.be.checked')

☑️ be.checked → elemento selecionado.

☐ not.be.checked → elemento não selecionado.

7. Validando textos

Podemos verificar o conteúdo de um elemento utilizando have.text. 

cy.get('h1')
    .should('have.text', 'Página inicial')

Essa assertion verifica o texto completo do elemento.

Também podemos utilizar include.text quando queremos verificar apenas uma parte do texto. 

cy.get('.mensagem')
    .should('include.text', 'sucesso')
📝

have.text

Valida o conteúdo de texto esperado.

🔎

include.text

Verifica se o texto contém determinado conteúdo.

8. Validando valores de campos

Para campos de formulário podemos utilizar have.value. 

cy.get('input[name="email"]')
    .should('have.value', 'usuario@email.com')

Esse tipo de validação é útil depois de preencher um campo: 

cy.get('input[name="email"]')
    .type('usuario@email.com')

cy.get('input[name="email"]')
    .should('have.value', 'usuario@email.com')

9. Validando atributos

Também podemos verificar atributos de elementos utilizando have.attr. 

cy.get('a.logo')
    .should('have.attr', 'href')

Podemos também verificar o valor esperado do atributo: 

cy.get('a.logo')
    .should('have.attr', 'href', '/')

🔗 have.attr → permite validar atributos como href, src, id, title e outros.

10. Validando classes CSS

Podemos verificar se um elemento possui determinada classe utilizando have.class. 

cy.get('.alerta')
    .should('have.class', 'alerta-sucesso')

Essa validação pode ser útil quando uma classe representa determinado estado visual da aplicação. 

cy.get('.status')
    .should('have.class', 'ativo')

11. Utilizando negações

O Cypress permite utilizar not para validar que uma determinada condição não seja verdadeira. 

cy.get('.loading')
    .should('not.be.visible')

Outro exemplo: 

cy.get('button')
    .should('not.be.disabled')

✅ be.visible → esperamos que esteja visível.

❌ not.be.visible → esperamos que não esteja visível.

12. Encadeando assertions

Podemos realizar várias validações sobre o mesmo elemento. 

cy.get('button')
    .should('be.visible')
    .and('be.enabled')
    .and('have.text', 'Entrar')

Nesse exemplo verificamos três condições:

👁️ O botão está visível.

🟢 O botão está habilitado.

📝 O botão possui o texto esperado.

O método and() permite continuar a cadeia de validações.

13. Exemplo completo de teste

Vamos combinar ações e assertions em um teste simples de login. 

describe('Login', () => {

    it('deve realizar login com sucesso', () => {

        cy.visit('/login')

        cy.get('[data-testid="email"]')
            .type('usuario@email.com')

        cy.get('[data-testid="senha"]')
            .type('123456')

        cy.get('[data-testid="entrar"]')
            .click()

        cy.get('h1')
            .should('be.visible')
            .and('have.text', 'Dashboard')

    })

})

🧭 Fluxo:

1️⃣ Acessar a página de login.

2️⃣ Preencher o e-mail.

3️⃣ Preencher a senha.

4️⃣ Clicar no botão.

5️⃣ Validar o resultado.

14. Assertions devem validar comportamento

Uma assertion deve representar uma expectativa real sobre o comportamento da aplicação.

Por exemplo, apenas verificar se um elemento existe pode não ser suficiente: 

cy.get('.mensagem')
    .should('exist')

Se o objetivo do teste é verificar uma mensagem de sucesso, podemos realizar uma validação mais específica: 

cy.get('.mensagem')
    .should('be.visible')
    .and('have.text', 'Cadastro realizado com sucesso')
Boa prática:

Prefira assertions que validem aquilo que realmente importa para o comportamento que está sendo testado.

15. Assertions comuns

Assertion Objetivo
be.visible Verifica se o elemento está visível.
exist Verifica se o elemento existe no DOM.
not.exist Verifica se o elemento não existe.
be.enabled Verifica se o elemento está habilitado.
be.disabled Verifica se o elemento está desabilitado.
be.checked Verifica se checkbox ou radio está selecionado.
have.text Valida o texto do elemento.
include.text Verifica se o elemento contém determinado texto.
have.value Valida o valor de um campo.
have.attr Valida atributos do elemento.
have.class Valida classes CSS.

Erros comuns ao utilizar Assertions

❌

Não validar o resultado

Criar um teste que apenas executa ações sem verificar se o comportamento esperado aconteceu.

❌

Validar apenas existência

Verificar somente se um elemento existe quando seria necessário validar seu conteúdo ou estado.

❌

Assertions muito genéricas

Utilizar verificações que não representam claramente o comportamento esperado.

❌

Excesso de validações

Adicionar diversas assertions sem relação com o objetivo principal do teste.

Boas práticas com Assertions

🎯

Valide o comportamento

Crie assertions relacionadas ao resultado esperado pelo usuário.

🔎

Seja específico

Prefira validações que realmente comprovem o resultado esperado.

🧪

Combine ações e validações

Depois de executar uma ação importante, verifique seu resultado.

🧹

Evite excesso

Mantenha somente as validações relevantes para o objetivo do teste.
