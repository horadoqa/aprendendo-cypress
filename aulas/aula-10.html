O que é um teste automatizado?

Um teste automatizado é um conjunto de instruções executadas por uma ferramenta para verificar se a aplicação apresenta o comportamento esperado.

Em um teste E2E com Cypress, podemos reproduzir ações semelhantes às realizadas por um usuário: acessar uma página, encontrar um elemento, clicar, preencher um campo e verificar um resultado.

👤 Usuário → realiza uma ação.

🤖 Cypress → automatiza essa ação.

🔎 Assertion → verifica se o resultado esperado aconteceu.

1. Criando a primeira Spec

Os testes End-to-End ficam dentro da pasta cypress/e2e.

Vamos criar um arquivo chamado: 

cypress/e2e/primeiro-teste.cy.js

O sufixo .cy.js é utilizado para identificar arquivos de teste Cypress escritos em JavaScript.

📁 cypress/e2e → pasta dos testes E2E.

📄 primeiro-teste.cy.js → arquivo contendo os testes.

2. Estrutura básica de um teste

Uma estrutura simples de teste pode ser criada utilizando describe() e it(). 

describe('Minha primeira suíte', () => {

it('meu primeiro teste', () => {

    // comandos do teste

})

})

Essa estrutura permite organizar os testes em grupos e definir o comportamento esperado em cada cenário.

📦

describe()

Agrupa testes relacionados a uma determinada funcionalidade ou contexto.

🧪

it()

Representa um caso de teste específico que será executado pelo Cypress.

3. Criando o primeiro teste

Vamos criar um teste simples para acessar a página inicial da aplicação. 

describe('Página inicial', () => {

it('deve acessar a página inicial', () => {

    cy.visit('/')

})

})

O comando cy.visit() é utilizado para navegar até uma página da aplicação.

Como configuramos a baseUrl na aula anterior, podemos utilizar apenas: 

cy.visit('/')

🌐 baseUrl → define o endereço principal.

🧭 cy.visit() → navega até o endereço informado.

4. Executando o primeiro teste

Depois de criar o arquivo, podemos abrir o Cypress utilizando: 

npx cypress open

Na interface do Cypress, devemos acessar a opção de testes E2E e localizar o arquivo: 

primeiro-teste.cy.js

Ao selecionar o arquivo, o Cypress abrirá o navegador e executará o teste.

💻

Abrir Cypress

Execute npx cypress open para iniciar a interface do Cypress.

🧪

Selecionar E2E

Escolha o modo de testes End-to-End.

📄

Selecionar a Spec

Abra o arquivo primeiro-teste.cy.js.

▶️

Executar

O Cypress executará automaticamente os comandos definidos no teste.

5. Entendendo o resultado

Quando o teste é executado, o Cypress apresenta informações sobre o resultado da execução.

Quando todas as etapas são concluídas sem falhas, o teste é apresentado como aprovado.

✅ Passed → o teste foi executado com sucesso.

❌ Failed → alguma etapa do teste apresentou uma falha.

⏸️ Pending → o teste foi definido, mas não foi executado.

A interface também apresenta detalhes da execução, facilitando a identificação da etapa em que ocorreu algum problema.

6. Adicionando uma asserção

Um teste não precisa apenas executar ações. Ele também deve verificar se o resultado esperado realmente aconteceu.

Para isso, podemos utilizar uma asserção com should(). 

describe('Página inicial', () => {

it('deve exibir o título da página', () => {

    cy.visit('/')

    cy.get('h1')
        .should('be.visible')

})

})

Nesse exemplo, o Cypress procura um elemento h1 e verifica se ele está visível.

🔎 cy.get() → localiza o elemento.

✅ should() → verifica uma condição esperada.

7. Entendendo o fluxo do teste

Nosso primeiro teste possui um fluxo bastante simples: 

cy.visit('/')

    ↓

cy.get('h1')

    ↓

should('be.visible')

Podemos interpretar esse fluxo da seguinte forma:

1️⃣

Acessar

O Cypress acessa a página inicial da aplicação.

2️⃣

Localizar

O Cypress procura o elemento definido pelo seletor.

3️⃣

Validar

O Cypress verifica se o elemento está visível.

8. Criando mais de um teste

Uma mesma Spec pode conter vários casos de teste. 

describe('Página inicial', () => {

it('deve acessar a página', () => {

    cy.visit('/')

})

it('deve exibir o título', () => {

    cy.visit('/')

    cy.get('h1')
        .should('be.visible')

})

})

Cada chamada de it() representa um caso de teste independente dentro da suíte.

Boa prática:

Procure criar testes que tenham um objetivo claro. Isso facilita a leitura e a identificação de falhas.

9. Testando o título da página

Podemos verificar também o título definido no elemento <title> da página. 

cy.visit('/')

cy.title()
.should('eq', 'Minha Aplicação')

O comando cy.title() obtém o título atual da página.

Depois utilizamos should() para verificar se o valor corresponde ao esperado.

🌐 cy.visit() → acessa a página.

🏷️ cy.title() → obtém o título da página.

✅ should('eq', ...) → verifica se o valor é igual ao esperado.

10. Validando textos

Outra validação comum é verificar se determinado texto está presente na página. 

cy.get('h1')
.should('contain', 'Bem-vindo')

Nesse exemplo, o Cypress procura o elemento h1 e verifica se ele contém o texto esperado.

Também podemos utilizar uma verificação de igualdade quando desejamos validar exatamente o conteúdo: 

cy.get('h1')
.should('have.text', 'Bem-vindo')
Atenção:

A escolha da asserção depende do comportamento que queremos validar. Em alguns casos, verificar se um texto está contido no elemento é mais adequado do que exigir igualdade exata.

11. Construindo um teste completo

Podemos combinar navegação, localização de elementos e validações em um único cenário. 

describe('Página inicial', () => {

it('deve carregar corretamente', () => {

    cy.visit('/')

    cy.get('h1')
        .should('be.visible')

    cy.title()
        .should('not.be.empty')

})

})

Esse teste realiza três ações principais:

🌐

Navegação

Acessa a página inicial utilizando cy.visit().

🔎

Localização

Localiza o elemento h1 utilizando cy.get().

✅

Validação

Verifica se o elemento está visível e se a página possui um título.

12. O que são os comandos cy?

Os comandos que começam com cy. fazem parte da API do Cypress.

Alguns exemplos que já conhecemos: 

cy.visit('/')

cy.get('h1')

cy.title()

Esses comandos são utilizados para interagir com a aplicação e obter informações durante a execução dos testes.

🌐

cy.visit()

Navega para uma URL.

🔎

cy.get()

Localiza elementos da página.

🏷️

cy.title()

Obtém o título atual da página.

13. Encadeando comandos

Os comandos do Cypress podem ser utilizados em sequência para representar um fluxo de teste. 

cy.get('button')
.should('be.visible')
.click()

Nesse exemplo, o Cypress:

1️⃣ Localiza o botão.

2️⃣ Verifica se o botão está visível.

3️⃣ Clica no botão.

Esse tipo de encadeamento será bastante utilizado nas próximas aulas.

14. O que acontece quando o teste falha?

Imagine que nosso teste espera encontrar um elemento h1, mas esse elemento não existe na página. 

cy.get('h1')
.should('be.visible')

Nesse caso, a asserção não será atendida e o Cypress marcará o teste como falho.

❌ Teste falhou → o comportamento esperado não foi encontrado.

🔎 Investigação → devemos analisar o motivo da falha.

🛠️ Correção → corrigimos a aplicação ou o próprio teste, conforme a causa identificada.

15. Utilizando o Cypress para investigar falhas

Uma das características úteis do Cypress é a possibilidade de acompanhar visualmente a execução do teste.

Quando um teste falha, podemos observar:

🖥️

Estado da página

Observar como a aplicação estava no momento da falha.

📋

Comando que falhou

Identificar qual comando ou asserção apresentou o problema.

🔍

Mensagem de erro

Analisar a mensagem apresentada pelo Cypress para entender a falha.

16. Executando o teste pelo terminal

Além da interface gráfica, também podemos executar os testes através do terminal.

Para executar os testes E2E em modo de execução, podemos utilizar: 

npx cypress run

Nesse modo, o Cypress executa os testes sem depender da interface interativa do Cypress App.

🖥️ cypress open → utilizado para trabalhar de forma interativa com a interface do Cypress.

⚙️ cypress run → utilizado para executar os testes pelo terminal.

17. Nosso primeiro fluxo E2E

Agora podemos representar um fluxo completo de teste: 

describe('Página inicial', () => {

it('deve carregar corretamente', () => {

    cy.visit('/')

    cy.get('h1')
        .should('be.visible')

    cy.title()
        .should('not.be.empty')

})

})

🌐 1. Navegar → acessamos a aplicação.

🔎 2. Localizar → encontramos um elemento.

✅ 3. Validar → verificamos o comportamento esperado.

📊 4. Resultado → o Cypress informa se o teste passou ou falhou.

Erros comuns ao criar o primeiro teste

❌

Esquecer a baseUrl

Tentar utilizar caminhos relativos sem configurar corretamente o endereço da aplicação.

❌

Seletor incorreto

Utilizar um seletor que não corresponde a nenhum elemento da página.

❌

Não criar uma asserção

Executar ações sem verificar se o resultado esperado realmente aconteceu.

❌

Teste sem objetivo claro

Criar cenários muito grandes ou difíceis de entender desde o início.

Boas práticas para os primeiros testes

🎯

Tenha um objetivo claro

Cada teste deve verificar um comportamento específico da aplicação.

🔎

Valide resultados

Não apenas execute ações. Verifique se o resultado esperado realmente aconteceu.

📖

Use nomes descritivos

Descreva claramente o comportamento que está sendo testado.

🧹

Mantenha testes simples

Prefira cenários fáceis de entender, executar e investigar.
