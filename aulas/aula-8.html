Configurando o Projeto Cypress

Aprenda a organizar o projeto Cypress, entender o arquivo de configuração e definir as principais opções utilizadas durante a execução dos testes.

Agora vamos entender como organizar o projeto e configurar o Cypress para que ele possa ser utilizado de forma consistente nos nossos testes.

O que é a configuração do Cypress?

A configuração do Cypress define como o framework deverá se comportar durante a execução dos testes.

Em vez de repetir determinadas informações em cada teste, podemos centralizar configurações importantes em um arquivo próprio.

⚙️ Configuração → define o comportamento do Cypress.

🧪 Testes → utilizam essas configurações durante a execução.

📁 Projeto → mantém as configurações organizadas.

1. Estrutura do projeto

Depois de instalar e configurar o Cypress, teremos uma estrutura semelhante a esta: 

curso-cypress/

├── cypress/
│ └── e2e/
├── node_modules/
├── cypress.config.js
├── package-lock.json
└── package.json

Cada item possui uma responsabilidade diferente dentro do projeto.

🧪

cypress/

Diretório utilizado para arquivos relacionados aos testes Cypress.

📄

cypress.config.js

Arquivo principal de configuração do Cypress.

📦

package.json

Define informações, scripts e dependências do projeto Node.js.

🔒

package-lock.json

Registra informações sobre as versões das dependências instaladas.

2. Conhecendo o cypress.config.js

O arquivo cypress.config.js é utilizado para definir configurações do Cypress.

Uma configuração inicial pode ser: 

const { defineConfig } = require('cypress')

module.exports = defineConfig({

e2e: {

}

})

A propriedade e2e concentra as configurações relacionadas aos testes End-to-End.

Importante:

Não precisamos colocar todas as configurações possíveis no arquivo. Podemos adicionar somente aquilo que faz sentido para o projeto.

3. O que é defineConfig()?

O defineConfig() é utilizado para declarar a configuração do Cypress. 

const { defineConfig } = require('cypress')

module.exports = defineConfig({

e2e: {

}

})

Dentro do objeto passado para defineConfig(), podemos definir diferentes opções do projeto.

⚙️

Configuração centralizada

Mantém opções importantes do Cypress em um único arquivo.

🧩

Configuração por projeto

Cada projeto pode possuir suas próprias configurações.

4. Configurando a baseUrl

Uma das configurações mais importantes é a baseUrl.

Ela define a URL principal utilizada pela aplicação que será testada. 

const { defineConfig } = require('cypress')

module.exports = defineConfig({

e2e: {

    baseUrl: 'http://localhost:3000'

}

})

Depois disso, podemos utilizar caminhos relativos nos testes: 

cy.visit('/')

Ou: 

cy.visit('/login')

Se a baseUrl for: 

http://localhost:3000

então: 

cy.visit('/login')

acessará: 

http://localhost:3000/login

5. Por que utilizar baseUrl?

Sem uma baseUrl, poderíamos acabar repetindo a URL completa em diversos testes.

Por exemplo: 

cy.visit('http://localhost:3000/login')

cy.visit('http://localhost:3000/produtos')

cy.visit('http://localhost:3000/dashboard')

Com a baseUrl configurada: 

cy.visit('/login')

cy.visit('/produtos')

cy.visit('/dashboard')

Isso deixa os testes mais simples e facilita a alteração da URL da aplicação quando necessário.

6. Configurando o viewport

O Cypress permite configurar o tamanho da área disponível para a aplicação durante os testes.

Essa configuração é conhecida como viewport. 

const { defineConfig } = require('cypress')

module.exports = defineConfig({

viewportWidth: 1280,

viewportHeight: 720,

e2e: {

    baseUrl: 'http://localhost:3000'

}

})

Nesse exemplo, definimos uma área de: 

1280 x 720
↔️

viewportWidth

Define a largura da área de visualização.

↕️

viewportHeight

Define a altura da área de visualização.

7. Testando diferentes tamanhos de tela

O viewport também pode ser utilizado para testar comportamentos relacionados a diferentes tamanhos de tela.

Por exemplo: 

cy.viewport(375, 667)

Esse comando altera o tamanho do viewport durante o teste.

Podemos também utilizar nomes de dispositivos suportados pelo Cypress: 

cy.viewport('iphone-x')
Importante:

Testar diferentes tamanhos de tela é útil quando a aplicação possui comportamentos responsivos.

8. Configurando retries

O Cypress permite configurar tentativas adicionais para testes que falharem.

Essa funcionalidade é conhecida como retries. 

const { defineConfig } = require('cypress')

module.exports = defineConfig({

retries: {

    runMode: 2,

    openMode: 0

},

e2e: {

    baseUrl: 'http://localhost:3000'

}

})
Configuração Quando é utilizada
runMode Quando os testes são executados através do cypress run.
openMode Quando os testes são executados através da interface do Cypress.
Atenção:

Retries não devem ser utilizados para simplesmente esconder testes instáveis. Eles podem ser úteis em determinados ambientes, mas um teste que falha de forma intermitente deve ser investigado.

9. Configurando timeouts

O Cypress possui mecanismos de espera automática, mas também permite configurar determinados tempos de espera.

Um exemplo é o defaultCommandTimeout: 

const { defineConfig } = require('cypress')

module.exports = defineConfig({

defaultCommandTimeout: 10000,

e2e: {

    baseUrl: 'http://localhost:3000'

}

})

Nesse exemplo, o valor foi configurado para 10 segundos.

Boa prática:

Evite aumentar timeouts indiscriminadamente. Primeiro investigue se o problema está relacionado ao carregamento da aplicação, ao seletor ou ao próprio teste.

10. Uma configuração completa

Podemos combinar algumas das configurações estudadas: 

const { defineConfig } = require('cypress')

module.exports = defineConfig({

viewportWidth: 1280,

viewportHeight: 720,

defaultCommandTimeout: 10000,

retries: {

    runMode: 2,

    openMode: 0

},

e2e: {

    baseUrl: 'http://localhost:3000'

}

})

O arquivo centraliza configurações que serão utilizadas durante a execução dos testes.

🌐 baseUrl → endereço principal da aplicação.

↔️ viewportWidth → largura do viewport.

↕️ viewportHeight → altura do viewport.

⏱️ defaultCommandTimeout → tempo padrão de espera de comandos.

🔄 retries → configura novas tentativas para testes que falharem.

11. Configuração por ambiente

Em projetos reais, podemos ter diferentes ambientes para executar os testes.

Por exemplo:

💻

Desenvolvimento

Ambiente utilizado pelos desenvolvedores durante o desenvolvimento da aplicação.

🧪

Homologação

Ambiente utilizado para validações e testes antes da publicação.

🚀

Produção

Ambiente onde a aplicação é disponibilizada para seus usuários.

A utilização de uma configuração centralizada ajuda a manter o projeto organizado quando trabalhamos com diferentes ambientes.

12. Variáveis de ambiente

O Cypress também permite trabalhar com informações específicas de cada ambiente.

Podemos, por exemplo, utilizar configurações relacionadas a uma API ou aplicação. 

const { defineConfig } = require('cypress')

module.exports = defineConfig({

e2e: {

    env: {

        ambiente: 'teste'

    }

}

})

Durante os testes, podemos acessar esse valor: 

cy.env('ambiente')
Importante:

Informações sensíveis, como senhas e tokens, não devem ser colocadas diretamente no código do projeto.

13. Utilizando a configuração no teste

Depois de configurar a baseUrl, podemos simplificar nossos testes.

Configuração: 

e2e: {

baseUrl: 'http://localhost:3000'

}

Teste: 

describe('Página inicial', () => {

it('deve carregar a página', () => {

    cy.visit('/')

    cy.get('h1')
        .should('be.visible')

})

})

O teste não precisa conhecer a URL completa. Essa responsabilidade foi centralizada na configuração do projeto.

14. Organização dos arquivos

Conforme o projeto crescer, podemos organizar diferentes tipos de arquivos dentro da estrutura do Cypress. 

curso-cypress/

├── cypress/
│ ├── e2e/
│ ├── fixtures/
│ └── support/
│
├── node_modules/
│
├── cypress.config.js
├── package-lock.json
└── package.json
Pasta Objetivo
e2e Arquivos dos testes E2E.
fixtures Dados utilizados pelos testes.
support Arquivos de suporte e comandos compartilhados.

Essas pastas serão exploradas com mais detalhes ao longo das próximas aulas.

Erros comuns de configuração

❌

URL incorreta

Configurar uma baseUrl que não corresponde ao endereço onde a aplicação está executando.

❌

Configuração excessiva

Alterar diversas opções sem entender exatamente o impacto de cada uma.

❌

Ignorar a configuração do projeto

Colocar informações que deveriam estar centralizadas dentro de vários testes.

❌

Usar retries para esconder problemas

Repetir automaticamente testes instáveis sem investigar a causa da falha.

Boas práticas de configuração

🎯

Configure apenas o necessário

Evite adicionar configurações sem uma necessidade real do projeto.

📁

Centralize configurações

Utilize o cypress.config.js para manter configurações globais organizadas.

🔐

Proteja informações sensíveis

Evite armazenar credenciais e tokens diretamente no código dos testes.

🧹

Mantenha o projeto organizado

Separe testes, dados, arquivos de suporte e configurações de forma clara.
