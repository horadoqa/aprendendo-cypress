AULA 16 • CLICK()

click()

Aprenda a utilizar o comando click() para automatizar cliques e interações com elementos da aplicação utilizando Cypress.

Objetivos da aula

Na aula anterior, aprendemos como utilizar seletores para localizar elementos de forma mais confiável.

Agora vamos aprender a interagir com esses elementos. O comando click() é um dos comandos mais utilizados em testes E2E, pois permite simular ações de clique realizadas pelo usuário.

🖱️

Utilizar click()

Aprender a realizar cliques em elementos utilizando Cypress.

🎯

Trabalhar com seletores

Localizar corretamente o elemento que deverá receber a interação.

🔗

Encadear comandos

Combinar comandos de localização e interação em uma mesma sequência.

✅

Validar resultados

Verificar se o clique produziu o comportamento esperado na aplicação.

O que é o click()?

O click() é um comando do Cypress utilizado para realizar uma ação de clique em um elemento da página.

Ele pode ser utilizado em botões, links, elementos de menu, checkbox e outros elementos que aceitam interação. 

cy.get('button').click()

Nesse exemplo, o Cypress primeiro localiza um botão e depois realiza um clique nesse elemento.

🧭 Localizar → encontrar o elemento.

🖱️ Interagir → executar o clique.

✅ Validar → verificar o resultado esperado.

1. Sintaxe básica

A forma mais simples de utilizar o comando é: 

cy.get('seletor').click()

Por exemplo: 

cy.get('#login').click()

Nesse caso, o Cypress procura pelo elemento que possui o ID login e executa o clique.

🔎

cy.get()

Localiza o elemento que será utilizado na interação.

🖱️

click()

Executa a ação de clique no elemento encontrado.

2. Clicando em um botão

Um dos usos mais comuns do click() é interagir com botões.

Considere o seguinte HTML: 

<button id="salvar">
Salvar

Podemos automatizar o clique utilizando: 

cy.get('#salvar').click()

O Cypress localizará o botão pelo ID e realizará a interação.

Exemplo:

Usuário clica em "Salvar" → aplicação processa a ação → mensagem de sucesso é exibida.

3. Clicando em links

Também podemos utilizar o click() para clicar em links.

Exemplo: 

<a href="/produtos" id="produtos">
Produtos

O teste pode ser escrito da seguinte forma: 

cy.get('#produtos').click()

Depois do clique, podemos validar se a aplicação apresentou o resultado esperado. 

cy.get('#produtos').click()

cy.url()
.should('include', '/produtos')

4. Utilizando contains()

Quando queremos localizar um elemento pelo texto apresentado na interface, podemos utilizar contains(). 

cy.contains('Entrar').click()

Nesse exemplo, o Cypress procura um elemento que contenha o texto Entrar e executa o clique.

Exemplo: 
<button>
Entrar

Podemos interagir com ele utilizando: 

cy.contains('Entrar').click()

Apesar de ser útil, é importante escolher seletores estáveis e específicos quando o projeto possuir elementos com textos semelhantes.

5. Utilizando data-testid

Uma estratégia comum para automação é utilizar atributos específicos para testes.

Por exemplo: 

<button data-testid="btn-login">
Entrar

O teste pode utilizar: 

cy.get('[data-testid="btn-login"]')
.click()

🎯 A utilização de atributos destinados à automação pode reduzir a dependência de classes e estruturas visuais da aplicação.

6. Clique e validação

Em um teste E2E, normalmente não queremos apenas clicar em um elemento. Também queremos verificar o resultado dessa ação.

Exemplo: 

cy.get('#login').click()

cy.get('.mensagem-sucesso')
.should('be.visible')

Nesse teste:

1️⃣

Localizar

O botão de login é localizado.

2️⃣

Clicar

O Cypress executa o clique.

3️⃣

Validar

A mensagem esperada é validada.

7. Clicando em checkbox

O comando click() também pode ser utilizado para interagir com elementos como checkbox.

Exemplo: 

<input
type="checkbox"
id="termos"

>

Podemos utilizar: 

cy.get('#termos').click()

Depois podemos validar o estado do elemento: 

cy.get('#termos')
.should('be.checked')

O clique representa a ação do usuário, enquanto a asserção verifica se o estado esperado foi alcançado.

8. Quando existem vários elementos

Um seletor pode encontrar mais de um elemento. Nesse cenário, é importante entender como o Cypress trata a coleção encontrada.

Por exemplo: 

<button class="produto">
Produto 1

Se utilizarmos: 

cy.get('.produto').click()

O comportamento padrão pode não ser o que desejamos quando o seletor encontra múltiplos elementos.

Para clicar especificamente em um elemento, podemos utilizar comandos como first() ou eq(). 

cy.get('.produto')
.first()
.click()

Ou: 

cy.get('.produto')
.eq(1)
.click()

9. Utilizando { force: true }

O Cypress normalmente verifica se o elemento está em uma condição adequada para receber a interação.

Em algumas situações específicas, podemos utilizar a opção force: 

cy.get('#botao')
.click({ force: true })

Essa opção força a execução da ação mesmo quando determinadas verificações de interação normalmente impediriam o clique.

Atenção:

O uso de force: true não deve ser utilizado simplesmente para fazer um teste passar. Antes de utilizá-lo, investigue por que o elemento não está interagível.

10. Opções do click()

O comando click() aceita opções que permitem controlar determinados comportamentos. 

cy.get('#botao')
.click({
    force: true
})

Também podemos utilizar posições específicas: 

cy.get('#botao')
.click('topLeft')

Algumas posições disponíveis incluem:

Posição Descrição
topLeft Canto superior esquerdo.
topRight Canto superior direito.
center Região central do elemento.
bottomLeft Canto inferior esquerdo.
bottomRight Canto inferior direito.

11. Clique utilizando coordenadas

Também é possível informar coordenadas para definir a posição do clique dentro do elemento. 

cy.get('#area')
.click(10, 20)

Nesse exemplo, o clique será realizado utilizando as coordenadas fornecidas.

Boa prática:

Prefira interações baseadas em elementos e seletores estáveis. O uso de coordenadas pode tornar os testes mais sensíveis a alterações de layout.

12. Exemplo completo: menu

Vamos imaginar uma aplicação com um botão que abre um menu. 

<button data-testid="menu">
Menu





Produtos
Clientes
Configurações

O teste pode ser: 

cy.get('[data-testid="menu"]')
.click()

cy.get('.menu')
.should('be.visible')

Dessa forma, testamos tanto a ação quanto o resultado esperado.

13. Exemplo completo: login

Podemos combinar os conhecimentos das aulas anteriores para criar um fluxo simples de login. 

cy.visit('/login')

cy.get('[data-testid="email"]')
.type('usuario@email.com')

cy.get('[data-testid="senha"]')
.type('123456')

cy.get('[data-testid="btn-login"]')
.click()

cy.get('.dashboard')
.should('be.visible')

🌐 visit() → acessa a página.

🔎 get() → localiza os campos.

⌨️ type() → preenche os dados.

🖱️ click() → executa o login.

✅ should() → valida o resultado.

14. Pensando como um teste E2E

Um teste automatizado deve representar uma ação relevante do usuário.

Por isso, podemos pensar no fluxo da seguinte maneira: 

Usuário

↓
Localiza elemento
↓
Clica
↓
Aplicação processa ação
↓
Novo estado
↓
Teste valida resultado
👤

Ação do usuário

O usuário realiza uma interação na aplicação.

🧪

Automação

O Cypress reproduz essa interação.

🔍

Validação

O teste verifica o comportamento esperado.

Erros comuns ao utilizar click()

❌

Seletor incorreto

O teste tenta clicar em um elemento que não corresponde ao elemento esperado.

❌

Ignorar o resultado

O teste realiza o clique, mas não verifica o comportamento produzido pela ação.

❌

Utilizar force sem investigar

Forçar o clique pode esconder problemas reais de interação ou sincronização.

❌

Depender de coordenadas

Coordenadas podem deixar os testes mais sensíveis a alterações no layout.

Boas práticas com click()

🎯

Utilize seletores estáveis

Prefira atributos e seletores pensados para automação.

🔍

Valide o resultado

Depois da interação, verifique se o comportamento esperado aconteceu.

🧹

Evite force sem necessidade

Investigue primeiro por que o elemento não está disponível para interação.

🧩

Mantenha os testes simples

Cada interação deve representar uma etapa clara do comportamento que está sendo testado.

Resumindo

🖱️ click() → realiza uma ação de clique.

🔎 cy.get() → localiza o elemento que será utilizado.

🎯 contains() → permite localizar elementos pelo conteúdo textual.

🧪 data-testid → pode ser utilizado como estratégia de seleção para automação.

🔧 force: true → força a interação e deve ser utilizado com critério.

📍 Posições → permitem definir regiões específicas do elemento para o clique.

✅ Assertions → permitem validar o resultado da interação.
