Validando Textos

Aprenda a validar textos, mensagens e conteúdos exibidos na interface utilizando asserções do Cypress.

Nas aulas anteriores, aprendemos como localizar elementos e criar asserções utilizando o Cypress.

Agora vamos aprender a validar textos exibidos pela aplicação e garantir que as informações apresentadas ao usuário estejam corretas.

🔎

Localizar textos

Encontrar elementos que apresentam textos na página.

✅

Validar conteúdo

Verificar se um elemento apresenta o texto esperado.

📝

Validar mensagens

Testar mensagens de sucesso, erro, validação e informação.

🧪

Criar testes confiáveis

Utilizar asserções de texto de maneira clara e objetiva.

O que significa validar um texto?

Validar um texto significa verificar se determinado conteúdo apresentado pela aplicação corresponde ao comportamento esperado.

Por exemplo, imagine uma página contendo: 

<h1>Produtos</h1>

Podemos criar um teste para verificar se o título apresentado realmente é Produtos. 

cy.get('h1')
.should('have.text', 'Produtos')

🧪 O objetivo da asserção é comparar o estado atual da aplicação com o resultado esperado.

1. Utilizando have.text

Uma das formas de validar o conteúdo completo de um elemento é utilizar a asserção have.text. 

cy.get('h1')
.should('have.text', 'Produtos')

Nesse exemplo, o Cypress verifica se o conteúdo textual do elemento corresponde ao valor informado.

🎯

Elemento

O primeiro argumento identifica o elemento que será validado.

📝

have.text

Indica que queremos validar o texto do elemento.

✅

Texto esperado

Representa o conteúdo que esperamos encontrar.

2. Utilizando contains

Outra forma bastante utilizada para localizar elementos pelo conteúdo textual é o contains(). 

cy.contains('Produtos')

Podemos utilizar o comando para localizar um elemento que contenha determinado texto.

Por exemplo: 

cy.contains('Bem-vindo ao sistema')
.should('be.visible')
Importante:

contains() é um comando de localização. Ele pode ser combinado com uma asserção para validar o resultado.

3. contains() com seletor

Também podemos informar um seletor junto com o texto que queremos encontrar. 

cy.contains('button', 'Salvar')

Nesse caso, o Cypress procura um elemento button que contenha o texto Salvar.

Podemos então validar o botão: 

cy.contains('button', 'Salvar')
.should('be.visible')
🔎

Seletor

Define o tipo ou elemento que queremos localizar.

📝

Texto

Define o conteúdo que o elemento deve conter.

4. have.text x contain.text

O Cypress possui diferentes formas de validar conteúdos textuais.

Uma delas é utilizar have.text para verificar o conteúdo textual completo. 

cy.get('h1')
.should('have.text', 'Produtos')

Outra possibilidade é utilizar contain.text quando queremos verificar se determinado texto está presente. 

cy.get('p')
.should('contain.text', 'sucesso')
Asserção Objetivo
have.text Verificar o conteúdo textual do elemento.
contain.text Verificar se o elemento contém determinado texto.

5. Utilizando contain.text

A asserção contain.text é útil quando o elemento possui outros conteúdos além do texto que queremos verificar.

Imagine o seguinte HTML: 

<div class="mensagem">

Pedido realizado com sucesso!

Número do pedido: 12345

Podemos verificar apenas uma parte do conteúdo: 

cy.get('.mensagem')
.should('contain.text', 'Pedido realizado com sucesso')

Dessa forma, não precisamos conhecer todo o conteúdo textual existente dentro do elemento.

6. Obtendo o texto de um elemento

O Cypress também permite acessar o texto de um elemento utilizando uma função de callback. 

cy.get('h1').then(($element) => {

const texto = $element.text()

cy.log(texto)

})

O método .text() pertence ao objeto jQuery disponibilizado pelo Cypress nesse contexto.

Atenção:

Na maioria dos testes, não é necessário extrair o texto manualmente. Asserções como have.text e contain.text normalmente deixam o teste mais simples e direto.

7. Validando textos com match

Também podemos utilizar expressões regulares para validar padrões de texto.

Para isso, podemos utilizar a asserção match. 

cy.get('.email')
.should('match', /^[^@]+@[^@]+\.[^@]+$/)

Nesse exemplo, o teste verifica se o conteúdo corresponde ao padrão esperado para um endereço de e-mail.

🔎 Expressões regulares são úteis quando o conteúdo pode variar, mas precisa respeitar determinado padrão.

8. Validando mensagens de sucesso

Uma situação comum em testes E2E é validar mensagens exibidas depois de uma ação do usuário.

Imagine que o usuário clique em um botão para salvar um cadastro: 

cy.get('[data-cy="salvar"]')
.click()

cy.get('.mensagem-sucesso')
.should('contain.text', 'Cadastro realizado com sucesso')

O teste confirma que a mensagem esperada foi apresentada após a ação.

🖱️

Ação

O usuário realiza uma ação na aplicação.

⚙️

Processamento

A aplicação processa a ação realizada.

✅

Validação

O teste verifica a mensagem apresentada.

9. Validando mensagens de erro

Também podemos validar mensagens exibidas quando ocorre algum problema durante uma operação. 

cy.get('[data-cy="login"]')
.click()

cy.get('.erro')
.should('contain.text', 'Usuário ou senha inválidos')

Esse tipo de validação ajuda a garantir que a aplicação apresenta informações adequadas ao usuário.

Exemplo:

Se o usuário informar uma senha incorreta, o teste pode verificar se a mensagem de erro correspondente foi apresentada.

10. Trabalhando com textos dinâmicos

Nem sempre o texto apresentado pela aplicação será exatamente igual em todas as execuções.

Por exemplo: 

Pedido criado com sucesso! Número: 12345

O número do pedido pode mudar a cada execução.

Nesse caso, podemos validar somente a parte estável: 

cy.get('.mensagem')
.should('contain.text', 'Pedido criado com sucesso')
Boa prática:

Quando parte do texto é dinâmica, valide somente aquilo que representa o comportamento que realmente precisa ser garantido.

11. Atenção a maiúsculas e minúsculas

Ao comparar textos, é importante observar se o conteúdo esperado diferencia letras maiúsculas e minúsculas. 

cy.get('h1')
.should('have.text', 'Produtos')

Um texto como: 

produtos

não é igual a: 

Produtos

Sempre observe exatamente qual comportamento a aplicação deve apresentar antes de definir a asserção.

12. Atenção aos espaços e formatação

Espaços, quebras de linha e formatações podem influenciar a comparação de textos.

Por isso, quando uma validação textual falhar, verifique também o conteúdo real renderizado pelo elemento. 

cy.get('.mensagem')
.should('contain.text', 'Operação realizada')
Dica:

Se a validação não estiver funcionando como esperado, utilize o Cypress Runner para inspecionar o elemento e entender qual texto está realmente sendo renderizado.

13. Exemplo de teste completo

Vamos combinar navegação, interação e validação de texto em um único teste. 

describe('Cadastro', () => {

it('deve exibir mensagem de sucesso', () => {

    cy.visit('/cadastro')

    cy.get('[data-cy="nome"]')
        .type('João')

    cy.get('[data-cy="email"]')
        .type('joao@email.com')

    cy.get('[data-cy="salvar"]')
        .click()

    cy.get('.mensagem-sucesso')
        .should(
            'contain.text',
            'Cadastro realizado com sucesso'
        )

})

})

O teste executa uma ação e depois valida o resultado apresentado pela aplicação.

14. Validando textos em listas

Também podemos validar textos presentes em listas ou conjuntos de elementos.

Imagine: 

<ul>

<li>Produto A</li>
<li>Produto B</li>
<li>Produto C</li>

Podemos verificar se determinado item está presente: 

cy.get('li')
.should('contain.text', 'Produto B')

Ou localizar diretamente pelo conteúdo: 

cy.contains('Produto B')
.should('be.visible')

15. Texto como seletor

Embora seja possível localizar elementos pelo texto, nem sempre essa é a melhor estratégia para todos os cenários.

Por exemplo: 

cy.contains('Salvar').click()

Esse teste pode funcionar bem quando o texto representa uma informação estável da interface.

Entretanto, em aplicações onde o texto pode mudar, um atributo dedicado pode ser mais apropriado: 

cy.get('[data-cy="salvar"]').click()
Boa prática:

Use o texto quando ele fizer parte importante do comportamento que você deseja validar. Para localizar elementos de forma estável, atributos dedicados como data-cy podem ser uma alternativa adequada.

Erros comuns ao validar textos

❌

Validar texto errado

Verificar um texto diferente daquele realmente apresentado pela aplicação.

❌

Ignorar conteúdo dinâmico

Comparar exatamente um texto que possui partes variáveis.

❌

Usar seletores frágeis

Depender de estruturas de HTML que podem mudar frequentemente.

❌

Validar detalhes irrelevantes

Criar asserções para informações que não representam um comportamento importante.

Boas práticas para validação de textos

🎯

Valide comportamentos importantes

Priorize textos que representam resultados relevantes para o usuário.

🧩

Prefira textos estáveis

Evite depender de partes que mudam constantemente.

🔎

Escolha a asserção adequada

Utilize have.text ou contain.text de acordo com o objetivo da validação.

🧹

Mantenha os testes claros

Escreva asserções que deixem evidente aquilo que o teste está verificando.
