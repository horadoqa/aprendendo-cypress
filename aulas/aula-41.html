AULA 41 • CYPRESS EM HEADLESS

Cypress em Headless

Aprenda a executar testes Cypress sem abrir visualmente o navegador e prepare sua suíte para execução automatizada em ambientes de CI/CD.

Objetivos da aula

Nas aulas anteriores, aprendemos a organizar nossos testes e construir uma suíte automatizada utilizando Cypress.

Agora vamos aprender como executar esses testes utilizando o modo headless, uma abordagem muito utilizada em servidores e pipelines de integração contínua.

Entender Headless

Compreender o que significa executar um navegador em modo headless.

⚙️

Executar pelo terminal

Executar testes Cypress utilizando comandos diretamente pelo terminal.

🚀

Automatizar execuções

Preparar os testes para ambientes automatizados e pipelines.

📊

Gerar evidências

Entender como screenshots, vídeos e resultados podem ser utilizados em execuções headless.

O que é execução Headless?

O termo headless significa executar uma aplicação ou navegador sem apresentar sua interface gráfica para o usuário.

No Cypress, isso permite executar os testes sem abrir visualmente a janela do navegador. 

npx cypress run

🖥️ Modo interativo → normalmente utilizado durante o desenvolvimento dos testes.

⚙️ Modo headless → executa os testes pelo terminal sem apresentar a interface gráfica do navegador.

🚀 CI/CD → o modo headless é especialmente útil em servidores e pipelines automatizados.

1. Cypress Open x Cypress Run

O Cypress possui diferentes formas de iniciar a execução dos testes.

Durante o desenvolvimento, podemos utilizar: 

npx cypress open

Esse comando abre a interface do Cypress, permitindo selecionar e acompanhar os testes visualmente.

Para uma execução automatizada, utilizamos: 

npx cypress run
🪟

cypress open

Abre a interface gráfica do Cypress para desenvolvimento e depuração.

⚙️

cypress run

Executa os testes pelo terminal, sendo adequado para automação.

2. Executando o primeiro teste em Headless

Para executar a suíte de testes pelo terminal, utilize: 

npx cypress run

O Cypress iniciará a execução dos testes encontrados na estrutura configurada do projeto.

Ao final, o terminal apresentará informações sobre os testes executados.

O comando cypress run é uma das principais formas de executar testes Cypress em ambientes automatizados.

3. Escolhendo o navegador

Podemos informar qual navegador será utilizado durante a execução.

Por exemplo: 

npx cypress run --browser chrome

Também podemos utilizar outros navegadores compatíveis com o ambiente de execução. 

npx cypress run --browser electron

A disponibilidade dos navegadores depende do ambiente onde o Cypress está sendo executado.

4. Executando uma Spec específica

Nem sempre precisamos executar toda a suíte. Podemos selecionar uma spec específica. 

npx cypress run --spec "cypress/e2e/login.cy.js"

Isso pode ser útil durante o desenvolvimento, principalmente quando queremos validar rapidamente um conjunto específico de testes.

🎯

Execução específica

Executa somente o arquivo de teste informado.

⚡

Feedback rápido

Evita executar testes que não fazem parte da validação atual.

🧪

Depuração

Facilita a investigação de problemas em uma spec específica.

5. Executando diferentes arquivos de teste

Também podemos informar padrões para selecionar diferentes arquivos de teste. 

npx cypress run --spec "cypress/e2e/**/*.cy.js"

O padrão utilizado depende da organização do projeto e dos arquivos que desejamos executar.

Boa prática:

Organize suas specs de forma consistente para facilitar a seleção dos testes durante execuções locais e automatizadas.

6. Headless em ambientes de CI

Em um ambiente de integração contínua, normalmente não existe uma área de trabalho gráfica disponível para abrir manualmente o navegador.

Por isso, a execução pelo terminal é fundamental para automatizar os testes. 

npx cypress run

Um pipeline pode instalar as dependências, iniciar a aplicação e executar a suíte automaticamente. 

npm ci

npm run build

npm start

npx cypress run

O fluxo exato depende da tecnologia utilizada pela aplicação e da configuração do pipeline.

7. Utilizando baseUrl

Quando a aplicação possui uma URL conhecida, podemos configurar o baseUrl no Cypress. 

const { defineConfig } = require('cypress')

module.exports = defineConfig({

    e2e: {

        baseUrl: 'http://localhost:3000'

    }

})

Assim, os testes podem utilizar: 

cy.visit('/login')

Em vez de repetir a URL completa: 

cy.visit('http://localhost:3000/login')

Uma configuração adequada do baseUrl facilita a execução dos testes em diferentes ambientes.

8. Configurando diferentes ambientes

Em projetos reais, os testes podem ser executados contra diferentes ambientes, como desenvolvimento, homologação e produção controlada.

O Cypress permite trabalhar com configurações e variáveis de ambiente para adaptar a execução. 

npx cypress run --env ambiente=homologacao

Dentro do teste, podemos acessar informações de ambiente através das APIs de configuração do Cypress. 

const ambiente = Cypress.env('ambiente')

cy.log(ambiente)

Evite colocar credenciais ou informações sensíveis diretamente nos arquivos versionados do projeto.

9. Screenshots e evidências

Durante a execução automatizada, evidências podem ajudar na análise de falhas.

Podemos solicitar uma screenshot durante o teste: 

cy.screenshot('tela-login')

As evidências podem ser armazenadas pelo processo de execução e posteriormente utilizadas para investigação.

📸

Screenshots

Capturam o estado visual da aplicação em determinado momento.

🎥

Vídeos

Podem ajudar a analisar a sequência de ações realizada durante uma execução.

📋

Logs

Fornecem informações importantes sobre comandos e resultados da execução.

10. Entendendo o resultado da execução

Quando os testes são executados pelo terminal, o Cypress apresenta um resumo da execução. 

Running:  login.cy.js

  Login
    ✓ deve realizar login
    ✓ deve bloquear senha inválida

  2 passing

Quando um teste falha, o processo também fornece informações para ajudar na investigação. 

1 failing

  Login
    1) deve realizar login

       AssertionError:
       expected URL to include "dashboard"

Em pipelines, o resultado da execução pode ser utilizado para determinar se a etapa de testes foi concluída com sucesso.

11. O resultado do comando e o pipeline

Em uma execução automatizada, o processo que executa o Cypress precisa saber se os testes foram aprovados ou se houve falhas.

O comando de execução retorna um resultado que pode ser utilizado pelo sistema de automação para decidir o próximo passo do pipeline. 

npx cypress run

Por isso, uma falha nos testes pode interromper etapas posteriores de um pipeline, dependendo da configuração utilizada.

🧪 Testes aprovados → o pipeline pode continuar.

❌ Testes com falha → o pipeline pode interromper a execução ou executar etapas específicas de tratamento.

12. Comandos úteis

Comando Objetivo
npx cypress open Abre a interface do Cypress.
npx cypress run Executa os testes pelo terminal.
npx cypress run --browser chrome Executa os testes utilizando o navegador especificado.
npx cypress run --spec ... Executa uma spec específica.
npx cypress verify Verifica a instalação do Cypress.

13. Modo interativo x Headless

Característica Modo interativo Headless
Interface visual Sim Não
Execução pelo terminal Não é o foco Sim
Desenvolvimento Muito utilizado Também pode ser utilizado
CI/CD Menos adequado Muito utilizado
Depuração visual Facilitada Depende dos logs e evidências

14. Exemplo completo

Considere uma spec de login: 

describe('Login', () => {

    it('deve realizar login com sucesso', () => {

        cy.visit('/login')

        cy.get('#email')
            .type('usuario@teste.com')

        cy.get('#senha')
            .type('123456')

        cy.get('#login')
            .click()

        cy.url()
            .should('include', 'dashboard')

    })

})

Podemos executar essa spec em headless: 

npx cypress run \
    --spec "cypress/e2e/login.cy.js" \
    --browser chrome

Nesse cenário, o teste pode ser executado sem abrir visualmente a interface do navegador.

Boas práticas para execução Headless

⚙️

Padronize os comandos

Utilize scripts npm para facilitar a execução dos testes pela equipe.

🎯

Separe ambientes

Mantenha configurações adequadas para cada ambiente de execução.

📸

Mantenha evidências

Utilize screenshots, vídeos e logs para facilitar a investigação de falhas.

🔐

Proteja credenciais

Evite armazenar senhas, tokens e informações sensíveis diretamente no código.

Erros comuns

❌

Navegador indisponível

O ambiente pode não possuir o navegador configurado ou disponível para execução.

❌

Aplicação não iniciada

O teste pode tentar acessar uma aplicação que ainda não está disponível.

❌

BaseUrl incorreta

Uma URL base configurada incorretamente pode fazer os testes acessarem o endereço errado.

❌

Falta de evidências

Sem logs e evidências, investigar falhas em ambientes remotos pode ser mais difícil.
