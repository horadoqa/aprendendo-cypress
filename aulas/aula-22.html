Relembrando as Assertions

Uma assertion é uma verificação utilizada para confirmar se o resultado obtido corresponde ao resultado esperado.

Por exemplo: 

cy.get('h1')
    .should('be.visible')

Nesse caso, esperamos que o elemento h1 esteja visível.

🧪 Ação: executar uma operação na aplicação.

🔎 Assertion: verificar se o resultado esperado aconteceu.

1. O que é should()?

O should() é utilizado para realizar assertions sobre elementos encontrados pelo Cypress ou sobre valores produzidos por comandos.

Um exemplo simples: 

cy.get('h1')
    .should('be.visible')

Podemos interpretar esse código como:

🔎 Encontre o elemento h1.

✅ Verifique se ele está visível.

2. should() com valores esperados

Algumas assertions recebem um segundo argumento contendo o valor esperado. 

cy.get('h1')
    .should('have.text', 'Página inicial')

Nesse exemplo, o Cypress verifica se o texto do elemento corresponde ao valor informado.

Outro exemplo: 

cy.get('input')
    .should('have.value', 'usuario@email.com')

should() pode combinar uma condição com um valor esperado.

3. Encadeando should() com and()

Podemos realizar várias verificações sobre o mesmo elemento utilizando and(). 

cy.get('button')
    .should('be.visible')
    .and('be.enabled')
    .and('have.text', 'Entrar')

O teste verifica três condições:

👁️

Visível

O botão precisa estar visível.

🟢

Habilitado

O botão precisa estar habilitado.

📝

Texto

O botão precisa apresentar o texto esperado.

4. should() com callback

Além de utilizar strings como be.visible e have.text, também podemos passar uma função para o should(). 

cy.get('.produto')
    .should(($elemento) => {

        expect($elemento).to.have.length(1)

    })

Nesse formato, recebemos o elemento encontrado e podemos realizar verificações dentro da função.

Importante:

O callback deve ser utilizado quando precisamos de uma lógica de validação que não seja bem representada por uma assertion simples.

5. O que é expect()?

O expect() é uma forma de criar assertions utilizando a biblioteca de assertions integrada ao ecossistema utilizado pelo Cypress.

Um exemplo simples: 

expect(10).to.equal(10)

Nesse caso estamos verificando se o valor 10 é igual a 10.

expect() permite realizar assertions diretamente sobre valores e objetos.

6. Utilizando expect() com valores

Podemos utilizar expect() para comparar valores diretamente. 

const idade = 30

expect(idade).to.equal(30)

Podemos também validar strings: 

const nome = 'Maria'

expect(nome).to.equal('Maria')

Ou verificar se determinado texto contém outro texto: 

const mensagem = 'Cadastro realizado com sucesso'

expect(mensagem).to.include('sucesso')

7. Utilizando expect() com elementos

Podemos utilizar expect() dentro de um callback do Cypress para validar propriedades de um elemento. 

cy.get('h1')
    .then(($titulo) => {

        expect($titulo).to.be.visible

    })

Nesse exemplo:

🔎 cy.get() → localiza o elemento.

📦 $titulo → representa o elemento encontrado.

✅ expect() → valida uma condição sobre esse elemento.

8. equal()

O matcher equal() verifica se dois valores são equivalentes. 

expect(5).to.equal(5)

Outro exemplo: 

const status = 'aprovado'

expect(status).to.equal('aprovado')

equal() → compara o valor esperado com o valor recebido.

9. include()

O matcher include() verifica se determinado conteúdo está presente em outro valor. 

const mensagem = 'Login realizado com sucesso'

expect(mensagem)
    .to.include('sucesso')

Nesse caso, não precisamos comparar toda a mensagem. Basta verificar se ela contém a palavra esperada.

10. Validando valores booleanos

Podemos utilizar assertions para validar valores booleanos. 

const usuarioAtivo = true

expect(usuarioAtivo).to.be.true

Também podemos validar o valor false: 

const usuarioBloqueado = false

expect(usuarioBloqueado).to.be.false
✅

true

Valida que o valor seja verdadeiro. 

to.be.true
❌

false

Valida que o valor seja falso. 

to.be.false

11. Validando existência com expect()

Podemos verificar se um objeto ou valor existe. 

const usuario = {
    nome: 'João'
}

expect(usuario).to.exist

Também podemos validar quando esperamos que um valor não exista: 

expect(null).to.not.exist

to.exist → espera que o valor exista.

to.not.exist → espera que o valor não exista.

12. should() x expect()

As duas abordagens podem ser utilizadas para criar assertions, mas possuem estilos diferentes.

should() expect()
Geralmente utilizado em uma cadeia de comandos Cypress. Geralmente utilizado diretamente sobre um valor ou objeto.
Possui sintaxe integrada ao encadeamento do Cypress. Utiliza uma sintaxe baseada em expect e matchers.
Muito utilizado para validar elementos da interface. Útil para validar valores, objetos e resultados intermediários.
Pode utilizar callbacks. Pode ser utilizado dentro de callbacks e outras funções.

13. Exemplo utilizando should()

Imagine que queremos validar o título de uma página. 

cy.visit('/')

cy.get('h1')
    .should('be.visible')
    .and('have.text', 'Página inicial')

Nesse caso, a validação está diretamente relacionada ao elemento localizado pelo Cypress.

14. Exemplo utilizando expect()

Agora podemos obter um valor e realizar uma assertion utilizando expect(). 

cy.get('h1')
    .invoke('text')
    .then((texto) => {

        expect(texto)
            .to.equal('Página inicial')

    })

🔎 invoke() → obtém o texto do elemento.

📦 then() → recebe o resultado.

✅ expect() → valida o valor obtido.

15. expect() em respostas de API

O expect() também pode ser bastante útil para validar dados retornados por uma API. 

cy.request('/api/usuarios/1')
    .then((response) => {

        expect(response.status)
            .to.equal(200)

        expect(response.body.nome)
            .to.equal('João')

    })

Podemos validar diferentes informações da resposta, como status HTTP e propriedades do corpo.

🌐 response.status → status HTTP da resposta.

📦 response.body → conteúdo retornado pela API.

16. Utilizando not com expect()

Assim como nas assertions do should(), podemos utilizar not para representar uma condição negativa. 

const status = 'cancelado'

expect(status)
    .to.not.equal('aprovado')

Outro exemplo: 

const mensagem = 'Erro inesperado'

expect(mensagem)
    .to.not.include('sucesso')

17. Quando utilizar should()?

O should() é especialmente natural quando estamos trabalhando diretamente com elementos e comandos do Cypress.

🖥️

Elementos da interface

Validar visibilidade, texto, atributos, classes e estados.

🔗

Encadeamento

Realizar várias validações sobre um mesmo elemento.

🧪

Assertions simples

Criar verificações utilizando os matchers fornecidos pelo Cypress.

18. Quando utilizar expect()?

O expect() é especialmente útil quando precisamos trabalhar diretamente com valores obtidos durante a execução do teste.

📦

Valores

Comparar strings, números e valores booleanos.

🌐

APIs

Validar status, body e outras informações de respostas HTTP.

🧩

Objetos

Validar propriedades e estruturas de objetos.

19. Teste completo utilizando as duas abordagens

Podemos utilizar should() e expect() no mesmo teste quando isso fizer sentido. 

describe('Cadastro', () => {

    it('deve realizar cadastro com sucesso', () => {

        cy.visit('/cadastro')

        cy.get('[data-testid="nome"]')
            .type('Maria')

        cy.get('[data-testid="email"]')
            .type('maria@email.com')

        cy.get('[data-testid="cadastrar"]')
            .click()

        cy.get('.mensagem')
            .should('be.visible')
            .and('include.text', 'sucesso')

        cy.get('.mensagem')
            .invoke('text')
            .then((texto) => {

                expect(texto)
                    .to.include('sucesso')

            })

    })

})

O importante não é utilizar as duas abordagens obrigatoriamente, mas escolher a forma que melhor representa a validação necessária.

Erros comuns

❌

Confundir ação com assertion

Comandos como click() e type() executam ações; eles não substituem uma validação do resultado.

❌

Usar expect() sem necessidade

Evite transformar uma validação simples de elemento em uma lógica desnecessariamente complexa.

❌

Criar assertions irrelevantes

Uma assertion deve estar relacionada ao objetivo do teste.

❌

Comparar valores incorretamente

Verifique se o tipo e o valor esperado realmente correspondem ao resultado produzido.

Boas práticas

🎯

Valide o que importa

Crie assertions relacionadas ao comportamento que realmente precisa ser validado.

🔎

Prefira clareza

Utilize a abordagem que torne a intenção do teste mais fácil de compreender.

🧪

Evite duplicação

Não repita várias vezes a mesma validação sem uma necessidade clara.

📖

Mantenha os testes legíveis

O código deve deixar claro qual comportamento está sendo validado.

Resumindo

🔎 should() → realiza assertions integradas ao fluxo de comandos do Cypress.

🔗 and() → permite encadear outras validações.

🧩 should(callback) → permite executar uma lógica personalizada de validação.

✅ expect() → realiza assertions diretamente sobre valores e objetos.

🎯 equal() → compara valores.

🔎 include() → verifica se determinado conteúdo está presente.

❌ not → representa uma condição negativa.
