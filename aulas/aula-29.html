O que são variáveis?

Variáveis são utilizadas para armazenar informações que podem ser utilizadas posteriormente durante a execução do código.

Em JavaScript, podemos criar variáveis utilizando const, let ou, em códigos legados, var. 

const nome = 'Maria'

let idade = 25

Depois podemos utilizar essas variáveis em diferentes operações: 

const nome = 'Maria'

cy.log(nome)

📦 Variável → armazena um valor que pode ser utilizado pelo código.

🔤 Valor → informação armazenada na variável.

🧪 Teste → utiliza essas informações durante a execução do cenário.

1. const e let

Em testes Cypress, é comum utilizar const para valores que não serão reatribuídos. 

const email = 'usuario@teste.com'

cy.log(email)

Já o let pode ser utilizado quando o valor precisa ser alterado posteriormente. 

let status = 'pendente'

status = 'aprovado'

cy.log(status)
🔒

const

Utilize quando a variável não precisará receber outro valor.

🔄

let

Utilize quando o valor poderá ser reatribuído.

⚠️

var

É uma forma antiga de declaração e geralmente não é a primeira escolha em código moderno.

2. Utilizando variáveis nos testes

Variáveis podem deixar os testes mais organizados quando determinados valores precisam ser utilizados mais de uma vez. 

const email = 'usuario@teste.com'

const senha = '123456'

cy.visit('/login')

cy.get('#email')
.type(email)

cy.get('#senha')
.type(senha)

Nesse exemplo, os dados utilizados no formulário foram armazenados em variáveis.

Isso pode facilitar a leitura do teste e evitar que o mesmo valor seja repetido diretamente em diversos comandos.

3. Variáveis contendo objetos

Uma variável também pode armazenar um objeto com diversas informações relacionadas. 

const usuario = {

nome: 'Maria',
email: 'maria@teste.com',
senha: '123456'

}

Podemos acessar cada propriedade utilizando a notação de ponto: 

cy.log(usuario.nome)

cy.log(usuario.email)

cy.log(usuario.senha)

Essas informações também podem ser utilizadas diretamente nos comandos do Cypress: 

cy.get('#email')
.type(usuario.email)

cy.get('#senha')
.type(usuario.senha)

Objetos são úteis para agrupar informações relacionadas em uma única variável.

4. Armazenando dados de um fixture em uma variável

Na aula anterior, utilizamos o cy.fixture() para carregar dados externos.

Podemos receber esses dados dentro de um then(): 

cy.fixture('usuario.json')
.then((usuario) => {

    cy.log(usuario.nome)

})

O parâmetro usuario representa os dados carregados pelo fixture dentro daquele callback.

Também podemos criar outras variáveis a partir dessas informações: 

cy.fixture('usuario.json')
.then((usuario) => {

    const email = usuario.email

    cy.log(email)

})

O valor recebido pelo then() está disponível dentro do contexto daquela função.

5. O que é um alias?

Um alias é um nome associado a determinado valor, elemento ou resultado dentro do Cypress.

Podemos criar aliases utilizando o comando .as(). 

cy.fixture('usuario.json')
.as('usuario')

Nesse exemplo, criamos o alias chamado usuario.

Para acessar esse alias, utilizamos o símbolo @: 

cy.get('@usuario')
.then((usuario) => {

    cy.log(usuario.nome)

})

🏷️ .as() → cria um alias.

@ nome → referencia o alias criado.

🔗 cy.get() → pode ser utilizado para recuperar o alias.

6. Criando alias para elementos

Aliases também podem ser utilizados para referenciar elementos encontrados na página. 

cy.get('#email')
.as('campoEmail')

Depois podemos recuperar o elemento através do alias: 

cy.get('@campoEmail')
.type('usuario@teste.com')

Isso pode ser útil quando o mesmo elemento precisa ser referenciado em diferentes momentos do teste.

O alias representa uma referência ao elemento ou valor que foi associado a ele.

7. Criando aliases para valores

Podemos criar aliases para valores retornados por comandos do Cypress. 

cy.get('#email')
.invoke('val')
.as('email')

Depois podemos recuperar o valor: 

cy.get('@email')
.then((email) => {

    cy.log(email)

})
🧩

Elementos

Um alias pode representar um elemento encontrado na página.

📄

Dados

Um alias pode representar dados carregados durante o teste.

📦

Resultados

Um alias pode armazenar o resultado produzido por um comando Cypress.

8. Fixture com alias

Uma combinação bastante comum é carregar um fixture e imediatamente criar um alias para seus dados. 

cy.fixture('usuario.json')
.as('usuario')

Depois podemos utilizar o alias: 

cy.get('@usuario')
.then((usuario) => {

    cy.get('#email')
        .type(usuario.email)

    cy.get('#senha')
        .type(usuario.senha)

})

Essa abordagem permite carregar os dados uma vez e referenciá-los pelo alias durante o cenário.

9. Aliases dentro de beforeEach()

Quando diversos testes precisam dos mesmos dados, podemos criar o alias dentro de um beforeEach(). 

beforeEach(() => {

cy.fixture('usuario.json')
    .as('usuario')

})

Cada teste poderá recuperar os dados utilizando o alias: 

it('deve realizar login', () => {

cy.get('@usuario')
    .then((usuario) => {

        cy.visit('/login')

        cy.get('#email')
            .type(usuario.email)

        cy.get('#senha')
            .type(usuario.senha)

    })

})

O beforeEach() é executado antes de cada teste dentro do contexto em que foi definido.

10. Variável x Alias

Variáveis JavaScript e aliases do Cypress possuem propósitos relacionados, mas não são a mesma coisa.

Recurso Exemplo Utilização
Variável const usuario Armazenar valores dentro do escopo JavaScript.
Alias .as('usuario') Criar uma referência que pode ser recuperada pela cadeia do Cypress.
Referência @usuario Recuperar um alias criado anteriormente.

Uma variável JavaScript segue as regras de escopo e execução do JavaScript.

Um alias faz parte do mecanismo de aliases do Cypress e é recuperado através da cadeia de comandos.

11. Entendendo escopo de variáveis

O escopo determina onde uma variável pode ser acessada dentro do código. 

describe('Usuário', () => {

const nome = 'Maria'

it('deve exibir o usuário', () => {

    cy.log(nome)

})

})

Nesse exemplo, a variável nome foi declarada dentro do bloco do describe() e pode ser acessada pelos testes que estão dentro desse escopo.

Uma variável criada dentro de uma função, por outro lado, normalmente ficará disponível somente dentro daquele contexto. 

it('teste', () => {

const nome = 'Maria'

cy.log(nome)

})

Entender escopo é importante para evitar erros ao tentar acessar variáveis fora do contexto em que foram declaradas.

12. Trabalhando com valores dentro do then()

Comandos Cypress são encadeados e seus resultados podem ser trabalhados dentro de callbacks como o then(). 

cy.get('#nome')
.invoke('text')
.then((nome) => {

    cy.log(nome)

})

Também podemos utilizar o valor recebido para realizar outras operações: 

cy.get('#nome')
.invoke('text')
.then((nome) => {

    expect(nome)
        .to.contain('Maria')

})

O valor recebido pelo callback está disponível diretamente através do parâmetro definido na função.

13. Aliases com intercept()

Aliases também são muito utilizados em conjunto com o cy.intercept().

Podemos atribuir um alias a uma interceptação: 

cy.intercept('GET', '/api/usuarios')
.as('buscarUsuarios')

Depois podemos aguardar a requisição: 

cy.wait('@buscarUsuarios')

Também podemos acessar informações da requisição e da resposta: 

cy.wait('@buscarUsuarios')
.then((interceptacao) => {

    expect(interceptacao.response.statusCode)
        .to.equal(200)

})

Aliases são especialmente úteis para tornar testes de API e testes E2E mais fáceis de ler.

14. Trabalhando com múltiplos aliases

Um mesmo teste pode possuir diversos aliases, desde que cada um tenha um nome diferente. 

cy.fixture('usuario.json')
.as('usuario')

cy.fixture('produto.json')
.as('produto')

Podemos acessar cada informação separadamente: 

cy.get('@usuario')
.then((usuario) => {

    cy.log(usuario.nome)

})

cy.get('@produto')
.then((produto) => {

    cy.log(produto.nome)

})

Utilize nomes de aliases claros e relacionados ao conteúdo que eles representam.

15. Exemplo comparando variável e alias

Podemos armazenar um valor diretamente em uma variável: 

const email = 'usuario@teste.com'

cy.get('#email')
.type(email)

Ou podemos utilizar um alias: 

cy.wrap('usuario@teste.com')
.as('email')

cy.get('@email')
.then((email) => {

    cy.get('#email')
        .type(email)

})

A escolha depende do contexto. Variáveis são recursos do JavaScript, enquanto aliases são recursos do Cypress para referenciar valores, elementos ou resultados dentro do fluxo de testes.

Boas práticas com variáveis e aliases

🏷️

Use nomes claros

Escolha nomes que expliquem o conteúdo armazenado na variável ou alias.

🎯

Use o recurso adequado

Utilize variáveis para dados do JavaScript e aliases quando fizer sentido dentro do fluxo do Cypress.

♻️

Evite duplicação

Reutilize informações quando elas forem necessárias em diferentes etapas do teste.

🔐

Proteja dados sensíveis

Evite armazenar credenciais reais e informações confidenciais diretamente no código dos testes.

Erros comuns

❌

Confundir variável com alias

Variáveis JavaScript e aliases do Cypress possuem comportamentos e formas de acesso diferentes.

❌

Ignorar o escopo

Tentar utilizar uma variável fora do contexto em que ela foi declarada.

❌

Alias inexistente

Tentar acessar um alias que ainda não foi criado ou que possui outro nome.

❌

Nomes pouco claros

Utilizar nomes genéricos que dificultam a compreensão do teste.

16. Exemplo completo

Vamos combinar variáveis, fixture, alias e beforeEach() em um cenário de login.

Fixture: 

{

"email": "usuario@teste.com",
"senha": "123456"

}

Teste: 

describe('Login', () => {

beforeEach(() => {

    cy.fixture('usuario.json')
        .as('usuario')

})

it('deve realizar login com sucesso', () => {

    cy.get('@usuario')
        .then((usuario) => {

            const email = usuario.email
            const senha = usuario.senha

            cy.visit('/login')

            cy.get('#email')
                .type(email)

            cy.get('#senha')
                .type(senha)

            cy.get('#login')
                .click()

            cy.url()
                .should('include', 'dashboard')

        })

})

})

Observe a separação das responsabilidades:

📁 Fixture → armazena os dados.

🏷️ Alias → disponibiliza os dados dentro do fluxo Cypress.

📦 Variáveis → armazenam os valores utilizados pelo cenário.

🧪 Teste → executa as ações e valida o resultado.
